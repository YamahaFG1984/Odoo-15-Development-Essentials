15 → 20 变化速查

原书基于 Odoo 15，本教程按 Odoo 20 讲解，每一章里都用紫色的「Odoo 20 变化」提示框标出了差异。 这个附录把它们集中到一起，按主题排成对照表。当你在网上看到旧教程、旧代码，或者要把老模块迁移到新版本时，可以在这里快速查到「现在该怎么写」。

让工具先帮你改：upgrade_code

上面很多变化是机械性的（改个名字、换种写法），Odoo 自带了一个代码改写工具 upgrade_code，内置一系列迁移脚本（位于源码的 odoo/upgrade_code/ 目录）。 Odoo 20 带的脚本包括：

📝

17.5-01-tree-to-list

<tree> → <list>，tree,form → list,form

🔑

18.1-00-sql-constraint

_sql_constraints → models.Constraint

🔗

18.1-02-route-jsonrpc

type='json' → type='jsonrpc'

📅

18.5-00-domain-dynamic-dates

把视图里的日期表达式改写成动态日期

📞

19.1-00-t-call

t-call 内部的 t-set → 属性传参

💾

19.3-00-base64-in-xml

XML 中的 type="base64" → type="bytes"

🛡

19.4-00-ir-access

ir.model.access + ir.rule → ir.access

⭐

19.5-00-material-symbols-icons

Font Awesome 图标名 → Material Symbols

🔍

20.0-00-search-date-filters

去掉日期筛选上已移除的属性

⚙

owl3-migration

前端 OWL 组件迁移到 OWL 3

使用方法：在模块所在的 Git 仓库里运行，先演练、再执行、最后用 git diff 逐处检查：

cd ~/work20/library                       # 你的模块仓库，确保已提交、工作区干净
odoo upgrade_code --addons-path=. --from 15.0 --dry-run    # 只列出会被改写的文件
odoo upgrade_code --addons-path=. --from 15.0              # 真正改写
git diff                                   # 逐处检查改动
odoo upgrade_code --addons-path=. --script 19.4-00-ir-access   # 也可以只运行某一个脚本
工具只做「体力活」

这些脚本是尽力而为的文本改写，它们自己也这样声明：能帮你完成大量重复劳动，但不是银弹。 像看板模板从 kanban-box 到 card 的重写、name_get 改为 _compute_display_name、 create 改为批量、XML-RPC 客户端改为 JSON-2 这些需要理解业务含义的改动，仍然要你手工完成。 另外它只改代码，不迁移数据库；已有数据的大版本升级见第 15 章末尾的说明。

迁移书中模块的检查清单

如果你手上有按原书写的 Odoo 15 版图书馆模块，可以按下面的顺序把它迁移到 Odoo 20：

  1. 清单：version 改为 20.0.1.0.0 这样的格式；assets 的值改成列表，CSS 放进正确的资源包；删掉 views/assets.xml 这类旧式资源文件。
  2. 安全：运行 19.4-00-ir-access 脚本或手工改写为 security/ir.access.csv；组定义改用 privilege_id、user_ids、group_ids。
  3. 模型：_sql_constraints → models.Constraint；去掉 states=；name_get → _compute_display_name；create 改为 @api.model_create_multi； group_expand 去掉 order 参数；message_post 改用关键字参数；self._cr 之类改为 self.env.cr。
  4. 视图：tree → list；attrs / states → 条件表达式；oe_chatter → <chatter/>；图标换成 Material Symbols；看板改写为 card 模板。
  5. 前端：Bootstrap 4 类名换成 5；门户首页卡片改为 portal.entry，计数改为 _prepare_portal_counter_values()；type="json" 路由改为 jsonrpc；外部客户端改用 JSON-2 API。
  6. 测试：SingleTransactionCase 改为 TransactionCase；在一个新数据库上用 --test-enable 安装全部模块，确认测试通过、日志里没有弃用警告。
弃用警告是你的朋友

很多旧写法在 Odoo 20 上「还能跑」，只是在日志里留下一条 DeprecationWarning。这些写法往往会在下一两个版本里被彻底移除。 迁移时把日志里的弃用警告也一并清理干净，下次升级会轻松得多。

写在最后

恭喜你读完了整本教程！从开发者模式里点点鼠标，到写模型、视图、业务逻辑、API、报表、门户，再到部署上线，你已经走完了一个 Odoo 应用从无到有的全过程。 Odoo 每年都在变，但模型、视图、动作、安全、继承这些核心概念十几年来一直没变——掌握了它们，再看新版本的变化就只是「换个写法」。

  • 官方文档：odoo.com/documentation（选择对应版本），其中的开发者教程和参考手册是最权威的资料。
  • 源码就是最好的文档：遇到不确定的地方，到 Odoo 源码里搜一搜官方模块是怎么写的，本教程的很多细节就是这样核实的。
  • 社区：Odoo 社区协会（OCA）维护着大量高质量的开源模块，参与其中是学习和结识同行的好方法。
