第 13 章

网站与门户

到目前为止，我们做的界面都在后台：只有员工登录后才能看到。但很多业务需要面向外部的人： 访客想浏览馆藏书目，会员想查看自己借了哪些书。这一章我们离开后台 Web 客户端，用网页控制器 + 服务端 QWeb 做两类前端页面：任何人都能打开的公开页面，以及会员登录后在「我的账户」里看到的门户页面。

本章目标

  • 理解前端页面的三件套：控制器（路由）、QWeb 模板、静态资源
  • 掌握 @route 的参数、URL 里取参数的写法，以及 request / response 对象
  • 为门户用户配置访问权限：只能看到「自己的」数据
  • 在门户首页加一张「借书单」卡片，并做出列表页、详情页和面包屑
  • 了解 Odoo 20 门户的新机制：portal.entry 卡片记录和计数器方法

做一个前端网页

一个前端网页由三个部分合作完成：

第一步：网页控制器

控制器是继承 odoo.http.Controller 的类，里面用 @http.route 装饰的方法会被「挂」到某个 URL 上。 Odoo 加载模块时会自动发现这些类，不需要在任何地方注册： 

from odoo import http
from odoo.http import request


class Main(http.Controller):

    @http.route("/library/catalog", auth="public", website=True)
    def catalog(self, **kwargs):
        Book = request.env["library.book"]
        books = Book.sudo().search([])
        return request.render(
            "library_portal.book_catalog",
            {"books": books},
        )
  • auth="public"：不登录也能访问。没登录的访客会以一个共享的「公共用户」（Public user）身份运行代码。
  • website=True：告诉 Odoo 这是一个前端网站页面，渲染时会准备好前端布局需要的变量（语言、网站、菜单等）。
  • request.env：和模型方法里的 self.env 一样，是当前用户的环境。
  • request.render(模板, 值)：渲染一个 QWeb 模板，第二个参数是模板里能用的变量。
关于 sudo()

公共用户没有读取图书的权限，所以这里用 sudo() 以超级用户身份搜索。这在只读、并且数据本来就打算公开时没问题。 但要记住：sudo() 会绕过所有访问规则，千万不要把 URL 参数直接拼进 sudo 的搜索条件里让外部用户随意查询，也不要在 sudo 下写数据。 更稳妥的做法是给 base.group_public 组授予图书的只读权限（下一节会讲 ir.access），然后去掉 sudo()。

第二步：QWeb 模板

模板和第 12 章的报表一样是服务端 QWeb，表达式写的是 Python。区别是外层不再调用报表布局，而是调用前端布局 web.frontend_layout，它会给页面加上 <head>、页头导航栏和页脚： 

<odoo>
    <template id="book_catalog" name="Book List">
        <t t-call="web.frontend_layout">
            <t t-set="title">Book Catalog</t>
            <div class="oe_structure">
                <div class="container">
                    <h1 class="h1-book-catalog">Book Catalog</h1>
                    <table class="table">
                        <thead>
                            <tr>
                                <th scope="col">Title</th>
                                <th scope="col">Published</th>
                                <th scope="col">Publisher</th>
                            </tr>
                        </thead>
                        <tbody>
                            <tr t-foreach="books" t-as="book">
                                <td><span t-field="book.name"/></td>
                                <td><span t-field="book.date_published"/></td>
                                <td><span t-field="book.publisher_id"/></td>
                            </tr>
                        </tbody>
                    </table>
                </div>
            </div>
        </t>
    </template>
</odoo>
  • <t t-set="title">：前端布局会把 title 变量用作浏览器标签页的标题。
  • oe_structure：如果安装了网站应用，带这个类的区域可以在网站编辑器里拖入积木块。
  • QWeb 模板是 XML，所以每个标签都必须闭合（<br/> 而不是 <br>）。

深入理解网页控制器

控制器是服务器端响应 Web 请求的组件。一个请求从进入 Odoo 到返回页面，大致经过下面这些步骤：

声明路由

@http.route 装饰器最常用的参数：

参数含义
第一个位置参数URL 路径，可以是一个字符串，也可以是字符串列表（多个 URL 指向同一个方法）
type'http'（默认，普通网页请求）或 'jsonrpc'（前端 JavaScript 用 JSON-RPC 调用）
auth 'user'：必须登录；'public'：可以不登录，以公共用户身份运行； 'bearer'：用请求头里的 API 密钥认证（适合给程序调用的接口）； 'none'：连数据库都不需要，框架内部用
methods允许的 HTTP 方法，比如 ['GET']、['POST']；不写就全部允许
website是否是前端网站页面（影响语言、网站变量等）
csrf是否做 CSRF 校验。http 类型默认开启，所以提交表单时要带上 csrf_token
readonly只读请求可以在只读副本数据库上执行，减轻主库压力
⇪ Odoo 20 变化

JSON 请求的类型名从 type='json' 改成了 type='jsonrpc'（Odoo 19 起，旧名字还能用但会有弃用警告）。 新增的 auth='bearer' 让同一个路由既能被浏览器会话访问，也能被带 Authorization: Bearer <API 密钥> 的程序访问， 第 9 章的 JSON-2 API 就是这样实现的。readonly 参数也是新加的。

从 URL 里取参数

路由字符串里可以用 <类型:名字> 的格式声明参数，取出来的值会作为同名关键字参数传给方法。 URL 里 ? 后面的查询参数（或者 POST 表单提交的字段）也会作为关键字参数传入：

写法得到的值
<int:page>整数
<name> 或 <string:name>字符串（不含 /）
<path:subpath>可以包含 / 的字符串
<model("library.book"):book>直接得到一条记录。URL 里可以写数字 id，也可以写 book-title-7 这种「slug」形式
方法参数最后加上 **kw

如果 URL 带了一个方法没有声明的查询参数（比如广告跟踪加的 ?utm_source=...），而方法没有 **kw，请求就会报错。 加上 **kw 把多余的参数「兜住」，是写路由方法的好习惯。

路由方法的返回值可以是：

  • request.render(...) 返回的响应对象：最常见，渲染一个 QWeb 模板；
  • 一个字符串：直接作为 HTML 返回；
  • request.redirect(url)：跳转到另一个地址；
  • request.make_response(...) / request.make_json_response(...)：返回文件、JSON 等非 HTML 内容；
  • 对于 type='jsonrpc' 的路由，直接返回 Python 字典或列表，框架会转成 JSON。

request 对象

每个 Web 请求到来时，Odoo 都会创建一个 request 对象，在代码里用 from odoo.http import request 导入就能直接用：

属性 / 方法用途
request.envOdoo 环境，和 self.env 用法相同。数据库游标用 request.env.cr
request.env.user当前用户（访客则是公共用户）
request.session会话，可以在里面存一些跨请求的小数据
request.db数据库名
request.httprequest底层的 werkzeug 请求对象：请求头、路径、原始数据等
request.csrf_token()生成 CSRF 令牌，放进 HTML 表单的隐藏字段
request.render(模板, 值)返回一个「延迟渲染」的 QWeb 响应
request.redirect(url)重定向
request.not_found()返回 404
request.update_env(user=..., context=...)切换当前用户或上下文
⇪ Odoo 20 变化

书里列出的 request.cr 从 Odoo 19 起已弃用（使用时会有警告），请写 request.env.cr。 书里 Tip 提到网站变量是在 ir.ui.view 的 _prepare_qcontext 里准备的，现在改由 ir.qweb 模型的 _prepare_environment 方法负责。

response 对象

request.render() 并不会马上渲染模板，而是返回一个「记着要渲染什么」的响应对象。这样做的好处是： 其他模块继承你的控制器时，可以先调用 super() 拿到这个响应，修改里面的数据，再交给框架去渲染： 

from odoo import http
from odoo.addons.library_portal.controllers.main import Main


class MainExtended(Main):

    @http.route()          # 重写路由方法时必须重新加上装饰器，参数可以省略
    def catalog(self, **kwargs):
        response = super().catalog(**kwargs)
        books = response.qcontext["books"]
        response.qcontext["books"] = books.filtered("active")
        return response
响应对象的属性 / 方法用途
template要渲染的模板名
qcontext传给模板的数据字典
render()立即渲染，返回 HTML
flatten()强制渲染，把结果固定为响应体

它同时也是 werkzeug 的 Response，可以设置状态码、响应头、Cookie 等。

门户：给外部用户看的「我的账户」

门户（Portal）是 Odoo 给外部用户（客户、供应商、会员……）准备的自助区域。不同的应用会往门户里加功能： 销售应用让客户查看报价单和订单，项目应用让客户跟进任务。我们要让图书馆会员在这里查看自己的借书单。

创建门户用户

门户用户不需要单独去「用户」菜单创建，而是从联系人发起：打开会员对应的联系人，点击「齿轮」动作菜单 → Grant portal access（授予门户访问权限），在弹出的向导里确认邮箱并点「Grant Access」，Odoo 会发一封邀请邮件。 对方点链接设置密码后就能登录了。

本地测试不想收邮件？

在开发环境里，授予门户权限后可以直接以管理员身份到「设置 → 用户和公司 → 用户」里找到这个新用户（记得去掉「内部用户」筛选）， 手动设置密码，然后用隐身窗口以这个用户登录测试。

门户功能的实现分三部分：访问权限、控制器、QWeb 模板。我们依次来做。

第 1 部分：门户用户的访问权限

门户用户默认看不到任何图书馆数据。我们要给 base.group_portal 组授权： 图书和借书阶段可以读全部；但会员、借书单和借书单明细只能读属于自己的。 

id,name,model_id,group_id/id,operation,domain
access_book_portal,Book: portal,library.book,base.group_portal,r,
access_stage_portal,Checkout Stage: portal,library.checkout.stage,base.group_portal,r,
access_member_portal,Member: portal own,library.member,base.group_portal,r,"[('partner_id', '=', user.partner_id.id)]"
access_checkout_portal,Checkout: portal own,library.checkout,base.group_portal,r,"[('member_id.partner_id', '=', user.partner_id.id)]"
access_checkout_line_portal,Checkout Line: portal own,library.checkout.line,base.group_portal,r,"[('checkout_id.member_id.partner_id', '=', user.partner_id.id)]"

回忆第 3 章：operation 写 r 表示只读；domain 列里可以使用 user（当前用户）变量。 因为这些规则都指定了组，它们是「授权」：门户用户能读的就是满足这些条件的记录，其余一概看不到。

Odoo 15（书中写法）
<!-- ir.model.access.csv：只管「能不能读这个模型」 -->

<!-- 再用 ir.rule 限制「能读哪些记录」 -->

  <field name="model_id"
         ref="library_checkout.model_library_checkout"/>
  <field name="domain_force">
    [('member_id.partner_id', '=', user.partner_id.id)]
  </field>

</record>
Odoo 20

第 2 部分：门户控制器

门户的控制器都继承自 portal 模块的 CustomerPortal 类。继承它有两个好处： 可以重写它的方法给门户首页添加内容，也可以复用它的工具方法（比如准备布局数据、检查访问权限）：

CustomerPortal 的成员用途
_items_per_page每页显示多少条，默认 80
_prepare_portal_layout_values()门户页面通用的模板数据（页面名、首页卡片、负责的销售员等）
_prepare_portal_counter_values(counter)告诉门户首页某张卡片的记录怎么数（下一节讲）
_document_check_access(模型, id)检查当前用户能否读这条记录，能则返回它（sudo 版），否则抛出异常
_get_page_view_values(...)准备详情页的数据，包括「上一条 / 下一条」导航

另外 portal 模块还提供了一个分页函数 pager()。先看列表页：

from odoo.exceptions import AccessError, MissingError
from odoo.http import request, route
from odoo.addons.portal.controllers import portal


class CustomerPortal(portal.CustomerPortal):

    @route(
        ["/my/book-checkouts", "/my/book-checkouts/page/<int:page>"],
        auth="user",
        website=True,
    )
    def my_book_checkouts(self, page=1, **kw):
        Checkout = request.env["library.checkout"]
        domain = []  # 访问规则已经保证只能看到自己的借书单
        # 分页数据
        checkout_count = Checkout.search_count(domain)
        pager_data = portal.pager(
            url="/my/book-checkouts",
            total=checkout_count,
            page=page,
            step=self._items_per_page,
        )
        # 当前页的记录
        checkouts = Checkout.search(
            domain,
            limit=self._items_per_page,
            offset=pager_data["offset"],
        )
        # 记下浏览顺序，详情页上的「上一条 / 下一条」会用到
        request.session["my_checkouts_history"] = checkouts.ids[:100]
        # 模板数据
        values = self._prepare_portal_layout_values()
        values.update({
            "checkouts": checkouts,
            "page_name": "book_checkouts",
            "default_url": "/my/book-checkouts",
            "pager": pager_data,
        })
        return request.render("library_portal.my_book_checkouts", values)

注意 domain 是空的：我们没有在代码里写「只查自己的」，因为上一节的访问规则已经替我们过滤了。 把权限放在访问规则里而不是控制器里，任何地方（门户、API、后台）读数据时都同样安全。

书中的小错误

书里分页器的 url 写成了 "/my/book_checkouts"（下划线），而路由是 "/my/book-checkouts"（连字符）， 点击第 2 页时会 404。上面的代码已经改正。

然后是详情页。Odoo 自带的应用都用 _document_check_access() 来取记录：它会检查当前用户能不能读这条记录， 记录不存在时抛出 MissingError，没有权限时抛出 AccessError，我们捕获后跳回门户首页： 

    @route(
        ["/my/book-checkout/<int:checkout_id>"],
        auth="user",
        website=True,
    )
    def my_book_checkout(self, checkout_id, **kw):
        try:
            checkout_sudo = self._document_check_access(
                "library.checkout", checkout_id
            )
        except (AccessError, MissingError):
            return request.redirect("/my")
        values = self._prepare_portal_layout_values()
        values = self._get_page_view_values(
            checkout_sudo, None, values,
            "my_checkouts_history", False,
        )
        values.update({
            "doc": checkout_sudo,
            "page_name": "book_checkout",
        })
        return request.render("library_portal.book_checkout", values)
为什么不用 <model(...)> 直接取记录？

书里用的是 <model('library.checkout'):doc>，也能工作：没有权限时会在渲染模板时报错。 但用 <int:checkout_id> + _document_check_access() 可以自己决定没权限时怎么办（这里是跳回首页）， 还能配合 _get_page_view_values() 得到「上一条 / 下一条」按钮。这也是 Odoo 20 官方应用的写法。

第 3 部分：在门户首页加一张卡片

字段含义
name / description卡片的标题和说明文字（可翻译）

完整的门户控制器

把前面的片段合起来，controllers/portal.py 的完整代码如下：

from odoo.exceptions import AccessError, MissingError
from odoo.http import request, route
from odoo.addons.portal.controllers import portal


class CustomerPortal(portal.CustomerPortal):

    def _prepare_portal_counter_values(self, counter):
        if counter == "book_checkout_count":
            return "library.checkout", [], "read"
        return super()._prepare_portal_counter_values(counter)

    @route(
        ["/my/book-checkouts", "/my/book-checkouts/page/<int:page>"],
        auth="user",
        website=True,
    )
    def my_book_checkouts(self, page=1, **kw):
        Checkout = request.env["library.checkout"]
        domain = []
        checkout_count = Checkout.search_count(domain)
        pager_data = portal.pager(
            url="/my/book-checkouts",
            total=checkout_count,
            page=page,
            step=self._items_per_page,
        )
        checkouts = Checkout.search(
            domain,
            limit=self._items_per_page,
            offset=pager_data["offset"],
        )
        request.session["my_checkouts_history"] = checkouts.ids[:100]
        values = self._prepare_portal_layout_values()
        values.update({
            "checkouts": checkouts,
            "page_name": "book_checkouts",
            "default_url": "/my/book-checkouts",
            "pager": pager_data,
        })
        return request.render("library_portal.my_book_checkouts", values)

    @route(["/my/book-checkout/<int:checkout_id>"], auth="user", website=True)
    def my_book_checkout(self, checkout_id, **kw):
        try:
            checkout_sudo = self._document_check_access(
                "library.checkout", checkout_id
            )
        except (AccessError, MissingError):
            return request.redirect("/my")
        values = self._prepare_portal_layout_values()
        values = self._get_page_view_values(
            checkout_sudo, None, values, "my_checkouts_history", False
        )
        values.update({
            "doc": checkout_sudo,
            "page_name": "book_checkout",
        })
        return request.render("library_portal.book_checkout", values)

小结

  • 前端页面 = 控制器（@http.route）+ 服务端 QWeb 模板 + web.assets_frontend 里的资源。
  • auth 决定谁能访问：user 要登录、public 可匿名、bearer 用 API 密钥；JSON 路由用 type='jsonrpc'。
  • URL 里的 <int:id>、<model(...):rec> 和查询参数都会变成方法参数；记得加 **kw。
  • request.render() 返回延迟渲染的响应，继承者可以通过 response.qcontext 修改数据。
  • 门户用户属于 base.group_portal。在 Odoo 20 用带域的 ir.access 规则让他们只读到自己的记录。
  • 门户控制器继承 CustomerPortal：首页卡片是 portal.entry 记录，计数靠 _prepare_portal_counter_values()； 列表页用 pager() + portal.portal_table，详情页用 _document_check_access()；面包屑继承 portal.portal_breadcrumbs。
