第 11 章

看板视图与 OWL 模板

看板（Kanban）把「工作进行到哪一步」变成一眼就能看懂的画面，是支撑精益流程的利器。 Odoo 的看板视图由 QWeb 模板驱动 —— 这是 Odoo 基于 XML 的模板语言，报表和网站也用它。 这一章给借书单做一个看板，顺带把 QWeb 模板语言彻底学一遍，最后学会给模块加入自己的 CSS 和 JavaScript。

本章目标

  • 理解看板、拉动式流程和看板状态
  • 用 Odoo 20 的写法设计看板：分列、进度条、card 和 menu 模板
  • 在卡片上使用颜色、优先级、活动、状态、头像等组件
  • 掌握客户端 QWeb 的全部常用指令：t-out、t-set、t-if、t-foreach、t-att、t-call……
  • 扩展别人的看板视图
  • 通过清单的 assets 键加入 CSS / JS，并认识 OWL 组件
⇪ 看板的写法在 Odoo 18 有一次大改

书里的看板卡片模板叫 kanban-box，里面用 oe_kanban_global_click、o_kanban_record_title、oe_kanban_bottom_left 等一堆 CSS 类手工搭布局，下拉菜单要自己写 Bootstrap 的 dropdown 标记。 Odoo 18 起改成了语义化的写法：卡片模板叫 card，布局用 <main>、<aside>、<footer>， 下拉菜单是一个单独的 menu 模板，卡片默认就可以点击打开。 在 Odoo 20 里，没有 card 模板的看板会直接报错，书中的看板代码必须重写。

认识看板

Kanban 是日语「看板 / 广告牌」，源自丰田的精益生产，后来随着敏捷开发在软件行业流行起来。看板是一块可视化的工作队列： 列代表流程的阶段，卡片代表工作项。新工作从最左边一列开始，一路向右，到最右一列时完成。

和沉重的工作流引擎相比，看板往往是管理流程更有效的方式。在 Odoo 里，看板视图有两种用法：

卡片列表
只是把记录显示成卡片，不分列。比如联系人、产品、员工、应用列表。
看板
按某个字段（通常是阶段）分组成列，卡片可以在列之间拖动 —— 拖动就是修改那个分组字段。比如 CRM 的销售管道、项目任务。

看板状态：从「推」到「拉」

卡片从左往右移动，意味着一种推动式策略：这一阶段做完了，就把工作推给下一阶段。这容易造成下游积压。 精益方法更推荐拉动式：下一阶段有空了，才从上一阶段拉取工作。

Odoo 用看板状态支持拉动式：每张卡片有一个状态灯 —— 灰色（进行中）、红色（受阻）、绿色（就绪）。 某阶段的工作做完了，不急着把卡片推到下一列，而是标成绿色，表示「可以被下一阶段拉走了」；遇到阻碍就标红，表示需要帮助。 看板状态只在当前阶段有意义，卡片换阶段时应当重置为灰色。

设计看板视图

表单视图主要使用 Odoo 专有的元素（<field>、<group>），只零星用一些 HTML。看板视图正好相反：它以 HTML 为主， 另外支持 <field>、<widget> 等少数 Odoo 元素。卡片的 HTML 由 QWeb 模板动态生成，这带来了很大的灵活性，也让设计更复杂。 好办法是：找一个和你的需求相近的现成看板，看它是怎么写的，照着改。

最小的看板

  1. 在动作的 view_mode 里加入 kanban，放在第一位让它成为默认视图： 
    <field name="view_mode">kanban,list,form,activity,calendar,pivot,graph</field>
  2. 新建 views/checkout_kanban_view.xml，并加入清单的 data。
  3. 写一个最小的看板：
<odoo>
    <record id="library_checkout_kanban" model="ir.ui.view">
        <field name="model">library.checkout</field>
        <field name="arch" type="xml">
            <kanban default_group_by="stage_id">
                <templates>
                    <t t-name="card">
                        <field name="name"/>
                    </t>
                </templates>
            </kanban>
        </field>
    </record>
</odoo>
  • 看板视图是一个 <kanban> 元素，卡片模板写在 <templates> 里。
  • t-name="card" 的模板就是每张卡片的内容，这里只显示一个字段。
  • default_group_by="stage_id" 默认按阶段分列，就成了看板；用户仍然可以在搜索栏改用别的分组方式。

看板的属性和子元素

<kanban> 属性作用
default_group_by默认按哪个字段分列
default_order卡片的默认排序
highlight_color存放卡片颜色的整数字段名，卡片左侧会显示对应颜色的色条
quick_create="false"关闭列头「+」快速创建（只输入标题就新建一张卡片）
quick_create_view快速创建时使用的表单视图的 XML ID
on_create="quick_create"点「新建」按钮时用快速创建而不是打开完整表单
group_create / group_edit / group_delete设为 false 时禁止新建 / 编辑 / 删除列
records_draggable="false"禁止在列之间拖动卡片
can_open="false"点击卡片不打开表单
class给看板根元素加 CSS 类
sample="1"没有数据时显示示例卡片

<kanban> 里可以放这些元素：

  • <field>：在模板之外声明的字段，会被加载到前端但不显示。模板的表达式里用到、却没有在模板里用 <field> 显示的字段，应该在这里声明。
  • <progressbar>：列头的进度条。
  • <header>：放按钮，和列表视图的页眉类似。
  • <templates>：必需，放 QWeb 模板：card（卡片，必需）、menu（卡片的下拉菜单，可选），以及你自己定义的、可以被 t-call 的辅助模板。

列头进度条

进度条在每一列的列头显示一个数字和一条彩色的条，表示这一列里各个子状态的比例。CRM 用它显示活动是「已计划 / 今天 / 已逾期」，项目任务用它显示看板状态。 我们给借书单加上看板状态： 

    kanban_state = fields.Selection(
        [("normal", "In Progress"),
         ("blocked", "Blocked"),
         ("done", "Ready for next stage")],
        "Kanban State",
        default="normal",
    )

    def write(self, vals):
        # 换阶段时重置看板状态
        if "stage_id" in vals and "kanban_state" not in vals:
            vals["kanban_state"] = "normal"
        # ……第 8 章 write() 里原有的逻辑……
        return super().write(vals)

<kanban default_group_by="stage_id">
    <progressbar field="kanban_state"
                 colors='{"done": "success", "blocked": "danger", "normal": "300"}'
                 sum_field="num_books"/>
    <templates>
        <t t-name="card">
            <field name="name"/>
        </t>
    </templates>
</kanban>
  • field：按哪个字段的取值分段。
  • colors：每个取值用什么颜色。值会被拼成 Bootstrap 的背景色类 bg-颜色，所以可以用 success、warning、danger、info，以及灰度 200、300 等。
  • sum_field：列头数字默认是卡片数量，指定这个字段后改为显示该字段的合计（这里是借出的书的总数）。
ⓘ 书里的 "muted" 和 sum_fields

书中写的 "normal": "muted" 在当前版本里不对应任何背景色类，灰色改用 "300"；属性名也应是 sum_field（单数），而不是书中正文里的 sum_fields。

设计卡片

以 CRM 销售管道的卡片为蓝本，一张信息丰富的卡片通常有这些区域：

为此先给模型补几个字段：

    color = fields.Integer()
    priority = fields.Selection(
        [("0", "Normal"),
         ("1", "High"),
         ("2", "Very High"),
         ("3", "Critical")],
        default="0",
    )

    book_cover = fields.Image(related="book_id.image")

然后是完整的看板视图：

<odoo>
    <record id="library_checkout_kanban" model="ir.ui.view">
        <field name="model">library.checkout</field>
        <field name="arch" type="xml">
            <kanban default_group_by="stage_id" highlight_color="color" sample="1">
                <!-- 表达式里要用的字段 -->
                <field name="state"/>
                <field name="num_books"/>
                <field name="line_ids"/>

                <progressbar field="kanban_state"
                             colors='{"done": "success", "blocked": "danger", "normal": "300"}'
                             sum_field="num_books"/>

                <templates>
                    <!-- 卡片右上角的下拉菜单 -->
                    <t t-name="menu">
                        <a t-if="widget.editable" role="menuitem" type="open"
                           class="dropdown-item">Edit</a>
                        <a t-if="widget.deletable" role="menuitem" type="delete"
                           class="dropdown-item">Delete</a>
                        <a t-if="record.state.raw_value == 'open'" role="menuitem"
                           type="object" name="button_done"
                           class="dropdown-item">Return Books</a>
                        <div role="separator" class="dropdown-divider"/>
                        <field name="color" widget="kanban_color_picker"/>
                    </t>

                    <!-- 可复用的片段：显示前几本书的封面 -->
                    <t t-name="book_covers">
                        <div class="d-flex gap-1">
                            <t t-foreach="record.line_ids.raw_value.slice(0, limit)"
                               t-as="line" t-key="line">
                                <img t-att-src="'/web/image/library.checkout.line/' + line + '/book_cover'"
                                     height="48" alt="Cover"/>
                            </t>
                        </div>
                    </t>

                    <!-- 卡片 -->
                    <t t-name="card">
                        <main>
                            <field name="name" class="fw-bold fs-5"/>
                            <div t-att-class="record.priority.raw_value >= '2' ? 'text-danger' : ''">
                                <field name="request_date"/>
                            </div>
                            <field name="member_id" widget="many2one_avatar"/>
                            <div t-if="record.num_books.raw_value == 0" class="text-muted">No books!</div>
                            <div t-elif="record.num_books.raw_value == 1">One book</div>
                            <div t-else=""><field name="num_books"/> books</div>
                            <t t-call="book_covers">
                                <t t-set="limit" t-value="3"/>
                            </t>
                            <footer>
                                <div class="d-flex">
                                    <field name="priority" widget="priority"/>
                                    <field name="activity_ids" widget="kanban_activity" class="ms-2"/>
                                </div>
                                <div class="d-flex ms-auto align-items-center">
                                    <field name="kanban_state" widget="state_selection" class="me-1"/>
                                    <field name="user_id" widget="many2one_avatar_user"/>
                                </div>
                            </footer>
                        </main>
                    </t>
                </templates>
            </kanban>
        </field>
    </record>
</odoo>

下面逐块解释。

标题和内容

<main> 是卡片的主体区域，里面的元素默认从上到下排列。可以随意使用 HTML 元素，也可以用 <field>， 后者会像在表单里一样按字段类型正确格式化（日期按用户的日期格式、多对一显示名称……）。 标题直接用 Bootstrap 的工具类加粗放大：class="fw-bold fs-5"。many2one_avatar 组件把会员显示成「头像 + 名字」。

下拉菜单

menu 模板定义卡片右上角 ⋮ 按钮里的菜单项。只要定义了这个模板，按钮就会自动出现，不用像书里那样自己写 Bootstrap 的 dropdown 标记。

  • <a type="open"> 打开记录，<a type="delete"> 删除记录。
  • widget.editable、widget.deletable 告诉你当前用户能不能编辑、删除，用 t-if 控制菜单项是否出现。
  • <a type="object" name="button_done"> 和表单里的按钮一样调用模型方法；type="action" 执行动作。
  • <field name="color" widget="kanban_color_picker"/> 放一个调色板，选中的颜色存进 color 字段；配合 <kanban highlight_color="color">，卡片左侧就会出现对应颜色的色条。
Odoo 15：颜色要自己算 CSS 类
<ul class="oe_kanban_colorpicker" data-field="color"/>
...
<div t-attf-class="oe_kanban_global_click
  {{!selection_mode ? 'oe_kanban_color_' +
    kanban_getcolor(record.color.raw_value) : ''}}">
Odoo 20：声明一下就行
<kanban highlight_color="color">
...
<t t-name="menu">
    <field name="color" widget="kanban_color_picker"/>
</t>

页脚

<footer> 固定在卡片底部。里面用两个 flex 容器：左边放优先级（priority，可点击的星星）和活动指示器（kanban_activity）； 右边用 ms-auto 推到最右，放看板状态灯（state_selection）和负责人头像（many2one_avatar_user）。

⇪ 组件改名

书里看板状态用的 kanban_state_selection 组件已不存在，改用 state_selection；它按取值 normal / blocked / done 显示灰 / 红 / 绿。

侧栏

<aside> 和 <main> 并列，通常用来放图片或头像（比如联系人看板右侧的照片）。给 <t t-name="card"> 加 class="flex-row" 可以让它们横向排列。 借书单的卡片没有用到它。

卡片里的动作链接

和表单按钮一样，卡片里的 <a> 或 <button> 可以通过 type 属性执行动作：

  • type="object" + name="方法名"：调用模型方法
  • type="action" + name="%(动作 XML ID)d"：执行窗口动作
  • type="open"：打开记录的表单
  • type="archive" / type="unarchive"：归档 / 恢复
  • type="delete"：删除记录

可复用的卡片视图（Odoo 20 新增）

Odoo 20 新增了一种 card 视图类型：把卡片的模板单独写成一个视图，再在看板里用 card_id 引用它。 这样同一种卡片可以被多个看板（或其他使用卡片的地方）复用： 

<record id="library_checkout_card" model="ir.ui.view">
    <field name="model">library.checkout</field>
    <field name="arch" type="xml">
        <card>
            <templates>
                <t t-name="menu"> ... </t>
                <t t-name="card"> ... </t>
            </templates>
        </card>
    </field>
</record>

<record id="library_checkout_kanban" model="ir.ui.view">
    <field name="model">library.checkout</field>
    <field name="arch" type="xml">
        <kanban card_id="%(library_checkout_card)d"
                default_group_by="stage_id" highlight_color="color">
            <progressbar field="kanban_state" colors='{"done": "success", "blocked": "danger"}'/>
        </kanban>
    </field>
</record>

QWeb 模板语言

QWeb 解析器在模板里寻找特殊的指令（以 t- 开头的 XML 属性），用动态生成的 HTML 替换它们。指令可以写在任何元素上 —— <div>、<span>、<field>……如果需要用指令、又不想多出一个 HTML 元素，就用 <t>：它是「隐形」的，本身不会出现在输出里。

求值上下文

卡片模板的表达式里可以使用这些变量：

变量含义
record当前记录。record.字段.raw_value 是原始值，适合做判断；record.字段.value 是按用户设置格式化后的文本，适合显示
widget卡片的辅助信息，如 widget.editable、widget.deletable

raw_value 的具体形式：多对一字段是 ID（或 false），对多字段是 ID 列表，日期是 ISO 格式的字符串。

💡 XML 里写不了 <

模板是 XML 文件，< 在 XML 里有特殊含义，不能直接写在属性值里。比较运算要写成 &lt;（小于）、&lt;=， 或者用 QWeb 支持的关键字 lt、lte、gt、gte：t-if="record.num_books.raw_value gt 0"。 > 在属性值里其实可以直接写，但为了统一，很多人也写成 &gt;。

下面逐个介绍指令。

t-out

输出表达式的值（自动转义 HTML）

t-set / t-value

定义变量

t-if / t-elif / t-else

条件渲染

t-foreach / t-as / t-key

循环

t-att-NAME / t-attf-NAME / t-att

动态属性

t-call

调用另一个模板

t-out：输出值

<field> 只能显示字段内容。t-out 可以输出任意表达式的结果，并自动做 HTML 转义（防止注入）： 

<t t-out="'Requested on ' + record.request_date.value"/>
⇪ t-esc 和 t-raw 已经退役

Odoo 15 引入 t-out 取代了 t-esc（转义输出）和 t-raw（不转义输出，有安全风险）。你在老模板里还会看到它们，新代码统一用 t-out。 需要输出 HTML 时，让值本身是「安全的 HTML」（服务端用 Markup，Html 字段的值本身就是），t-out 就会原样输出。

t-set：定义变量

<!-- 用表达式赋值 -->
<t t-set="red_or_black" t-value="record.num_books.raw_value == 0 ? 'text-danger' : ''"/>
<strong t-att-class="red_or_black"><field name="name"/></strong>

<!-- 用一段 HTML 赋值 -->
<t t-set="calendar_sign">
    <i class="oi" data-icon="calendar_month" title="Calendar"/>
</t>
<t t-out="calendar_sign"/>

t-attf- 与 t-att-：动态属性

t-attf-属性名 做字符串替换：在固定文本里嵌入 {{ 表达式 }}（或 #{ 表达式 }），适合拼 URL、CSS 类名：

<div t-attf-class="text-{{ record.priority.raw_value &lt; '2' ? 'body' : 'danger' }}">
    <field name="request_date"/>
</div>

t-att-属性名 用整个表达式的结果作为属性值：

<div t-att-class="record.priority.raw_value &lt; '2' ? 'text-body' : 'text-danger'">
    <field name="request_date"/>
</div>

当 t-att- 的结果为假值（false、null……）时，这个属性根本不会被输出。这对 checked、disabled 这类「出现即生效」的 HTML 属性很重要。 还有一个不带名字的 t-att，接受一个「属性名 → 值」的字典，一次设置多个属性：<p t-att="{'class': 'fw-bold', 'title': 'Hello'}"/>。

t-foreach：循环

<t t-foreach="record.line_ids.raw_value" t-as="line" t-key="line">
    <t t-out="line"/>
    <t t-if="!line_last">, </t>
</t>
  • t-foreach 接一个返回可迭代对象的表达式；t-as 给每次循环的元素起名字。
  • t-key 给每个元素一个唯一标识，帮助 OWL 在数据变化时高效地更新界面。客户端模板里循环时应该总是写上。
  • 循环会自动提供几个辅助变量，名字以 t-as 的值为前缀。以 t-as="line" 为例： line_index（从 0 开始的序号）、line_first（是否第一个）、line_last（是否最后一个）、line_value（遍历字典时的值）。 上例用 line_last 避免在最后一项后面多一个逗号。
  • 表达式就是 JavaScript，所以可以用 .slice(0, 5) 只取前 5 个。

看板里对多字段的 raw_value 是 ID 列表，不是记录。要显示关联记录的图片，可以直接拼 Odoo 的图片地址 /web/image/模型/ID/字段，这就是前面 book_covers 模板的做法。

⇪ kanban_image() 不见了

书里用 kanban_image('library.checkout.line', 'book_cover', line) 生成图片地址。这个辅助函数在新的看板实现里已不再提供， 直接拼 '/web/image/library.checkout.line/' + line + '/book_cover' 即可（对当前记录自己的图片字段，用 <field widget="image"/> 更简单）。

t-if：条件

<div t-if="record.num_books.raw_value == 0">No books!</div>
<div t-elif="record.num_books.raw_value == 1">One book</div>
<div t-else=""><field name="num_books"/> books</div>

只有条件为真时，元素及其内容才会被渲染。t-elif 和 t-else 必须紧跟在 t-if 元素后面。

💡 字段上的 invisible

对 <field> 元素，也可以像表单里那样用 invisible="not member_id" 这种 Python 风格的条件来隐藏，Odoo 自带的看板里大量这样写。

t-call：复用模板

与其到处重复同样的 HTML，不如把它做成一个可复用的片段。在 <templates> 里，任何 t-name 不是 card / menu 的模板都可以被 t-call 调用。

  • 被调用的模板和调用方共享上下文，调用方的变量在子模板里都能用。
  • 在 t-call 元素内部用 t-set 设置的变量是参数：只在子模板中可见，不会影响调用方。
  • t-call 元素内部的其他内容，在子模板里可以通过特殊变量 0 输出（<t t-out="0"/>）。这是做「布局模板」的标准手法，第 12、13 章会大量用到。

扩展看板视图

看板视图和其他视图一样可以继承扩展（第 4 章）：定位元素，用 position 指定操作。但看板的 XML 通常更复杂，定位更棘手：

  • 同一个字段可能出现多次：一次在模板外的字段声明里，一次在卡片模板里。简单定位器只匹配第一个，往往不是你想要的那个。
  • 大量没有标识的 HTML 元素（div、span），需要更复杂的 XPath。

解决办法是把 XPath 限定在 card 模板内部。比如在联系人看板卡片的名字前面加一个标签：

<record id="res_partner_kanban_inherit" model="ir.ui.view">
    <field name="name">Contact Kanban modification</field>
    <field name="model">res.partner</field>
    <field name="inherit_id" ref="base.res_partner_kanban_view"/>
    <field name="arch" type="xml">
        <xpath expr="//t[@t-name='card']//field[@name='name']" position="before">
            <span>Name: </span>
        </xpath>
    </field>
</record>

XPath 先找到 <t t-name="card">，再在它里面找 <field name="name">，就排除了模板外的那个同名字段。

💡 在命令行里试 XPath

复杂的 XPath 可以先在命令行里试。Ubuntu 上安装 libxml2-utils 后： xmllint --xpath "//t[@t-name='card']//field[@name='name']" library_checkout/views/checkout_kanban_view.xml。

加入 CSS 和 JavaScript

看板以 HTML 为主，大量使用 CSS 类。Odoo 用的是 Bootstrap 5，它的工具类（d-flex、ms-auto、fw-bold、text-danger……）通常就够用了。 需要自己的样式或脚本时，按惯例放在模块的 static/src/ 下，然后在清单的 assets 键里声明： 

    "assets": {
        "web.assets_backend": [
            "library_checkout/static/src/**/*",
        ],
    },

最常用的资源包：

  • web.assets_backend：后台 Web 客户端（看板、表单、自定义组件……）
  • web.assets_frontend：网站和门户页面（第 13 章）
  • web.report_assets_common：PDF 报表（第 12 章）

列表里可以写具体文件，也可以用 **/* 这样的通配符（会包含 .js、.xml 模板、.scss / .css）。 修改资源后需要升级模块；开发时用「开发者模式（含资源）」（?debug=assets）可以加载未压缩的源文件，方便在浏览器里调试。

⇪ 资源包的变化
  • 书里提到的 web.assets_common 已在 Odoo 16 拆分，日常开发只需要关心上面三个包。
  • Odoo 15 以前通过继承 web.assets_backend 模板、插入 <script> 和 <link> 标签来添加资源（原书仓库里的 views/assets.xml），这种方式早已废弃。
  • 书中清单里的 assets 值写成了集合 {...}，应该是列表 [...]：资源的加载顺序有时很重要，集合没有顺序。

一个最小的 OWL 字段组件

Odoo 的 Web 客户端是用自家的前端框架 OWL（Odoo Web Library）写的，Odoo 20 使用的是 OWL 3。 界面上的每个字段组件（widget）都是一个 OWL 组件。下面写一个最小的例子：显示借书数量、数量为 0 时标红的字段组件，让你对「组件是什么样子」有个直观印象。 

import { registry } from "@web/core/registry";
import { standardFieldProps } from "@web/views/fields/standard_field_props";
import { Component, useProps } from "@odoo/owl";

export class BookCountField extends Component {
    static template = "library_checkout.BookCountField";
    props = useProps(standardFieldProps);

    get count() {
        return this.props.record.data[this.props.name] || 0;
    }
}

registry.category("fields").add("book_count", {
    component: BookCountField,
    supportedTypes: ["integer"],
});

<?xml version="1.0" encoding="UTF-8"?>
<templates xml:space="preserve">
    <t t-name="library_checkout.BookCountField">
        <span t-att-class="this.count === 0 ? 'text-danger' : ''">
            <i class="oi me-1" data-icon="menu_book"/>
            <t t-out="this.count"/>
        </span>
    </t>
</templates>

然后在任何视图里就可以使用：<field name="num_books" widget="book_count"/>。

  • JS 文件是 ES 模块，用 import 引入 Odoo 和 OWL 提供的东西。@web/... 指向 web 模块的 static/src/，@odoo/owl 是 OWL 框架本身。
  • 组件类声明它的模板名（static template）和接受的属性（useProps）。字段组件都会收到 record（当前记录）和 name（字段名），值在 record.data[name] 里。
  • OWL 3 的模板里通过 this. 访问组件的属性和方法。
  • 最后在 fields 注册表里登记一个名字，视图里的 widget="..." 就是用这个名字查找组件的。
⚠ 前端开发是另一门功课

OWL 组件、服务、钩子、补丁（patch）机制……Odoo 的前端开发内容非常多，而且在大版本之间变化很快（Odoo 20 刚从 OWL 2 升级到 OWL 3）。 这个例子只是一个入口。深入学习请看官方文档的「Web framework」部分和教程，并多读 addons/web/static/src/ 里的源码 —— 那里有每一个组件的实现。

小结

  • 看板把流程可视化：列是阶段，卡片是工作项；看板状态（灰 / 红 / 绿）支持拉动式流程，列头进度条显示比例。
  • Odoo 20 的看板：<kanban> 里写 default_group_by、highlight_color、<progressbar>，模板 card 必需、menu 可选；卡片用 main / aside / footer 布局。
  • 卡片里的常用组件：kanban_color_picker、priority、kanban_activity、state_selection、many2one_avatar_user。
  • 客户端 QWeb 的表达式是 JavaScript；record.字段.raw_value 做判断、.value 做显示。
  • 指令：t-out、t-set、t-if/t-elif/t-else、t-foreach/t-as/t-key、t-att-/t-attf-、t-call。
  • 扩展看板时，把 XPath 限定在 //t[@t-name='card'] 内部。
  • 前端资源通过清单的 assets 键加入资源包；字段组件是注册到 fields 注册表的 OWL 组件。
