第 5 章

导入、导出与模块数据

菜单、视图、用户组、访问规则……模块里定义的大部分东西，最终都是数据库里的记录。 模块里的 XML 和 CSV 文件在运行时根本不会被读取，它们只是把这些记录装进数据库的一种手段。 所以，学会用文件表示数据，是写模块的基本功；它同样也是项目实施中批量导入、导出业务数据的基础。

本章目标

  • 理解外部标识符（XML ID）的作用，学会查找任意记录的 XML ID
  • 用界面导出、编辑、再导入 CSV，实现批量修改
  • 在 CSV 里表示关系字段（多对一、多对多、一对多）
  • 给模块添加初始数据和演示数据
  • 掌握 XML 数据文件：noupdate、eval、ref、对多字段命令、<delete> 和 <function>

外部标识符（XML ID）

它解决什么问题

每条记录在数据库里都有一个自增的数字 ID，比如 87。问题是：你没法提前知道模块安装时某条记录会被分配到哪个 ID，换一个数据库它又会不同。 外部标识符就是一个人类可读的、稳定的别名，让我们在不知道数字 ID 的情况下引用一条记录。它解决了两个问题：

  • 互相引用：菜单要引用动作，组要引用分类，书要引用作者……用 XML ID 引用，Odoo 负责翻译成真实的数字 ID。
  • 升级不重复：升级模块时数据文件会被再加载一遍。有了 XML ID，Odoo 就能认出「这条记录我以前建过」，于是更新它，而不是再建一条重复的。

在数据文件里，引用本模块的记录可以只写名字（action_library_book）， 引用其他模块的记录必须写完整 ID（base.user_admin），并且要确保那个模块在 depends 里，这样它的数据才会先加载。

查看和查找 XML ID

需要开启开发者模式。有三种常用方法：

  1. 技术菜单：设置 → 技术 → 用户界面 → 序列与标识符 → 外部标识符。按模块筛选 library_app，能看到本模块生成的全部 XML ID。
  2. 任意记录的表单：打开记录，调试菜单 → Metadata。弹窗里显示这条记录的数字 ID、XML ID 和「No Update」标志（还能点击修改它）。比如 Demo 用户的 XML ID 是 base.user_demo。
  3. 视图和动作：调试菜单 → View: Form 或 Action，打开的表单里有 External ID 字段。比如用户表单视图是 base.view_users_form。

在界面上导出和导入 CSV

要了解数据文件长什么样，最快的办法是让 Odoo 自己导出一份。导出的 CSV 可以拿来学习格式、批量编辑后再导回去，甚至直接改成模块的演示数据。

导出

  1. 先在图书馆应用里建两本书，比如《Odoo Development Essentials 11》和《Odoo 11 Development Cookbook》，并填上出版社和作者。
  2. 打开联系人应用，切换到列表视图，勾选要导出的行（勾表头的复选框可以全选）。
  3. 点顶部的 ⚙ 操作 → 导出。
  4. 在导出对话框里勾上 I want to update data (import-compatible export)（导入兼容的导出），格式选 CSV，字段只选「名称」，点导出。

得到的文件大致如下：

"id","name"
"__export__.res_partner_43_f82d2ecc","Alexandre Fayolle"
"__export__.res_partner_41_30a5bc3c","Daniel Reis"
"__export__.res_partner_44_6be5a130","Holger Brunn"
"__export__.res_partner_42_38b48275","Packt Publishing"
  • 第一行是字段名，导入时用来自动对应字段。
  • 因为选了「导入兼容」，Odoo 自动加了一列 id，里面是每条记录的 XML ID。原本没有 XML ID 的记录，会自动生成一个以 __export__ 开头的。
ⓘ 导出权限

在 Odoo 20 里，导出功能受用户组「Export: Allowed」（base.group_allow_export）控制。管理员默认拥有它；普通用户看不到导出菜单时，检查他是否在这个组里。

导入：批量修改的利器

用电子表格或文本编辑器打开刚才的 CSV，改几个名字，再加一行新数据，id 列留空： 

,Phillip K. Dick

回到联系人列表，点 ⚙ 操作 → 导入记录，上传文件。导入助手会显示列的对应关系，先点测试检查，没问题再点导入。

💡 分隔符和编码

如果导入助手把整行识别成了一列，或者中文变成乱码，在助手的选项里调整分隔符（逗号 / 分号）和编码（UTF-8）。不同的表格软件保存 CSV 的习惯不一样。

CSV 里的关系字段

前面的例子都是简单字段。书有出版社（多对一）和作者（多对多），这些关系在 CSV 里这样表示：

列名写法值适用
publisher_id/id关联记录的 XML ID多对一。推荐
publisher_id/.id关联记录的数字 ID只在同一个数据库里有效，很少用
publisher_id关联记录的显示名称按名字查找，重名时会出问题
author_ids/id逗号分隔的多个 XML ID，整体用双引号包起来多对多
id,name,author_ids/id
book_odc11,"Odoo 11 Development Cookbook","__export__.res_partner_43_f82d2ecc,__export__.res_partner_44_6be5a130"
★ 永远优先用 XML ID

数字 ID 只在当前数据库里有意义，导入到另一个库（比如从测试库到生产库）就会指向错误的记录，甚至是完全不相干的数据。除非有特别理由，否则用 /id。

一对多：表头与明细行

一对多关系常用来表示「表头 - 明细」或「父 - 子」结构，CSV 对它有专门的支持：同一个父记录可以占多行，后续行把父记录的列留空。 例如一个公司联系人有多个下属联系人（child_ids）： 

"id","name","child_ids/id","child_ids/name"
"base.res_partner_12","Azure Interior","base.res_partner_address_15","Brandon Freeman"
"","","base.res_partner_address_28","Colleen Diaz"
"","","base.res_partner_address_16","Nicole Ford"

不确定格式时，就先在界面上导出一份带这些字段的数据，照着它的结构来。

模块里的数据文件

模块用数据文件加载默认数据、演示数据、界面定义和各种配置。CSV 和 XML 都可以用：

CSV
和界面导入的格式完全一样。文件名必须等于目标模型名，比如加载书的数据要叫 library.book.csv，访问规则要叫 ir.access.csv。 简洁，适合大量同构数据。
XML
文件名随意，因为每条记录都写明了模型。功能更强：表达式求值、noupdate、删除记录、调用方法…… 视图、菜单这类界面定义都用 XML。

演示数据

给模块提供演示数据是好习惯：它展示模块怎么用，也方便测试。演示数据在清单的 demo 键里声明，格式和 data 一样。 演示数据只在启用了演示数据的数据库里加载（建库时用了 --with-demo）。

最省事的做法是从开发库里导出数据，存到模块的 data/ 目录。既然这些数据归我们的模块所有，要把导出生成的 __export__ 前缀改成有意义的名字： 

id,name
res_partner_alexandre,"Alexandre Fayolle"
res_partner_daniel,"Daniel Reis"
res_partner_holger,"Holger Brunn"
res_partner_packt,"Packt Publishing"

"id","name","date_published","publisher_id/id","author_ids/id"
library_book_ode11,"Odoo Development Essentials 11","2018-03-01",res_partner_packt,res_partner_daniel
library_book_odc11,"Odoo 11 Development Cookbook","2018-01-01",res_partner_packt,"res_partner_alexandre,res_partner_holger"

    "demo": [
        "data/res.partner.csv",
        "data/library.book.csv",
    ],

文件按声明顺序加载：书引用了联系人，所以联系人文件必须在前面。

ⓘ 数据文件里删掉的记录会怎样

如果某条记录原来在数据文件里，后来你把它从文件中删掉了，那么下次升级模块时，Odoo 会发现这个 XML ID 不再被任何文件提供，于是从数据库里删除这条记录（noupdate 的记录除外）。 这让「从模块里去掉一个菜单」这类操作能自动生效。

XML 数据文件

前几章我们已经大量使用 XML 数据文件。现在系统地看一下它的能力。给 library_app 再加一个演示数据文件：

<?xml version="1.0"?>
<odoo noupdate="1">
    <record model="res.partner" id="res_partner_huxley">
        <field name="name">Aldous Huxley</field>
    </record>

    <record model="library.book" id="library_book_bnw">
        <field name="name">Brave New World</field>
        <field name="author_ids" eval="[Command.link(ref('res_partner_huxley'))]"/>
        <field name="date_published">1932-01-01</field>
    </record>
</odoo>

    "demo": [
        "data/res.partner.csv",
        "data/library.book.csv",
        "data/book_demo.xml",
    ],

XML 数据文件的结构：

  • 根元素是 <odoo>。里面可以有 <data> 子元素，但不是必须的 —— 现在 <odoo> 和 <data> 作用相同。
  • 每个 <record> 相当于 CSV 里的一行，必须有 model（目标模型）和 id（XML ID）两个属性。
  • 每个 <field> 写一个字段。注意 XML 里没有 CSV 那种 publisher_id/id 斜杠写法，引用其他记录要用 ref 属性。

noupdate：只在安装时加载

默认情况下，每次升级模块都会重新加载数据文件，覆盖数据库里对应的记录。这意味着用户在界面上对这些记录做的修改，升级一次就没了。

💡 回顾：别直接改视图

这正是第 1 章强调「不要直接改视图，用继承视图」的原因 —— 直接改的视图会在模块升级时被覆盖。

有些数据只是初始配置，预期用户会按自己的需要修改（比如访问规则、邮件模板、序列号格式）。给它们加上 noupdate="1"， 就只在安装时创建一次，以后升级不再覆盖，用户的修改得以保留。

同一个文件里可以有多个 <data> 段，分别设置：

<odoo>
    <data>
        <!-- 每次升级都重新加载 -->
    </data>
    <data noupdate="1">
        <!-- 只在安装时加载一次 -->
    </data>
</odoo>
💡 开发时被 noupdate 坑了？

开发中修改了 noupdate 数据，升级却不生效 —— 这是预期行为。两个办法：开发期间先用 noupdate="0"，完工后再改成 1； 或者在命令行用 -i 对已安装的模块重新安装，它会无视 noupdate 标志。 noupdate 标志记录在每个 XML ID 上，也可以在「外部标识符」表单或调试菜单的 Metadata 弹窗里手动修改。

给字段赋值的几种方式

1. 直接写值。<field> 标签之间的文本就是值：

  • 日期写 YYYY-mm-dd，日期时间写 YYYY-mm-dd HH:MM:SS，会被正确转换。
  • 布尔字段：0 和 False 转换为假，其他非空值转换为真。

2. 用 eval 计算。属性值被当作 Python 表达式求值，可以用的东西包括：

  • Python 内置函数
  • 处理日期的 time、datetime、timedelta、relativedelta —— 让演示数据的日期总在安装日附近
  • ref('xml_id')：把 XML ID 翻译成数字 ID
  • Command：对多字段的写入命令（下面详述）
<!-- 出版日期设为昨天 -->
<field name="date_published" eval="(datetime.now() + timedelta(-1))"/>

<!-- 多对一：用 eval + ref() -->
<field name="publisher_id" eval="ref('res_partner_packt')"/>

3. 多对一用 ref 属性。上面第二种的简写：

<field name="publisher_id" ref="res_partner_packt"/>

4. 从文件加载二进制内容。比如给演示书加一个封面图：

<field name="image" type="bytes" file="library_app/static/img/bnw.png"/>
⇪ type="base64" → type="bytes"

以前从文件加载二进制内容写作 type="base64" file="..."。Odoo 19.3 起二进制字段内部不再到处做 base64 编码， 从文件加载时推荐写 type="bytes"。旧写法仍被接受。

对多字段的写入命令

一对多和多对多字段的值不是一个 ID，而是一组 ID。而且写入时可能有不同的意图：替换整个列表？追加几条？去掉几条？ 所以 Odoo 用一个命令列表来描述对它的操作。以 author_ids 为例： 

<!-- 替换：作者设为这两位，原来的作者全部移除 -->
<field name="author_ids"
       eval="[Command.set([ref('res_partner_alexandre'), ref('res_partner_holger')])]"/>

<!-- 追加：在现有作者里加上 Daniel -->
<field name="author_ids" eval="[Command.link(ref('res_partner_daniel'))]"/>

完整的命令表（左列是推荐的 Command 写法，中间是书里使用的等价旧式元组）：

Command 写法旧式元组作用
Command.create({...})(0, 0, {...})用给定的值新建一条记录，并关联上
Command.update(id, {...})(1, id, {...})修改一条已关联记录的值
Command.delete(id)(2, id)解除关联，并删除那条记录
Command.unlink(id)(3, id)只解除关联，不删除记录。多对多里「去掉一项」用它
Command.link(id)(4, id)关联一条已存在的记录
Command.clear()(5,)解除全部关联，不删除记录
Command.set([ids])(6, 0, [ids])用给定列表替换全部关联
⇪ 用 Command，别背数字

书里全部使用数字元组，比如 [(4, ref('x'))]、[(6, 0, [...])]。从 Odoo 14 起有了 Command 命名空间， 语义一目了然；数字写法仍然有效，你在老代码里会经常见到，所以两种都要认得。Python 代码里用 from odoo.fields import Command 导入； XML 的 eval 里可以直接用。

快捷标签

除了通用的 <record>，还有几个针对常用模型的快捷标签，写法更紧凑：

标签对应模型用途
<menuitem>ir.ui.menu菜单项
<template>ir.ui.viewQWeb 模板
<asset>ir.asset前端资源包里的一个文件（不常用，一般在清单的 assets 里声明）

书中提到的 <act_window> 和 <report> 快捷标签在 Odoo 14 已经移除，现在用 <record> 写。 再次提醒：快捷标签用于修改已有记录时会覆盖全部字段，只想改一个字段就用 <record>。

删除记录和调用方法

XML 数据文件不仅能写数据，还能删除数据、调用方法，适合较复杂的初始化场景。

删除记录用 <delete>，可以按 XML ID 或按域搜索：

<!-- 按 XML ID 删除 -->
<delete model="res.partner" id="library_app.res_partner_daniel"/>

<!-- 按域搜索后删除（效果同上） -->
<delete model="res.partner"
        search="[('id', '=', ref('library_app.res_partner_daniel'))]"/>

调用模型方法用 <function>，常用于准备演示数据或测试数据：

<data noupdate="1">
    <!-- 调用 library.book 模型的 _demo_prepare 方法，参数列表由 eval 给出 -->
    <function model="library.book" name="_demo_prepare" eval="[]"/>
</data>

这会在加载到这一行时执行 env["library.book"]._demo_prepare()。eval 是传给方法的参数列表，这里是空的。

小结

  • 模块里的数据文件只在安装 / 升级时加载进数据库；运行时 Odoo 只看数据库。
  • 外部标识符（XML ID）是记录的稳定别名，存在 ir.model.data 里，格式为「模块名.名字」。它让数据能互相引用，并且升级时更新而不是重复创建。
  • 导入兼容的 CSV 导出 + 编辑 + 再导入，是批量修改数据的标准方法；id 存在则更新，否则新建。
  • CSV 关系列用 /id 后缀引用 XML ID；多对多用逗号分隔的列表；一对多用多行，父记录列只填第一行。
  • 模块 CSV 的文件名必须等于模型名；演示数据放在清单的 demo 里，只在启用演示数据的库里加载。
  • XML 数据文件：noupdate="1" 保护用户的修改；eval 求值、ref 引用；对多字段用 Command 命令；还能 <delete> 和 <function>。

  3. 为 library_app 加上本章的三个演示数据文件，新建一个带演示数据的库安装它，确认数据都在。
