第 10 章

后台视图

业务逻辑再完善，如果界面难用，用户还是会出错、会抱怨。Odoo 的 Web 客户端提供了一整套构建界面的积木：菜单、动作、各种视图类型、几十种字段组件。 这一章以借书单为例，把这些积木一块块用起来，最后得到一个专业的「单据式」表单，以及列表、搜索、日历、透视表、图表等视图。

本章目标

  • 掌握菜单项和窗口动作的全部常用属性，并把动作放进「操作」菜单
  • 搭出单据式表单：页眉按钮、状态栏、标题、分组布局、页签、智能按钮
  • 熟悉字段的属性和常用组件（widget）
  • 用 Odoo 17+ 的条件表达式实现动态的隐藏 / 只读 / 必填
  • 做出带装饰、汇总、页眉按钮的列表视图，以及带筛选、分组、搜索面板的搜索视图
  • 认识活动、日历、透视表、图表视图

菜单项

菜单是界面导航的起点。它是一个树状结构：顶层是应用，下一层是应用的主菜单，还可以继续往下嵌套。 没有子菜单的「叶子」菜单项才能挂一个动作，告诉 Web 客户端点击后做什么。菜单存储在 ir.ui.menu 模型中， 可以在 设置 → 技术 → 用户界面 → 菜单项里浏览。 

<menuitem id="menu_library_checkout"
          name="Checkout"
          action="action_library_checkout"
          parent="library_app.menu_library"
          sequence="20"
          groups="library_app.library_group_user"/>
属性含义
name菜单标题
action点击时执行的动作的 XML ID
parent上级菜单的 XML ID。在别的模块里定义的，要写完整的 模块.标识符
sequence排序号，越小越靠前
groups能看到这个菜单的用户组，逗号分隔的 XML ID 列表
web_icon顶层菜单在应用切换器里的图标，格式 模块名,文件路径
💡 菜单也能嵌套着写

<menuitem> 可以嵌套：内层菜单自动以外层为父菜单，不用写 parent。Odoo 自己的 base_menus.xml 大量使用这种写法，结构一目了然。

窗口动作

窗口动作告诉 Web 客户端：打开哪个模型、用哪些视图、过滤哪些记录、带什么上下文。它既能挂在菜单上，也能被按钮调用。 存储在 ir.actions.act_window 模型中（设置 → 技术 → 动作 → 窗口动作）。 

<record id="action_library_checkout" model="ir.actions.act_window">
    <field name="name">Checkouts</field>
    <field name="res_model">library.checkout</field>
    <field name="view_mode">kanban,list,form,activity,calendar,pivot,graph</field>
    <field name="context">{'search_default_filter_not_done': 1}</field>
</record>
字段含义
name打开的视图的标题
res_model目标模型
view_mode可用的视图类型，逗号分隔，第一个是默认打开的
targetcurrent（默认，在主区域打开）或 new（在弹出对话框中打开）
context带给目标视图的上下文：设置默认值、默认筛选等，如 {'default_user_id': uid}
domain强制的过滤条件，用户无法取消，如 [('user_id', '=', uid)]
limit列表视图每页显示的记录数，默认 80
view_id指定使用某一个具体的视图（常和 target="new" 配合，弹出特定表单）
help没有记录时显示的 HTML 提示（「还没有借书单，点新建开始吧」）
⚠ 先写视图，再加 view_mode

上面的 view_mode 列出了本章后面才会定义的视图类型。看板（kanban）在第 11 章才写；在它们的视图定义完成之前，先别把它们加进 view_mode （Odoo 会为部分类型自动生成默认视图，但看板等类型没有可用的默认视图会报错）。

放进「操作」菜单

窗口动作还能出现在表单顶部、或列表选中记录后出现的 ⚙ 操作菜单里，作用于当前（选中的）记录。只需再设置两个字段：

  • binding_model_id：绑定到哪个模型，如 ref="model_library_checkout"
  • binding_view_types：在哪些视图类型里出现，如 form,list

第 8 章的群发消息向导就是这么做的。

表单视图的结构

表单视图是用户和数据交互的主要场所。它可以是简单的布局，也可以模仿纸质单据 —— 很多组织过去就是用纸质表单驱动流程的， 让表单看起来像一张单据，用户上手更快。下面是本节最终要做出来的借书单表单的结构：

先把骨架写出来：

<record id="view_form_checkout" model="ir.ui.view">
    <field name="model">library.checkout</field>
    <field name="arch" type="xml">
        <form>
            <header>
                <!-- 按钮和状态栏 -->
            </header>
            <sheet>
                <!-- 表单内容 -->
            </sheet>
            <chatter/>
        </form>
    </field>
</record>

视图的 name 字段可以省略，会自动生成，所以这里没写。

页眉：按钮

页眉通常放推动单据前进的操作按钮，「下一步」那个按钮一般会被高亮。加一个「还书」按钮，只在「已借出」状态下显示： 

<header>
    <button name="button_done"
            type="object"
            string="Return Books"
            invisible="state != 'open'"
            class="oe_highlight"/>
</header>
  • type="object" + name="button_done"：点击时调用模型的 button_done() 方法。
  • class="oe_highlight"：高亮为主按钮。有多个按钮时，突出最常用的那个。
  • invisible="state != 'open'"：一个 Python 风格的条件表达式，为真时隐藏按钮。表达式里可以直接使用记录的字段值。
Odoo 15（书中写法，Odoo 17 起不再支持）
<field name="state" invisible="True"/>
<button name="button_done" type="object"
    string="Return Books"
    attrs="{'invisible':
        [('state', 'in', ['new', 'done', 'cancel'])]}"
    class="oe_highlight"/>
<!-- 或者 -->
<button ... states="open"/>
Odoo 20
<button name="button_done" type="object"
    string="Return Books"
    invisible="state != 'open'"
    class="oe_highlight"/>
⇪ attrs 和 states 已经被移除

Odoo 17 删除了 attrs（用域表达式控制 invisible / readonly / required）和 states（列出可见的状态）两个属性， 改为直接在 invisible、readonly、required 属性里写条件表达式。 另一个好处是：表达式里用到的字段，Web 客户端会自动加载，不再需要像书里那样额外放一个 <field name="state" invisible="True"/>。 旧写法在 Odoo 20 上会导致视图校验失败、模块无法安装。

按钮调用的方法要在模型里实现：找到第一个 done 状态的阶段，把借书单移过去：

    def button_done(self):
        Stage = self.env["library.checkout.stage"]
        done_stage = Stage.search([("state", "=", "done")], limit=1)
        for checkout in self:
            checkout.stage_id = done_stage
        return True

self 通常是一条记录，但 API 允许对多条记录调用，所以用循环处理。修改 stage_id 会触发第 8 章写的 write()，自动记录归还日期。

页眉：状态栏

页眉里另一个常见元素是状态栏：一条显示流程各步骤、并标出当前所在位置的「管道」。它是一个使用 statusbar 组件的字段：

<header>
    <button name="button_done" type="object" string="Return Books"
            invisible="state != 'open'" class="oe_highlight"/>
    <field name="stage_id"
           widget="statusbar"
           options="{'clickable': True, 'fold_field': 'fold'}"/>
</header>
  • statusbar 组件既可以用于阶段（多对一字段），也可以用于状态（选择字段）。
  • clickable：允许用户直接点击状态栏切换阶段。如果希望流程只能通过按钮推进（比如要先做检查），就不要开启。
  • fold_field：阶段模型里哪个布尔字段表示「折叠」。被折叠的阶段（比如「已取消」）不单独显示，而是收进一个「更多」下拉里。

如果模型用的是选择字段 state，没有 fold_field，可以用 statusbar_visible 列出要显示的状态：

<field name="state" widget="statusbar" statusbar_visible="draft,open,done"/>

纸张区域

<sheet> 是表单的主体，通常由这几部分组成：

<sheet>
    <div class="oe_button_box" name="button_box"><!-- 智能按钮 --></div>
    <div class="oe_title"><!-- 标题 --></div>
    <group><!-- 头部字段 --></group>
    <notebook><!-- 页签：明细行、其他信息 --></notebook>
</sheet>

标题

先给借书单加两个字段：一个标题，一个借书人的头像（关联字段）：

    name = fields.Char(string="Title")
    member_image = fields.Binary(related="member_id.image_128")

<sheet>
    <div class="oe_button_box" name="button_box"/>
    <field name="member_image" widget="image" class="oe_avatar"/>
    <div class="oe_title">
        <label for="name"/>
        <h1><field name="name" placeholder="e.g. Summer reading list"/></h1>
        <h3>
            <span>By </span>
            <field name="member_id" class="oe_inline"/>
        </h3>
    </div>
    <!-- 后面的内容从这里继续…… -->
</sheet>
  • class="oe_avatar" 的图片组件显示为右上角的小头像。
  • oe_title 里可以用普通的 HTML 元素：div、span、h1、h3……
  • 不在 <group> 里的字段不会自动显示标签，所以用 <label for="name"/> 显式加一个。
  • oe_inline 让字段像行内元素一样跟着文字排版。
  • placeholder 是输入框为空时显示的提示文字。
⇪ 表单没有「编辑模式」了

书里用 class="oe_edit_only" / oe_read_only 让元素只在编辑 / 只读模式下出现（比如「By」只在只读时显示）。 Odoo 16 起表单始终处于可编辑状态（没有「编辑」按钮了，改了自动保存），这两个类已失去意义，直接去掉即可。

用 group 组织字段

主要内容用 <group> 组织。一个 group 在画布上划出两列：字段放进去，第一列是标签，第二列是值，字段越多就往下堆。 常见的做法是一个外层 group 套两个内层 group，得到左右两栏： 

<group name="group_top">
    <group name="group_col1">
        <field name="request_date"/>
    </group>
    <group name="group_col2">
        <field name="user_id"/>
        <field name="close_date"/>
    </group>
</group>

给 group 起 name 不是必须的，但推荐 —— 方便别的模块扩展。<group string="..."> 会给这一组加一个标题。 更细的布局控制：

  • <separator string="..."/>：加一条带标题的分隔线。
  • <newline/>：强制换行，下一个元素从新一行的第一列开始。
  • col（用在 group 上）：这个 group 有几列，默认 2。最好用偶数，因为一个字段默认占两列（标签 + 值）。
  • colspan（用在 group 里的元素上）：这个元素占几列。
<group name="group_top" col="4">
    <field name="request_date"/>
    <field name="user_id"/>
    <span colspan="2"/>
    <field name="close_date"/>
</group>

页签

<notebook> 是带多个页签的容器，用来把不常用的数据收起来，或者按主题组织大量字段。借书单的第一个页签放借的书： 

<notebook>
    <page name="page_lines" string="Borrowed Books">
        <field name="line_ids">
            <list editable="bottom">
                <field name="book_id"/>
                <field name="note"/>
            </list>
            <form>
                <group>
                    <field name="book_id"/>
                    <field name="note"/>
                </group>
            </form>
        </field>
    </page>
</notebook>
  • 多加几个 <page> 就是多个页签。string 是页签标题；invisible 可以按条件隐藏整个页签。
  • 页签里和 sheet 一样，不在 group 里的字段不显示标签。这里一对多字段占满整页，不需要标签。
  • 关系字段内部可以内嵌视图定义：明细列表用内嵌的 <list>；如果去掉 editable，点击一行会弹出用内嵌 <form> 渲染的对话框。

字段

在表单和列表里，<field> 元素用组件（widget）显示和编辑模型字段的数据。它的许多属性默认取自模型定义，但可以在视图里覆盖：

属性作用
name模型里的字段名
string标签文字，覆盖模型定义
help悬停提示
placeholder输入框为空时的提示文字
widget使用指定的组件显示
options传给组件的选项，JSON 风格的字典
classCSS 类
nolabel="1"在 group 里不显示自动标签，常和单独的 <label for> 配合
invisible / readonly / required隐藏 / 只读 / 必填。可以是 1，也可以是条件表达式（见「动态属性」一节）

ⓘ 隐藏字段不能被写入

invisible 的字段数据仍然会加载到表单上，但用户无法修改它。

每种字段类型都有默认组件，另外还有很多可选的。最常用的：

关系字段默认允许打开关联记录、在下拉框里直接新建（快速创建）。可以用选项关掉：

💡 找组件的地方

所有可用组件都在源码 addons/web/static/src/views/fields/ 下，每个子目录一个。其他应用也会注册自己的组件（比如 mail 的活动组件）。 开发者模式下悬停在字段上，提示里会显示它当前用的是哪个组件 —— 看到一个喜欢的效果，这样就能知道该怎么写。

按钮

按钮让用户触发动作：打开另一个视图，或者执行服务器上的业务逻辑。它可以放在页眉里，也可以放在表单和列表的任何地方。

属性作用
string按钮文字（有图标时作为提示文字）
typeobject（调用模型方法）或 action（执行一个动作）
name方法名，或动作的数据库 ID。用 %(xml_id)d 可以在加载视图时把 XML ID 翻译成数据库 ID
argstype="object" 时传给方法的额外参数
context设置上下文，被调用的方法或打开的视图都能读到
confirm点击后、执行前弹出的确认提示
special="cancel"向导里的「取消」按钮：关闭对话框，什么都不做
icon图标名，如 icon="book"
class样式，如 oe_highlight、btn-primary、btn-secondary、oe_link
⇪ 图标换成了 Material Symbols

书里的图标来自 Font Awesome：icon="fa-book"、<i class="fa fa-calendar"/>。 Odoo 19.5 起，界面图标统一换成了 Google 的 Material Symbols，按钮的 icon 属性直接写图标名： icon="book"、icon="calendar_month"；HTML 里写成 <i class="oi" data-icon="book"/>。 旧的 fa- 名字不会再显示。可以在 Material Symbols 网站上按英文关键词搜图标名；odoo-bin upgrade_code 带有自动转换脚本。

智能按钮

很多单据表单右上角有一排智能按钮：小方块，显示一个统计数字，点击后跳到相关记录。 比如在借书单上显示「这位会员还有几张未还的借书单」，点击打开它们的列表。

先需要一个计算字段提供统计数字。直观的写法是在循环里对每条记录做一次计数查询：

    count_checkouts = fields.Integer(compute="_compute_count_checkouts")

    def _compute_count_checkouts(self):
        for checkout in self:
            domain = [
                ("member_id", "=", checkout.member_id.id),
                ("state", "not in", ["done", "cancel"]),
            ]
            checkout.count_checkouts = self.search_count(domain)
⚠ 别在循环里查数据库

上面的写法违反了一个性能原则：在列表里显示 80 条借书单，就会执行 80 次查询。正确的做法是在循环之前一次性查出所有需要的数据，循环里只做查表： 

    def _compute_count_checkouts(self):
        domain = [
            ("member_id", "in", self.member_id.ids),
            ("state", "not in", ["done", "cancel"]),
        ]
        # _read_group 返回 [(会员记录, 数量), ...]，转成字典便于查找
        counts = dict(self._read_group(domain, ["member_id"], ["__count"]))
        for checkout in self:
            checkout.count_checkouts = counts.get(checkout.member_id, 0)

self.member_id 对多条记录调用时，返回所有不重复的会员组成的记录集。_read_group（第 7 章）一次查询得到每位会员的数量。 字典的键是会员记录本身，所以直接用 checkout.member_id 查找。

然后在按钮盒里放智能按钮：

<div class="oe_button_box" name="button_box">
    <button type="action"
            name="%(action_library_checkout)d"
            class="oe_stat_button"
            icon="book"
            domain="[('member_id', '=', member_id)]"
            context="{'default_member_id': member_id}">
        <field name="count_checkouts" string="Checkouts" widget="statinfo"/>
    </button>
</div>
  • class="oe_stat_button" 让按钮显示为方块样式；icon 设置图标。
  • 按钮是一个容器，里面放一个用 statinfo 组件的统计字段，字段的 string 作为按钮上的文字。
  • type="action" 执行窗口动作，%(action_library_checkout)d 把 XML ID 转成动作的数据库 ID。
  • domain 只显示相关记录；context 让在打开的列表里新建的记录自动填上当前会员。help 属性可以加悬停提示。

动态视图元素

onchange 与计算字段

用户在表单上修改数据时，onchange 机制会把修改发给服务器，执行 @api.onchange 方法，并自动重算相关的计算字段， 结果立即反映到表单上（第 8 章）。这一切不需要在视图里写任何东西。

条件属性：invisible、readonly、required

视图元素的 invisible、readonly、required 属性可以是一个条件表达式，根据记录当前的值动态求值： 

<!-- 只有已归还的借书单才显示归还日期 -->
<field name="close_date" invisible="state != 'done'"/>

<!-- 已借出之后，会员不能再改 -->
<field name="member_id" readonly="state in ('open', 'done')"/>

<!-- 已取消时备注必填 -->
<field name="note" required="state == 'cancel'"/>

<!-- 用于任何元素：页签、分组、按钮…… -->
<page name="page_admin" string="Admin" invisible="not user_id"/>

<!-- 也可以引用父记录（在一对多的明细行里）和上下文 -->
<field name="note" readonly="parent.state == 'done'"/>

表达式里可以使用：

  • 当前记录的任意字段名（字段不必出现在视图里，会自动加载）
  • parent：在一对多内嵌视图里引用父记录
  • context、uid（当前用户 ID）、context_today() 等
  • Python 风格的运算：==、!=、in、not、and、or

另外，任何元素都可以用 groups 属性，只对指定用户组的成员显示：groups="library_app.library_group_manager"。

ⓘ 界面限制不是安全措施

readonly、invisible 只影响界面。懂技术的用户依然可以通过外部 API 写入这些字段。 真正需要禁止的事情，要用访问规则、约束或在 write() 里检查来保证。（字段定义上的 groups 属性是例外，它会在服务端限制访问。）

列表视图

列表视图把记录显示为行、字段显示为列，默认只读，也可以设为可编辑。上面讲的字段和按钮属性在列表里同样适用。

<record id="view_list_checkout" model="ir.ui.view">
    <field name="name">Checkout List</field>
    <field name="model">library.checkout</field>
    <field name="arch" type="xml">
        <list decoration-muted="state in ('done', 'cancel')"
              decoration-bf="state == 'open'">
            <header>
                <button type="action"
                        name="%(action_checkout_message)d"
                        string="Send Messages"/>
            </header>
            <field name="name"/>
            <field name="request_date"/>
            <field name="member_id"/>
            <field name="user_id" optional="hide" widget="many2one_avatar_user"/>

            <field name="num_books" sum="Total Books"/>

</record>

页眉按钮

列表也可以有 <header>，放作用于选中记录的按钮，比藏在「操作」菜单里更显眼。按钮只在有记录被选中时出现。

行装饰

根据条件表达式改变整行的颜色或字体：

属性效果属性效果
decoration-bf加粗decoration-it斜体
decoration-muted灰色decoration-primary主题色
decoration-info蓝色decoration-success绿色
decoration-warning黄色decoration-danger红色

这些名字来自 Bootstrap 的颜色体系。装饰属性也可以用在单个 <field> 上，只改变那一个单元格。

列汇总

数值字段可以在列底部显示汇总：sum、avg、min、max，属性值是汇总的说明文字。 例子里的 num_books 是第 8 章练习里的计算字段： 

    num_books = fields.Integer(compute="_compute_num_books", store=True)

    @api.depends("line_ids")
    def _compute_num_books(self):
        for checkout in self:
            checkout.num_books = len(checkout.line_ids)

分组小计只对存储的字段有效，所以加了 store=True。后面的透视表和图表视图也需要它是存储字段。

其他列表属性

属性作用
default_order默认排序，如 default_order="request_date desc"
create / edit / delete设为 false 时禁用相应操作
editable="top|bottom"在列表里直接编辑，新行加在顶部 / 底部
multi_edit="1"选中多行后可以一次修改它们的同一个字段

搜索视图

视图右上方的搜索框，以及它下面的「筛选」「分组」「收藏」，都由搜索视图配置。开发者模式下，调试菜单 → SearchView 可以查看当前的搜索视图。 

<record id="view_filter_checkout" model="ir.ui.view">
    <field name="model">library.checkout</field>
    <field name="arch" type="xml">
        <search>
            <field name="name"/>
            <field name="member_id"/>
            <field name="user_id"/>

            <filter name="filter_not_done" string="To Return"
                    domain="[('state', '=', 'open')]"/>
            <filter name="filter_my_checkouts" string="My Checkouts"
                    domain="[('user_id', '=', uid)]"/>
            <separator/>
            <filter name="filter_request_date" string="Request Date"
                    date="request_date"/>

            <filter name="group_member" string="By Member"
                    context="{'group_by': 'member_id'}"/>

            <searchpanel>
                <field name="member_id" enable_counters="1"/>
                <field name="stage_id" select="multi"/>
            </searchpanel>
        </search>
    </field>
</record>

<field>：搜索建议

用户在搜索框里打字时，会看到「在 xxx 中搜索」的建议，每个 <field> 对应一条。可用属性：

  • name：要搜索的字段；string：显示的标签。
  • operator：使用不同于默认的运算符（默认：数值用 =，其他用 ilike）。
  • filter_domain：自定义搜索用的域，输入的文字用 self 引用。比如同时搜书名和 ISBN：filter_domain="['|', ('name', 'ilike', self), ('isbn', 'ilike', self)]"。
  • groups：只对某些组开放。

<filter>：预定义的筛选和分组

  • name：标识符，用于扩展，或在动作上下文里用 search_default_名字 默认开启。强烈建议总是写上。
  • string：显示的文字，必填。
  • domain：筛选条件。可以用 uid 表示当前用户。
  • context：通常用 {'group_by': '字段'} 定义一个分组选项（日期字段可写 'request_date:month'）。
  • date="日期字段"：日期筛选，自动提供按年、季度、月选择的子菜单。
  • groups：只对某些组显示。

筛选之间的组合规则：同一块里的筛选同时选中时是「或」，被 <separator/> 分开的不同块之间是「且」。 所以把互斥的选项放在一块（「已借出」或「已归还」），把正交的条件分开（「我的」且「本月的」）。

⇪ 日期筛选的范围属性被移除

Odoo 20 不再解析日期筛选上的 start_month、end_month、start_year、end_year 属性（RNG 校验会直接拒绝它们）， 只写 <filter name="..." date="request_date"/> 即可。

搜索面板

<searchpanel> 在视图左侧显示一个导航面板，列出某个字段的所有取值，点击即按它筛选。默认在列表和看板视图中显示（可用 view_types 属性修改）。 面板里的 <field> 支持：

  • select="multi"：显示复选框，可以多选（用于多对一和多对多字段）。
  • enable_counters="1"：每个值旁边显示记录数。数据量大时注意性能。
  • icon、color：图标和颜色。
  • limit：最多显示多少个值，默认 200，0 表示不限。
  • string、groups：标签和可见组。

日历视图

<record id="view_calendar_checkout" model="ir.ui.view">
    <field name="model">library.checkout</field>
    <field name="arch" type="xml">

            <field name="member_id"/>

属性含义
date_start开始日期字段（必填）
date_stop / date_delay结束日期字段 / 持续时长（天）字段，二选一
all_day表示「全天事件」的布尔字段
color按哪个字段给条目着色，同一个值同一种颜色
mode / scales默认显示方式（day / week / month / year）/ 可选的显示方式

透视表和图表视图

<record id="view_pivot_checkout" model="ir.ui.view">
    <field name="model">library.checkout</field>
    <field name="arch" type="xml">
        <pivot sample="1">
            <field name="stage_id" type="col"/>
            <field name="member_id" type="row"/>
            <field name="request_date" interval="week" type="row"/>
            <field name="num_books" type="measure"/>
        </pivot>
    </field>
</record>

<record id="view_graph_checkout" model="ir.ui.view">
    <field name="model">library.checkout</field>
    <field name="arch" type="xml">
        <graph type="bar" stacked="True" sample="1">
            <field name="stage_id"/>
            <field name="num_books" type="measure"/>
        </graph>
    </field>
</record>
  • type：row（默认，行分组）、col（列分组，仅透视表）、measure（度量，被汇总的值）。
  • interval：日期字段的分组粒度，day、week、month、quarter、year。
  • 图表的 type 可以是 bar（默认）、line、pie；柱状图加 stacked="True" 变成堆叠柱状图。
  • 度量字段必须是存储的字段，所以 num_books 要 store=True。

小结

  • 菜单是树，叶子菜单挂窗口动作；窗口动作决定模型、视图、域、上下文，binding_model_id 把它放进操作菜单。
  • 单据式表单 = <header>（按钮 + 状态栏）+ <sheet>（按钮盒、标题、group、notebook）+ <chatter/>。
  • group 默认两列，嵌套 group 得到左右两栏；col / colspan 精细控制。
  • 字段可以覆盖标签、组件和选项；按钮分 object 和 action 两类；智能按钮是装着 statinfo 字段的动作按钮。
  • Odoo 17+ 用条件表达式写 invisible / readonly / required，attrs 和 states 已移除；图标改用 Material Symbols 名称。
  • 列表视图：页眉按钮、行装饰、列汇总、可选列、行内编辑。
  • 搜索视图：<field> 提供搜索建议，<filter> 提供筛选和分组，<searchpanel> 提供左侧导航。
  • 活动、日历、透视表、图表视图让同一份数据有更多看法；度量字段需要存储。
