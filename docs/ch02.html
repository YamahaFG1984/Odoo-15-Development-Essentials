第 2 章

准备开发环境

第 1 章是在浏览器里「点」，从这一章开始我们要写代码了。写代码之前，得先有一个属于自己的 Odoo： 从源码安装、能随时重启、能同时跑好几个数据库、能看懂日志。这一章就把这套工作台搭好。

本章目标

  • 准备一台 Ubuntu 主机（真机、云服务器或 Windows 上的 WSL 都行）
  • 在 Python 虚拟环境里从 GitHub 源码安装 Odoo 20
  • 用命令行创建、复制、删除数据库
  • 理解配置文件、端口、数据库过滤、日志这些常用服务器选项
  • 把第三方模块（包括本书代码）加入插件路径，并打开开发者选项 --dev

准备一台 Ubuntu 主机

Odoo 官方推荐、也最常用的运行平台是 Debian / Ubuntu：Odoo 自己的 SaaS 就跑在 Debian 系统上，社区里绝大多数经验也基于它。 遇到问题时，用 Ubuntu 最容易找到答案。

⇪ 环境要求升级了

书里用的是 Ubuntu 20.04 + Python 3.6+。Odoo 20 的源码里写明了最低要求：Python 3.12、PostgreSQL 16， 官方支持的发行版是 Ubuntu 24.04 LTS。本章所有命令都以 Ubuntu 24.04 为准，它自带的正好是 Python 3.12 和 PostgreSQL 16。

你可以选择：

  • 已有的 Ubuntu 24.04：桌面版、服务器版、云主机都行，不需要图形界面，只要终端。先运行 sudo apt list 确认自己有管理员权限。
  • Windows 10/11 用 WSL：在 Windows 里跑一个真正的 Ubuntu，下面详述。
  • 不想在本机装？用 Docker：一条命令启动 Odoo 20 和 PostgreSQL，Windows、macOS、Linux 通用，见第 17 章。本章的源码安装仍然值得读，它能让你看清 Odoo 由哪些部分组成。
  • 虚拟机：用 VirtualBox 等软件装一个 Ubuntu Server。
ⓘ 不想自己管服务器？

Odoo 官方有一个托管平台 Odoo.sh，基于 Git 分支提供开发、测试、生产环境和邮件等配套服务。 它适合正式项目，但学习阶段在本机装一个更直观，我们也更能看清楚每一步在做什么。

在 Windows 上安装 WSL

WSL（Windows Subsystem for Linux）让你在 Windows 里运行一个完整的 Linux。以管理员身份打开 PowerShell，执行： 

wsl --install -d Ubuntu-24.04

重启后打开开始菜单里的「Ubuntu」，按提示设置 Linux 用户名和密码。记住这个密码，以后执行 sudo 都要用它。 在 Windows 资源管理器里输入 \\wsl$ 可以直接访问 Linux 里的文件。

从源码安装 Odoo 20

为什么从源码装，而不是用安装包？

  • 开发时你会频繁读 Odoo 自己的源码 —— 它是最好的文档。源码就在手边，随时 grep。
  • 用 Git 管理，切换版本、更新到最新修复都只需要一条命令。
  • 可以在同一台机器上并存多个 Odoo 版本，各自用独立的 Python 环境。

整个安装由下面几块组成，我们一块块来：

第一步：安装 PostgreSQL

sudo apt update
sudo apt install postgresql                     # 安装 PostgreSQL
sudo -u postgres createuser -s $USER            # 为当前系统用户创建数据库超级用户

最后一行很关键：它以 postgres 管理员身份，创建一个和你的 Linux 用户同名的数据库用户，并赋予超级用户权限。 这样以你的身份运行的 Odoo 就能连上数据库，并且能创建、删除数据库。PostgreSQL 默认用「同名本地用户免密」的方式认证，所以不需要设密码。

💡 WSL 用户注意

WSL 里的系统服务默认不会自动启动。每次打开 Ubuntu 后，先执行 sudo service postgresql start。

⚠ 开发可以，生产不行

开发环境里让 Odoo 用超级用户连数据库很方便；生产环境中，Odoo 应该用一个非超级用户的数据库账号运行。第 15 章会讲。

第二步：安装系统依赖

sudo apt install git python3-dev python3-pip python3-venv \
    build-essential libpq-dev libxml2-dev libxslt1-dev \
    libldap2-dev libsasl2-dev libssl-dev libjpeg-dev zlib1g-dev

有些 Python 库（比如连接 PostgreSQL 的 psycopg2、处理 XML 的 lxml、处理图片的 Pillow）在安装时需要编译 C 代码， 所以要先装这些「-dev」开发包。如果后面 pip install 报编译错误，十有八九是这里少了什么。

ⓘ 另一条路：直接用系统包

Odoo 源码里附带了一个脚本 setup/debinstall.sh，它会读取 debian/control 里的依赖列表，用 apt 一次性装好所有 python3-* 系统包。这样连虚拟环境都不需要。不过本教程仍然推荐虚拟环境，因为它能让不同项目互不干扰。

第三步：获取 Odoo 源码

mkdir ~/work20 && cd ~/work20
git clone https://github.com/odoo/odoo.git -b 20.0 --depth=1
  • -b 20.0：明确只取 20.0 这个分支。不要用 master，那是还在开发中的下一个版本。
  • --depth=1：只下载最新一次提交，不要几十年的完整历史，体积能小一个数量级。
💡 以后想要历史记录？

git fetch --unshallow 补全全部历史；git fetch --depth=100 只补最近 100 次提交； git fetch --shallow-since=2026-01-01 补某个日期之后的。

第四步：创建虚拟环境并安装依赖

虚拟环境是一个独立的 Python 安装目录。在它里面装的库不会影响系统，也不会被系统更新影响； 你还可以为不同的 Odoo 版本建不同的虚拟环境。 

python3 -m venv ~/work20/env20          # 创建虚拟环境
source ~/work20/env20/bin/activate      # 激活它
(env20) $ which python                  # 确认现在用的是虚拟环境里的 python
/home/you/work20/env20/bin/python

(env20) $ pip install -U pip
(env20) $ pip install -r ~/work20/odoo/requirements.txt   # 安装 Odoo 的全部依赖
(env20) $ pip install -e ~/work20/odoo                    # 把 Odoo 本身装成「可编辑」模式

激活后，命令提示符前面会出现 (env20)，这时 python 和 pip 都指向虚拟环境里的版本。 要退出，执行 deactivate。以后每次开新终端，都要先激活。

pip install -e 的 -e 表示「可编辑安装」：pip 不会把源码拷贝到别处，而是直接引用 ~/work20/odoo 目录。 这样你 git pull 更新源码后，不需要重新安装就生效。安装后会多出一个 odoo 命令。 

(env20) $ odoo --version
Odoo Server 20.0

去掉 --version 直接运行 odoo，服务器就会启动并一直等待请求。浏览器访问 http://localhost:8069。 按 Ctrl+C 停止服务器。

创建和管理数据库

在网页上创建

第一次访问 http://localhost:8069 时还没有任何数据库，Odoo 会显示一个创建数据库的表单：

字段含义
Master Password数据库管理器的主密码，存在服务器配置文件里。新版本会自动生成一个。
Database Name数据库名。同一个 PostgreSQL 里可以放很多个 Odoo 数据库，靠名字区分。
Email管理员的登录名，不一定要是真实邮箱，比如 admin。
Password管理员的登录密码。
Language / Country默认语言和公司所在国家（会影响会计等本地化功能）。
Demo data是否装入演示数据。开发和测试时通常勾上，有现成的客户、产品等数据可以玩。

创建完成后会跳到登录页。登录页底部的 Manage databases，或者直接访问 /web/database/manager，就是数据库管理器： 可以创建、备份、复制、删除数据库。

⚠ 生产环境要保护好数据库管理器

数据库管理器能做的事非常危险。生产环境中务必在配置文件里设置强主密码（admin_passwd = ...）， 更好的做法是直接关掉它（list_db = False）。

在命令行创建

开发时我们会经常建库、删库，命令行更快。先 Ctrl+C 停掉服务器，然后：

(env20) $ odoo -d 20-demo --with-demo --stop-after-init
  • -d 20-demo：使用名为 20-demo 的数据库，不存在就自动创建并初始化。
  • --with-demo：装入演示数据。
  • --stop-after-init：初始化完就退出，回到命令行。去掉它，服务器会在初始化后继续运行。
⇪ 演示数据默认不装了

Odoo 15 新建数据库时默认装演示数据，书里要用 --without-demo=all 才能不装。 从 Odoo 18.3 起反过来了：默认不装，需要时加 --with-demo。

如果没有用 --stop-after-init，留意日志里一行 INFO ... odoo.modules.loading: Modules loaded.，看到它就说明数据库加载完毕、可以接受请求了。 它不一定是最后一行，可能在倒数三四行。启动日志开头还有一行 HTTP service running on 主机名:8069，告诉你该访问哪个地址。

💡 开发时最常按的组合键

Ctrl+C 停止 → ↑ 调出上一条命令 → Enter。这就是「重启 Odoo」。

Odoo 20 的数据库子命令

Odoo 20 自带了一个命令行版的数据库管理器 odoo db，所有操作都会连同 filestore 一起处理： 

odoo db init 20-test --with-demo          # 创建并初始化一个新数据库
odoo db duplicate 20-demo 20-demo-copy    # 复制（含附件）
odoo db dump 20-demo                      # 导出为带 filestore 的 zip
odoo db load backup.zip                   # 从 dump 恢复
odoo db drop 20-demo-copy                 # 删除（含附件）

odoo module install -d 20-test contacts   # 给某个库安装模块

用 PostgreSQL 工具直接操作

这些 PostgreSQL 自带的命令也很常用，但要注意它们只处理数据库，不处理 filestore：

createdb MyDB                          # 手动创建一个空库
createdb --template=MyDB MyDBCopy      # 以 MyDB 为模板复制一个库（MyDB 不能有连接）
psql -l                                # 列出所有数据库
dropdb MyDBCopy                        # 删除数据库，不可恢复！
⚠ dropdb 没有回收站

删掉就是删掉了。对重要的数据库，动手之前先备份。

服务器选项和配置文件

Odoo 服务器有上百个选项，odoo --help 可以看全部。下面介绍最常用的几个。

配置文件

每次都在命令行敲一长串选项太累了。几乎所有选项都可以写进一个配置文件。不指定时，Odoo 默认读取 ~/.odoorc。 用 --save 可以把当前命令行上的选项保存进去： 

# 把选项存进指定的配置文件（不存在就创建）
(env20) $ odoo -c ~/work20/20-demo.conf -d 20-demo --save --stop

# 以后只要指定配置文件就行
(env20) $ odoo -c ~/work20/20-demo.conf

生成的文件是普通的 INI 格式，一个开发用配置文件大致是这样（只列出关键项）：

[options]
; 插件路径：Odoo 去哪些目录找模块，逗号分隔
addons_path = /home/you/work20/library,/home/you/work20/odoo/addons
; 默认使用的数据库
db_name = 20-demo
; 只允许访问名字匹配这个正则的数据库
dbfilter = ^20-demo$
; HTTP 端口
http_port = 8069
; 数据库管理器的主密码
admin_passwd = 一个很长的随机字符串
💡 选项可以缩写

只要不产生歧义，长选项可以缩写，比如 --stop-after-init 写成 --stop。

换端口：同时跑多个 Odoo

默认端口是 8069。用 -p（即 --http-port）可以换一个，这样同一台机器能同时跑多个 Odoo 实例：

# 终端 1
(env20) $ odoo -p 8070
# 终端 2
(env20) $ odoo -p 8071

这两个实例可以用相同或不同的数据库，甚至可以是不同版本的 Odoo —— 只要不同版本用不同的数据库。

限定可访问的数据库

同一个 Odoo 服务器可以服务多个数据库。有两个选项控制这一点：

--db-filter 的值是正则表达式，几个常用写法：

表达式含义能匹配
^20以 20 开头20-demo、20-library
demo$以 demo 结尾20-demo、19-demo
^20-demo$完全等于只有 20-demo
^20-demo.$. 是任意一个字符20-demo1、20-demo2
^20.*demo$.* 是任意多个字符20-demo、20-my-demo
ⓘ 浏览器里还开着旧会话？

如果你用 -d 重启服务器换了一个库，浏览器里之前登录另一个库的页面会报错 —— 那个库现在被拒绝访问了。重新打开 localhost:8069 即可。

读懂日志

Odoo 默认把日志打印到终端。每一行日志都有固定的结构：

HTTP 请求的日志更长一些，末尾带着性能数据：

... INFO 20-demo odoo.http.server: 127.0.0.1 - - [22/Oct/2026 08:06:57]
    "POST /web/dataset/call_kw/res.partner/web_read HTTP/1.1" 200 - 21 0.035 0.092 ro

最后几个数字很有用：

  • 21：这个请求执行了多少条 SQL 查询
  • 0.035：SQL 查询总耗时（秒）
  • 0.092：除 SQL 外的耗时，基本就是 Python 代码的执行时间

某个页面慢？先看这几个数字，就知道是数据库慢还是代码慢。

⇪ 新的 HTTP 服务器

书里的请求日志来自 werkzeug 模块。Odoo 19.4 起换成了基于 h11 的新 HTTP 服务器， 请求日志改由 odoo.http.server 输出，格式基本相同，末尾多了一列表示数据库游标模式（ro 只读 / rw 读写）。

控制日志的选项：

选项作用
--log-level=debug整体日志级别。从安静到啰嗦：critical、error、warn、info（默认）、debug、debug_rpc、debug_sql、debug_rpc_answer
--log-handler=模块:级别只调整某个模块的级别，可以写多次。例如 --log-handler=odoo.modules:DEBUG
--log-sql打印执行的 SQL（等于 odoo.sql_db:DEBUG）
--log-web调试 HTTP 请求处理（等于 odoo.http:DEBUG）
--logfile=路径写到文件而不是终端。Linux 上惯例放在 /var/log/odoo/

试试 odoo --log-level=debug_sql，然后在网页上随便点几下，看看终端里刷出的 SQL —— 这能让你直观感受到 ORM 在背后做了什么。

找到并安装更多模块

Odoo 生态里有海量现成模块，主要来源：

  • apps.odoo.com：官方应用商店，有免费也有付费。
  • github.com/OCA：Odoo 社区协会维护的几百个仓库，质量有保障，全部开源。

装模块最「直觉」的做法是把它拷进 ~/work20/odoo/addons/，和官方模块放一起。别这样做。 那个目录是一个 Git 仓库，我们希望它和上游保持同步；混进别人的模块会让更新变得一团糟。 正确做法是把模块放在独立的目录里，然后告诉 Odoo 也去那里找。

插件路径（addons_path）

拿本书的示例代码试一下：

cd ~/work20
git clone https://github.com/PacktPublishing/Odoo-15-Development-Essentials.git library

source env20/bin/activate
(env20) $ odoo -d 20-library --addons-path="./library,./odoo/addons"

启动日志的前几行会有一行 INFO ? odoo: addons paths: [...]，确认里面包含了 library 目录。 Odoo 自己的 odoo/odoo/addons（base 模块所在地）总是会被自动加入，不需要写。

⚠ 书中原版代码不能直接装进 Odoo 20

这个仓库的代码是为 Odoo 15 写的，有 <tree>、attrs、ir.model.access.csv 等旧写法，在 Odoo 20 上安装会报错。 从第 3 章开始，我们会一边讲一边把每个模块改写成 Odoo 20 的版本。上面这一步只是演示 addons_path 怎么用。

💡 一个仓库还是一个模块？

addons_path 里的每个目录，应该是「装着若干个模块的目录」，而不是模块本身。 比如 OCA 的仓库 OCA/web 克隆下来是一个目录，里面有几十个模块，把这个目录加进路径即可。

开发选项 --dev

Odoo 有一个服务器端的「开发模式」，用 --dev=all 打开（和第 1 章浏览器里的开发者模式是两回事）：

(env20) $ pip install watchdog       # 自动重载需要它来监视文件变化
(env20) $ odoo -d 20-library --dev=all

all 等于同时打开下面四项，你也可以用逗号只开其中几项：

功能效果
reload保存 Python 文件后，服务器自动重启。不用每次手动 Ctrl+C。
xml视图直接从源码的 XML 文件读取，而不是从数据库读。改了视图刷新浏览器就生效，不用升级模块。
qwebQWeb 模板出错时，在日志里打印编译后的模板，方便定位。
access出现访问权限错误时，在日志里打印完整的调用栈。
⇪ 调试器选项的变化

Odoo 15 的 --dev=all 还会在出异常时自动进入 pdb 调试器，并支持 --dev=ipdb 等写法。 Odoo 20 的 --dev 只保留了上表的功能（另有一个模拟只读副本的 replica）。需要断点调试时，直接在代码里写 breakpoint() 即可，第 8 章详细讲调试。

小结

  • Odoo 20 需要 Python 3.12+ 和 PostgreSQL 16+，推荐 Ubuntu 24.04；Windows 上用 WSL。
  • 从源码安装 = git clone 源码 + 虚拟环境 + pip install -r requirements.txt + pip install -e。
  • 主密码管服务器上的数据库管理器，管理员密码管某个数据库的登录，两者无关。
  • -d 库名 --with-demo --stop 建库；odoo db ... 子命令连 filestore 一起管理。
  • 常用选项写进配置文件，用 -c 指定；-p 换端口；--db-filter 筛选数据库。
  • 自己的模块和第三方模块放在独立目录，通过 --addons-path 告诉 Odoo。
  • 开发时用 --dev=all，省掉大部分手动重启。

动手练习

  1. 按本章步骤装好 Odoo 20，创建一个带演示数据的 20-demo 库，用 admin / admin 登录。
  2. 把常用选项（插件路径、数据库、db-filter）存进 ~/work20/20-demo.conf，以后只用 odoo -c 启动。
  3. 在两个终端分别用 8070 和 8071 端口启动两个实例，分别连接两个不同的数据库。
  4. 用 --log-level=debug_sql 启动，打开联系人列表，数一数终端里出现了多少条 SQL。再对照请求日志末尾的查询数验证一下。
  5. 用 odoo db duplicate 复制一个库，再用 psql -l 确认它存在，最后用 odoo db drop 删除它。
