第 7 章

记录集：操作模型数据

模型定义好了，数据也装进去了。接下来要学的是：怎么用代码去查数据、读数据、改数据。 业务逻辑的绝大部分工作，归根结底就是「查询、变换、写回」。这一章我们打开一个交互式的 Odoo 命令行，边敲边学 ORM 的全部基本操作。

本章目标

  • 用 odoo shell 交互式地探索 ORM
  • 理解执行环境 env 和上下文 context，学会切换用户、公司和上下文
  • 用 search()、browse() 和域表达式查询记录；用 _read_group() 做分组统计
  • 读取字段值、沿关系导航，处理日期时间
  • 创建、修改、复制、删除记录；对记录集做过滤、映射、排序和集合运算
  • 理解事务，在必要时安全地执行原始 SQL

odoo shell：交互式实验场

Python 自带交互式命令行，Odoo 也提供了一个类似的：shell 子命令，后面跟上平时启动 Odoo 用的选项：

(env20) $ odoo shell -c ~/work20/library.conf -d library

它会像平常一样启动 Odoo、加载数据库，但不启动 HTTP 服务，而是给你一个 Python 提示符。这里预先准备好了两个变量： env（执行环境）和 self（超级用户 OdooBot 的用户记录），效果就像你正身处某个模型方法之中。 

>>> self
res.users(1,)
>>> self._name
'res.users'
>>> self.name
'OdooBot'
>>> self.login
'__system__'
  • self 是一个 res.users 记录集，包含 ID 为 1 的一条记录。
  • 它的模型名是 res.users，名字是 OdooBot，登录名 __system__。

按 Ctrl+D 退出。下面所有以 >>> 开头的例子都可以在 shell 里直接试。

⚠ shell 里的修改默认不保存

shell 模拟的是「一个方法正在执行」的环境：你做的写操作都在一个事务里，退出时不会自动提交。想让修改真正写进数据库，要显式执行 env.cr.commit()。这反倒让 shell 成了安全的实验场。

💡 更好用的 shell

如果虚拟环境里装了 ipython（pip install ipython），odoo shell 会自动用它，带语法高亮和 Tab 补全。也可以用 --shell-interface=ipython 指定。

执行环境

记录集总是在一个执行环境里工作，环境携带着「这次操作是在什么情况下发生的」：用哪个数据库游标、当前用户是谁、语言和时区是什么…… 在模型方法里通过 self.env 访问它。

属性含义
env.cr当前使用的数据库游标
env.user当前用户的记录
env.uid当前用户的 ID，等于 env.user.id
env.context上下文：一个不可变的字典
env.company当前活动的公司
env.companies用户当前选中的（允许的）公司
env.lang当前语言代码
env.su是否处于超级用户模式（跳过权限检查）
⇪ 别再用 self._cr、self._uid、self._context

老代码里常见 self._cr、self._uid、self._context 这种写法，Odoo 19 起它们被标记为废弃。 统一使用 self.env.cr、self.env.uid、self.env.context。

环境同时也是访问模型注册表的入口：

>>> env["res.partner"].search([("display_name", "like", "Azure")])
res.partner(14, 26, 33, 27)

注意结果不是按 ID 排的，而是按模型的默认排序（联系人的 _order 是按显示名称）。

上下文（context）

上下文是一个字典，在客户端界面和服务端逻辑之间传递「附加信息」。Web 客户端发来的初始上下文大致是这样： 

>>> env.context
{'lang': 'zh_CN', 'tz': 'Asia/Shanghai', 'uid': 2, 'allowed_company_ids': [1]}

上下文里的一些键会影响服务端的行为：

  • lang：决定可翻译字段读出哪种语言的值。
  • tz：时区。服务端存的时间都是 UTC，返回给客户端显示时按这个时区换算。
  • active_test：设为 False 时，search() 不再自动排除已归档（active=False）的记录。

从一个视图通过链接或按钮打开另一个视图时，Web 客户端会自动往上下文里加入来源信息，向导最常用到它们：

  • active_model：来源记录的模型名
  • active_id：来源记录的 ID
  • active_ids：在列表里选中的多条记录的 ID 列表

还有两种特殊前缀，第 1 章已经见过：

  • default_字段名：在目标视图里给这个字段设默认值，如 {'default_user_id': uid}。
  • search_default_筛选名：在目标视图里默认启用这个筛选，如 {'search_default_filter_my_books': 1}。

修改环境

有时需要以「另一种身份」或「另一种上下文」操作记录。下面这些方法都返回一个新的记录集（同样的记录，换了环境），原记录集不变：

方法效果
rs.with_context(key=value, ...)在现有上下文上增加 / 修改几个键
rs.with_context(字典)用这个字典整个替换上下文
rs.sudo()进入超级用户模式，跳过访问权限检查（用户本身不变）。sudo(False) 退出
rs.with_user(user)换成另一个用户的身份（参数为用户记录或 ID）
rs.with_company(company)切换当前公司
rs.with_env(env)整个换成另一个环境
>>> Book = env["library.book"]
>>> Book.with_context(active_test=False).search([])   # 连归档的书也查出来
>>> Book.with_context(lang="zh_CN").browse(1).name     # 读中文名
>>> demo = env.ref("base.user_demo")
>>> Book.with_user(demo).search([])                    # 以 Demo 用户身份查询（受其权限约束）
⚠ sudo() 要克制

sudo() 绕过所有访问规则。它适合那些「用户本身无权、但业务上必须做」的内部操作（比如普通用户下单时要读一下他看不到的价格表）， 用的时候要把范围控制到最小，用完不要把 sudo 过的记录集到处传。滥用 sudo 是 Odoo 模块最常见的安全漏洞来源。

环境还提供 env.ref()，根据 XML ID 取记录，不存在会抛出 ValueError：

>>> env.ref("base.user_root")
res.users(1,)
>>> env.ref("library_app.nonexistent", raise_if_not_found=False)   # 不存在时返回 None

查询数据

search、search_count、browse

先从环境里拿到模型，再调用查询方法得到记录集：

>>> Partner = env["res.partner"]
>>> Partner.search([("display_name", "like", "Lumber")])
res.partner(15, 34)
>>> Partner.search([("is_company", "=", True)], order="name desc", limit=5, offset=10)
>>> Partner.search_count([("is_company", "=", True)])
12
>>> Partner.browse([15, 34])
res.partner(15, 34)
  • search(domain, offset=0, limit=None, order=None)：返回满足域条件的记录集。如果模型有 active 字段，默认只返回有效记录。 order 是排序字符串（字段名可跟 desc）；limit 和 offset 用于分页。
  • search_count(domain)：只返回数量，比 len(search(...)) 高效得多。
  • browse(ids)：已经知道 ID 时直接构造记录集，不查询数据库，也不检查这些记录是否存在（需要时用 .exists()）。

域表达式详解

域（domain）是 Odoo 的筛选条件语法，ORM 把它翻译成 SQL 的 WHERE 子句。一个域是一个条件列表，每个条件是一个 (字段, 运算符, 值) 三元组； 空列表 [] 表示没有条件，匹配全部记录。

域在两种地方被求值：客户端（窗口动作、视图里的属性）和服务端（访问规则、Python 代码）。两边能用的东西略有不同，下面会指出来。

字段

第一个元素是字段名。可以用点号沿关系往下走，比如 "publisher_id.country_id.name"。 （较老的版本里客户端域不支持点号，那时的变通办法是在模型上加一个关联字段。现在两边都支持了。）

运算符

运算符含义示例
=　!=等于 / 不等于('state', '=', 'done')
>　>=　<　<=大小比较('copies', '>', 2)
in　not in值在 / 不在列表里('book_type', 'in', ['paper', 'hard'])
like　not like包含子串（区分大小写），自动在两边加通配符('name', 'like', 'Odoo')
ilike　not ilike同上，不区分大小写('name', 'ilike', 'odoo')
=like　=ilikeSQL LIKE 原样匹配，自己写 % 和 _('isbn', '=like', '978%')
=?值为空（False / None）时条件恒真，否则等同于 =('user_id', '=?', uid)
child_of是某记录的后代（含自身），需要层级结构('category_id', 'child_of', 4)
parent_of是某记录的祖先（含自身）('category_id', 'parent_of', 7)
any　not any关联记录中有 / 没有满足子域的('author_ids', 'any', [('country_id.code', '=', 'BR')])
⇪ any 运算符

书里没有 any / not any，它们是 Odoo 17 加入的：在关系字段上嵌套一个子域。 比如「至少有一位巴西作者的书」写成 [('author_ids', 'any', [('country_id.code', '=', 'BR')])]， 比用点号的写法语义更清晰，尤其在需要对同一条关联记录同时满足多个条件时（点号写法会把多个条件分散到不同的关联记录上）。

值

第三个元素是一个 Python 表达式，可以是字面量（数字、布尔、字符串、列表），也可以引用求值上下文里的变量。 不接受记录对象，要用 ID：写 [('user_id', '=', user.id)]，而不是 [('user_id', '=', user)]。

在访问规则（ir.access 的 domain）里，可以使用这些变量：

  • user：当前用户记录，用 user.id 取 ID
  • company_id：当前公司的 ID
  • company_ids：允许的公司 ID 列表。多公司规则的标准写法是 [('company_id', 'in', company_ids + [False])]
  • time：Python 的 time 模块

日期字段的值还可以写成相对日期，Odoo 会在执行时换算：

[('date_published', '>=', 'today -1y')]   # 一年以内出版的
[('create_date', '>=', 'today =1d')]      # 本月 1 日以来创建的
[('request_date', '<', 'today')]          # 今天以前的
⇪ 动态日期

以前要在 Python 里先算好日期再放进域，或者在 XML 里用 context_today() 拼表达式。Odoo 19 起，域里的日期值可以直接写 'today'、'now' 加上偏移量（+3d、-1m、=1d 等），这对写在视图和访问规则里的静态域尤其方便。

对多字段上的条件

当字段是一对多或多对多时，条件作用于它的每一个值，只要有任何一个满足，记录就会被选中。 所以 = 和 in 在这里的含义是「包含」；!= 和 not in 的含义是「一个都不包含」。

组合条件：前缀表示法

一个域里有多个条件时，默认用「且」（AND）连接。也可以显式使用逻辑运算符：'&'（且）、'|'（或）、'!'（非）。 域使用前缀表示法（也叫波兰表示法）：运算符写在它要作用的条件前面。& 和 | 作用于紧随其后的两项，! 作用于紧随其后的一项。

看一个访问规则里常见的例子：

['|',
    ('message_follower_ids', 'in', [user.partner_id.id]),
    '|',
        ('user_id', '=', user.id),
        ('user_id', '=', False)
]

它筛选出：当前用户是关注者的，或负责人是当前用户的，或还没有负责人的记录。

💡 读前缀表达式的窍门

从左往右读，遇到运算符就记住「它要吃掉后面两项」，遇到条件就把它喂给最近一个还没吃饱的运算符。 多个条件默认用 AND 连接，所以 [A, B, C] 等于 ['&', '&', A, B, C]；而 N 个条件全部用 OR，需要 N-1 个 '|' 放在最前面：['|', '|', A, B, C]。

特殊条件

(1, '=', 1) 表示恒真，(0, '=', 1) 表示恒假。在老版本的访问规则里，常用恒真条件让高级别的组看到全部记录； 在 Odoo 20 的 ir.access 里，域留空就表示「全部记录」，这种写法已不太需要了。

Domain 对象：用代码组合条件

在 Python 代码里拼接域列表很容易出错（尤其是 OR）。Odoo 18 起提供了 Domain 类，用 &、|、~ 组合条件： 

from odoo.fields import Domain

active = Domain("active", "=", True)
has_publisher = Domain("publisher_id", "!=", False)
recent = Domain("date_published", ">=", "today -5y")

domain = active & (has_publisher | recent)      # 且、或
not_recent = ~recent                             # 非
domain = Domain.AND([active, has_publisher])     # 多个一起
books = env["library.book"].search(domain)       # search 直接接受 Domain
books = env["library.book"].search(domain & [("copies", ">", 1)])   # 也可以和列表混用
⇪ odoo.osv.expression 已废弃

老代码里组合域用的是 from odoo.osv import expression 的 expression.AND([...]) / expression.OR([...])。Odoo 19 起 odoo.osv 被废弃，改用 Domain.AND / Domain.OR。

分组统计：_read_group

有时需要按字段分组并做汇总（计数、求和、平均……），类似 SQL 的 GROUP BY。在服务端代码里用 _read_group()： 

>>> env["res.partner"]._read_group(
...     domain=[("display_name", "like", "Azure")],
...     groupby=["country_id"],
...     aggregates=["state_id:count_distinct", "__count"],
... )
[(res.country(233,), 1, 4)]
  • domain：先用域筛选记录。
  • groupby：分组字段列表。日期字段可以带粒度，如 "date_published:year"、"create_date:month"。
  • aggregates：汇总列表，格式为 "字段:函数"，函数可以是 PostgreSQL 支持的 sum、avg、min、max、count， 以及 count_distinct；"__count" 表示每组的记录数；"字段:recordset" 把该组的关联记录聚成一个记录集。
  • 还支持 having（对汇总结果再筛选）、offset、limit、order。

返回值是一个元组列表，每个元组依次是分组值和汇总值。分组值如果是关联字段，会直接是一个记录集（上例的 res.country(233,)），可以继续 .name。 上例的意思是：在美国（233）有 4 位名字含 Azure 的联系人，他们分布在 1 个州。

⇪ read_group 变了样

书里用的 read_group(domain, fields=["state_id:count_distinct"], groupby=["country_id"], lazy=False) 返回的是带 __count、__domain 等键的字典列表。Odoo 18.2 起这个旧接口被废弃：服务端代码用 _read_group()（返回元组，分组值为记录集）， 给 Web 客户端用的格式化版本叫 formatted_read_group()。在 Odoo 20 里公开的 read_group() 也已改成和 _read_group() 相同的参数，只是把记录集换成了 ID。

读取记录集中的数据

单条记录

只包含一条记录的记录集叫单例（singleton）。单例可以直接用点号读字段：

>>> print(self.name)
OdooBot
>>> for rec in self:         # 单例也是记录集，也能遍历
...     print(rec.name)
OdooBot

对包含多条记录的记录集用点号读字段会报错。要批量取值，用 mapped()：rs.mapped("name") 返回所有记录的 name 组成的列表。 只对单条记录有意义的方法，在开头调用 self.ensure_one()，它会在 self 不是恰好一条记录时报错（空记录集也算错）。

空记录集也能读

一个很方便的特性：空记录集读任何字段都不会报错，而是返回 False（关系字段则返回一个空记录集）。 所以沿着关系一路点下去，中间某一环为空也没关系： 

>>> self.company_id
res.company(1,)
>>> self.company_id.name
'YourCompany'
>>> self.company_id.currency_id.name
'EUR'
>>> self.company_id.parent_id          # 没有上级公司
res.company()
>>> self.company_id.parent_id.name     # 不报错，返回 False
False

所以不需要写 if record: print(record.name)，直接 print(record.name or "（无）") 即可。

日期和时间

日期和日期时间字段的值就是 Python 原生的 date / datetime 对象，可以直接做运算：

>>> env["res.users"].browse(2).login_date
datetime.datetime(2026, 10, 22, 8, 47, 57, 327756)

数据库里的日期时间一律以 UTC 存储，不带时区信息；记录集里读出来的也是 UTC。显示给用户时，由 Web 客户端按用户的时区（上下文里的 tz）换算； 用户输入时，再由客户端换算回 UTC 发给服务器。

写入记录

直接赋值

记录集实现了「活动记录」（active record）模式：给字段赋值，修改就会被保存到数据库。多条记录的记录集也可以直接赋值，所有记录都会被修改。

>>> root = env["res.users"].browse(1)
>>> root.name = "Superuser"
>>> root.name
'Superuser'

各类字段的赋值规则：

  • 日期 / 日期时间：可以赋 Python 对象，也可以赋 Odoo 默认格式的字符串：rec.date = date(2026, 12, 1) 或 rec.date = "2026-12-01"。
  • 多对一：赋一个单例记录集（或空记录集 / False 清空）。
  • 对多字段：赋一个任意大小的记录集，整体替换原有关联。赋 False 或 None 清空。
  • 二进制：见下面的版本提示。

想在对多字段上追加或去掉记录，用记录集运算（后面详述）：

>>> mycompany_partner = self.company_id.partner_id
>>> myaddress = self.partner_id
>>> mycompany_partner.child_ids |= myaddress   # 追加
>>> mycompany_partner.child_ids -= myaddress   # 去掉
⇪ 二进制字段不再用 base64

书里给二进制字段赋值要先 base64.b64encode()。Odoo 19.3 起二进制字段的值是一个 BinaryValue 对象： 读取时用 rec.image_1920.content 拿到原始字节；写入时用 BinaryBytes 包装原始字节（可以附带文件名）。 直接赋原始 bytes 会报 TypeError；为了兼容 RPC，赋 base64 字符串仍然可以。 

from odoo.tools.binary import BinaryBytes

with open("/tmp/cover.png", "rb") as f:
    book.image = BinaryBytes(f.read(), filename="cover.png")
raw = book.image.content          # bytes

write()

write() 是底层的写方法，接受一个「字段名 → 值」的字典。外部 API 和 XML 数据加载都用它；当值是先准备成字典再统一写入时，它也比逐个赋值更方便： 

>>> recs = env["res.partner"].search([("name", "ilike", "Azure")])
>>> recs.write({"comment": "Hello!"})
True
>>> self.write({"child_ids": address1 | address2})           # 关系字段可以直接用记录集
>>> self.write({"child_ids": [Command.set([address1.id, address2.id])]})   # 等价的命令写法
ⓘ 写操作什么时候真正进数据库？

从 Odoo 13 起，ORM 的写操作先记在内存缓存里，并不立即生成 SQL；在需要时（比如要执行一次搜索、方法结束、事务提交前）才统一「冲刷」（flush）到数据库。 这避免了复杂依赖下对同一条记录的反复更新。大多数时候你感觉不到它的存在，但在执行原始 SQL 前要记得手动冲刷（见本章最后一节）。

创建、复制、删除

>>> Partner = env["res.partner"]
>>> new = Partner.create({"name": "ACME", "is_company": True})
>>> new
res.partner(59,)

>>> # 一次创建多条：传入字典列表，效率高得多
>>> Partner.create([{"name": "A"}, {"name": "B"}, {"name": "C"}])
res.partner(60, 61, 62)

>>> # 复制：可以传入要覆盖的值
>>> demo = env.ref("base.user_demo")
>>> john = demo.copy({"name": "John", "login": "john@example.com"})

>>> # 删除
>>> Partner.search([("name", "=", "ACME")]).unlink()
True
  • create() 接受一个字典或字典列表，会自动应用字段的默认值，返回新记录。
  • copy() 复制记录，copy=False 的字段不会被复制（对多字段默认不复制）。
  • unlink() 删除记录集里的所有记录。删除时可能连带删除相关记录（比如 chatter 消息、关注者），日志里会看到相应的 INFO 信息。

日期与时间运算

Odoo 的字段类提供了几个获取「现在」的辅助函数：

函数返回
fields.Date.today()今天（以 UTC 为准）。可直接作默认值：default=fields.Date.today
fields.Date.context_today(record)按记录上下文中用户时区算出的「今天」。用户在 UTC+8 的凌晨，这两者会不同
fields.Datetime.now()现在（UTC）。可直接作默认值：default=fields.Datetime.now
fields.Datetime.context_timestamp(record, dt)把一个 UTC 的 naive datetime 转成用户时区的、带时区信息的 datetime

日期运算用 Python 标准库：

>>> from datetime import date, timedelta
>>> date(2026, 11, 3) + timedelta(days=7)
datetime.date(2026, 11, 10)

>>> from dateutil.relativedelta import relativedelta      # timedelta 不支持「月」和「年」
>>> date(2026, 11, 3) + relativedelta(years=1, months=1)
datetime.date(2027, 12, 3)

Odoo 在 odoo.tools.date_utils 里还提供了几个顺手的函数（fields.Date 和 fields.Datetime 上也有同名方法）：

>>> from odoo.tools import date_utils
>>> from datetime import datetime
>>> now = datetime(2026, 11, 3)
>>> date_utils.start_of(now, "week")      # 本周开始；粒度可选 year/quarter/month/week/day/hour
datetime.datetime(2026, 11, 2, 0, 0)
>>> date_utils.end_of(now, "week")
datetime.datetime(2026, 11, 8, 23, 59, 59, 999999)
>>> date_utils.add(date(2026, 11, 3), months=2)
datetime.date(2027, 1, 3)
>>> date_utils.subtract(date(2026, 11, 3), months=2)
datetime.date(2026, 9, 3)

日期与文本互转

>>> fields.Date.to_string(date(2026, 11, 3))        # → '2026-11-03'（Odoo 服务器格式）
>>> fields.Datetime.to_datetime("2026-11-21 23:11:55")
datetime.datetime(2026, 11, 21, 23, 11, 55)
>>> date(2026, 11, 3).strftime("%d/%m/%Y")          # 其他格式用 strftime / strptime
'03/11/2026'
>>> datetime.strptime("03/11/2026", "%d/%m/%Y")

从外部拿到的时间文本通常是本地时间，存进 Odoo 之前要转成 UTC。比如上海用户的 2026-12-01 00:30 应该存成 2026-11-30 16:30 UTC： 

>>> from datetime import datetime
>>> from zoneinfo import ZoneInfo
>>> naive = datetime(2026, 12, 1, 0, 30)
>>> local = naive.replace(tzinfo=ZoneInfo(env.context.get("tz") or "UTC"))
>>> utc = local.astimezone(ZoneInfo("UTC")).replace(tzinfo=None)   # Odoo 存 naive 的 UTC
>>> utc
datetime.datetime(2026, 11, 30, 16, 30)
⇪ pytz → zoneinfo

书里用第三方库 pytz 做时区转换。Python 3.9 起标准库自带 zoneinfo，在 Odoo 20 要求的 Python 3.12 上直接可用，写法更简单。

记录集运算

常用方法

方法 / 属性作用
rs.idsID 列表
rs.ensure_one()确认恰好一条记录，否则报错
rs.exists()只保留数据库里仍然存在的记录
rs.filtered(函数 或 "字段路径")过滤，保留结果为真的记录
rs.filtered_domain(域)用域表达式在内存里过滤（不查数据库），保持原顺序
rs.mapped(函数 或 "字段路径")映射。字段路径的最后一段是关系字段时返回记录集，否则返回列表
rs.sorted(函数 或 "字段名", reverse=False)排序，返回新记录集
rs.grouped("字段名")按字段值分组，返回 {值: 记录集} 字典
>>> rs0 = env["res.partner"].search([("display_name", "like", "Azure")])
>>> len(rs0)
4
>>> rs0.filtered(lambda r: r.name.startswith("Nicole"))
res.partner(27,)
>>> rs0.filtered("is_company")
res.partner(14,)
>>> rs0.mapped("name")
['Azure Interior', 'Brandon Freeman', 'Colleen Diaz', 'Nicole Ford']
>>> rs0.mapped("parent_id")                  # 关系字段 → 记录集（自动去重）
res.partner(14,)
>>> rs0.sorted("name", reverse=True).mapped("name")
['Nicole Ford', 'Colleen Diaz', 'Brandon Freeman', 'Azure Interior']
>>> rs0.grouped("is_company")
{True: res.partner(14,), False: res.partner(26, 33, 27)}

切片与集合运算

记录集是不可变的：所有运算都返回新的记录集，原记录集不变。可以像列表一样切片：

  • rs[0]、rs[-1]：第一条、最后一条（空记录集时会报错）
  • rs[:1]：第一条，空记录集时返回空记录集 —— 更安全的「取第一条」写法
  • rs[1:]：除第一条外的其余记录

它们都可以和赋值合写，常用于修改对多字段：

  • self.author_ids |= author1：如果还没有，就加上 author1
  • self.author_ids -= author1：如果有，就去掉 author1
  • self.author_ids &= author1：只保留也在 author1 里的
⚠ 用 | 而不是 +

记录集也支持 +，但它是「拼接」而不是「并集」，会产生重复：env.user + env.user 得到 res.users(2, 2)。几乎所有场景你要的都是 |。

在循环里累积记录

有时要在循环里逐个得到记录再汇总。最直观的做法是从一个空记录集开始，不断 |=： 

Partner = env["res.partner"]
recs = env["res.partner"]          # 空记录集
for i in range(3):
    rec = Partner.create({"name": f"Partner {i}"})
    recs |= rec

但记录集是不可变的，每次 |= 都会复制一份新的，记录越多越慢，所以大循环里应避免。更好的做法： 

# 1. 先收集数据，最后一次性 create（最快）
values = [{"name": f"Partner {i}"} for i in range(3)]
recs = env["res.partner"].create(values)

# 2. 用 Python 列表收集记录，最后再转成记录集
recs = []
for i in range(3):
    recs.append(Partner.create({"name": f"Partner {i}"}))
recs = Partner.concat(recs)        # 在空记录集上调用，传入一个可迭代对象（Odoo 20 的写法）

很多时候循环本身就不需要，mapped()、filtered() 往往能一行解决。

比较

  • rec in rs / rec not in rs：某条记录是否在记录集里
  • rs1 <= rs2：rs1 的所有记录都在 rs2 里（子集）；< 是真子集
  • rs1 >= rs2、rs1 > rs2：反过来

事务与原始 SQL

事务

客户端发起的每一次调用都在一个数据库事务里执行。方法顺利执行完，所有修改一起提交；中途出错（抛出异常），所有修改一起回滚，数据回到调用前的状态。 这由框架自动处理，一般不需要操心。

在少数高级场景里需要手动控制事务，可以使用游标：

  • env.cr.commit()：提交到目前为止的修改。
  • env.cr.rollback()：撤销自上次提交以来的修改。
  • with env.cr.savepoint():：建一个保存点，块里出错只回滚这一块，外面的修改不受影响 —— 比手动 commit 安全得多。
for book in books:
    try:
        with self.env.cr.savepoint():
            book.do_something_risky()
    except Exception:
        _logger.exception("处理 %s 失败，跳过", book.name)
⚠ 在业务代码里别随便 commit

手动 commit() 会破坏「出错全部回滚」的保证：前半部分已经提交了，后半部分出错就只能留下半截数据。批处理里需要「单条失败不影响其他」时，优先用 savepoint()。

执行原始 SQL

极少数情况下（复杂报表、性能关键的批量操作），可以直接执行 SQL。Odoo 17 起提供了 SQL 包装对象，用它组装查询可以避免 SQL 注入： 

>>> from odoo.tools import SQL
>>> query = SQL("SELECT id, login FROM res_users WHERE login = %s OR id = %s", "demo", 1)
>>> env.execute_query(query)                 # 返回元组列表
[(6, 'demo'), (1, '__system__')]
>>> env.execute_query_dict(query)            # 返回字典列表
[{'id': 6, 'login': 'demo'}, {'id': 1, 'login': '__system__'}]

>>> # 底层游标的写法也照样可用
>>> env.cr.execute("SELECT id, login FROM res_users WHERE login = %(login)s", {"login": "demo"})
>>> env.cr.fetchall()
[(6, 'demo')]
⚠ 永远不要用字符串拼接 SQL

cr.execute("... WHERE login = '%s'" % login) 这种写法会让用户输入直接变成 SQL 的一部分，就是教科书式的 SQL 注入漏洞。 值一律通过 %s 占位符作为参数传入，由数据库驱动负责转义。

原始 SQL 绕开了 ORM，所以要自己处理两件事：

  • 执行前冲刷：ORM 可能还有没写进数据库的修改，用 env.flush_all()，或针对某个模型 env["library.book"].flush_model(["name"])。
  • 修改后失效缓存：执行了 UPDATE / INSERT 之类的语句后，ORM 缓存里的值已经过时，用 env.invalidate_all()，或 Model.invalidate_model([字段...])、records.invalidate_recordset([字段...])。
⇪ 缓存 API 的新名字

书里的 self.env.cache.invalidate(fnames, ids) 在 Odoo 16 起被 invalidate_all() / invalidate_model() / invalidate_recordset() 取代；对应的冲刷方法是 flush_all() / flush_model() / flush_recordset()。

⚠ 原始 SQL 是最后的手段

它绕过了访问权限、约束、计算字段的依赖重算和审计字段。只有在你非常清楚后果、并且 ORM 确实满足不了需求时才用。

小结

  • odoo shell 提供了 env 和 self，是探索 ORM 的最佳场所；修改需 env.cr.commit() 才会保存。
  • 环境 env 携带游标、用户、上下文、公司；with_context()、with_user()、with_company()、sudo() 返回换了环境的新记录集。
  • search() + 域表达式查询；search_count() 计数；browse() 按 ID 构造。域用前缀表示法组合，Python 里可用 Domain 对象。
  • 分组统计用 _read_group(domain, groupby, aggregates)，返回元组列表。
  • 点号读取对空记录集是安全的；日期时间以 UTC 存储、按用户时区显示。
  • 写入：直接赋值或 write()；create() 支持批量；copy()、unlink()。二进制字段用 BinaryBytes。
  • 记录集方法：filtered、mapped、sorted、grouped、filtered_domain；集合运算用 | & -，不用 +。
  • 每次调用是一个事务；需要局部回滚用 savepoint()；原始 SQL 用 SQL 对象，前冲刷、后失效。
