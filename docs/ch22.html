术语表与概念地图

Odoo 的概念不算多，但名字容易混：模型和模块差一个字，动作和视图总是一起出现，「继承」有四种…… 这个附录先用三张概念地图把核心概念串起来，帮你建立整体印象；后半部分是按主题排列的术语表，每个词一句话解释，并注明在哪一章详细讲解。 读到一半忘了某个词是什么意思，就回到这里查一查。

一句话区分

模块（module）是交付单位，一个目录；模型（model）是数据结构，一个 Python 类、一张表。 一个模块可以定义很多个模型，也可以只修改别的模块的模型。

术语表：平台与运行

社区版 / 企业版
社区版（Community）开源，LGPL-3 许可；企业版（Enterprise）在社区版之上增加了部分应用和功能，需要订阅。本教程的内容两者通用。第 1 章
模块（module / addon）
功能的交付单位：一个包含清单文件的目录。安装、升级、卸载都以模块为单位。第 3 章
应用（application）
清单里 application: True 的模块，会显示在应用列表的默认筛选里、出现在主菜单上。其余的模块是「技术模块」，提供功能但不单独成为一个应用。第 3 章
清单（manifest）
模块目录里的 __manifest__.py，一个 Python 字典：名字、版本、依赖、数据文件、资源包、许可证。第 3 章
依赖（depends）
清单里列出的「本模块需要先装哪些模块」。决定了安装顺序，也决定了你能继承哪些模型和视图。第 4 章
插件路径（addons_path）
Odoo 查找模块的目录列表。每一项是「装着模块的目录」，而不是模块本身。第 2 章
配置文件
用 -c 指定的 ini 文件，[options] 段里写命令行选项的长期设置。第 2 章
主密码（master password）
配置文件里的 admin_passwd，保护数据库管理器（建库、删库、备份）。和任何数据库里的用户密码无关。第 2 章
开发者模式（debug mode）
浏览器端的开关（网址加 ?debug=1），显示技术菜单、字段名提示和调试菜单。第 1 章
开发选项（--dev）
服务器端的开关：reload 自动重启、xml 从文件读视图、qweb、access 打印更多调试信息。和开发者模式是两回事。第 2 章
安装 / 升级（-i / -u）
安装：第一次加载模块的模型和数据；升级：按当前代码重新加载，更新表结构和数据记录。注意「升级模块」和「升级 Odoo 大版本」是两件事。第 3 章
odoo shell
带 Odoo 环境的 Python 交互命令行，env 已经准备好，可以直接操作数据。第 7 章
注册表（registry）
某个数据库的所有模型类的集合，服务器加载模块后在内存里建立。env['library.book'] 就是从注册表里取出模型。第 7 章
文件存储（filestore）
附件的实际文件存放在 data_dir 下的目录里，而不是数据库里。备份时数据库和文件存储都要备份。第 15 章
worker
生产环境的多进程模式里处理请求的子进程，数量由 workers 设置；为 0 时是开发用的多线程模式。第 15 章
OCA
Odoo Community Association，维护着上千个开源模块的社区组织，也制定了一套被广泛采用的编码规范。第 19 章
Odoo.sh
Odoo 官方的云托管平台，基于 Git 分支自动构建和部署。第 2 章

术语表：模型与 ORM

ORM
对象关系映射：用 Python 类和方法操作数据库，而不用手写 SQL。Odoo 的 ORM 还负责权限检查、计算字段、缓存和翻译。第 6 章
模型（model）
一种业务数据的定义，例如 library.book。一个 Python 类，通常对应数据库里的一张表。第 6 章
_name / _description
模型的技术名（带点号，如 library.book）和给人看的名称。表名由技术名把点换成下划线得到。第 6 章
字段（field）
模型的一个属性，如 fields.Char、fields.Date。大部分字段对应表里的一列。第 6 章
多对一（Many2one）
指向另一个模型的一条记录，例如图书的出版社。字段名按惯例以 _id 结尾。第 6 章
一对多（One2many）
多对一的「反向」：列出指向自己的所有记录，例如借书单的明细行。不占表里的列。字段名以 _ids 结尾。第 6 章
多对多（Many2many）
两边都可以有多条，例如图书和作者。由 ORM 自动建立中间表。第 6 章
计算字段（compute）
值由方法算出来的字段。用 @api.depends 声明依赖，依赖变了自动重算；加 store=True 就存进数据库，可以搜索和分组。第 6 章
关联字段（related）
直接显示关联记录上的某个字段，例如 related="partner_id.email"。是计算字段的一种简写。第 6 章
约束（constraint）
保证数据合法的规则。数据库级的用 models.Constraint，Python 级的用 @api.constrains 装饰的方法。第 6 章
记录（record）
模型的一条数据，相当于表里的一行，用整数 id 标识。第 7 章
记录集（recordset）
同一模型的零条、一条或多条记录的有序集合。模型方法里的 self 就是记录集，所以要用 for 循环逐条处理。第 7 章
环境（env）
执行 ORM 操作的「身份」：数据库游标、当前用户、当前公司、上下文。self.env 随处可用。第 7 章
上下文（context）
随请求传递的一个字典，携带语言、时区、默认值（default_字段）等信息。用 with_context() 修改。第 7 章
域（domain）
描述查询条件的表达式，如 [("state", "=", "done")]。用在搜索、动作、权限规则、视图过滤器里。Odoo 20 也可以用 Domain 对象组合条件。第 7 章
sudo()
返回一个跳过权限检查的记录集副本。在需要「代表系统」做事时使用，要谨慎，别用来掩盖权限设计的问题。第 7 章
Command
写 x2many 字段时用的指令：Command.create()、Command.link()、Command.set() 等，从 odoo.fields 导入。第 7 章
事务（transaction）
一次请求里的所有数据库修改要么全部提交，要么在出错时全部回滚。所以报错时不会留下「改了一半」的数据。第 7 章
临时模型（TransientModel）
数据会被定期自动清理的模型，用来实现向导对话框。第 8 章
抽象模型（AbstractModel）
没有数据表的模型，用来定义可复用的字段和方法（混入类），或者作为报表的数据提供者。第 6 章
显示名（display_name）
记录在下拉框、面包屑里显示的名字，默认取 name 字段（或 _rec_name 指定的字段），可以重写 _compute_display_name 自定义。第 6 章

术语表：继承与扩展

类继承（_inherit）
只写 _inherit，就地扩展已有模型。最常用的扩展方式。第 4 章
原型继承
同时写 _name（新名字）和 _inherit，以已有模型为模板创建新模型。第 4 章
委托继承（_inherits）
新模型通过一个多对一字段嵌入父模型的记录，像拥有父模型的全部字段。第 4 章
混入类（mixin）
提供通用能力的抽象模型，通过原型继承「混入」到自己的模型里，如 mail.thread（消息）、mail.activity.mixin（活动）。第 4 章
super()
重写方法时调用原来的实现。几乎所有重写都应该调用它，否则原有的逻辑就丢了。第 4 章
视图继承（inherit_id）
新建一个视图记录，用 inherit_id 指向要修改的视图，里面用 XPath 或字段定位修改内容。第 4 章
XPath
在 XML 里定位节点的表达式，如 //field[@name='isbn']。配合 position（before / after / inside / replace / attributes）使用。第 4 章

术语表：数据文件

外部标识符 / XML ID
记录的「代码名」，格式是 模块名.标识符，如 library_app.action_library_book。数据文件靠它互相引用，升级时靠它找到要更新的记录。开发者模式下可以在调试菜单的 Metadata 里查看。第 5 章
数据文件
清单 data 里列出的 XML 或 CSV 文件，安装和升级时按顺序加载，用来创建视图、菜单、权限、初始数据等记录。第 5 章
noupdate
<data noupdate="1"> 里的记录只在安装时创建，之后升级不再覆盖，用来保护用户可能修改的数据。第 5 章
演示数据（demo）
清单 demo 里的数据文件，只在建库时选择加载演示数据时才会加载。第 5 章

术语表：界面

视图（view）
描述界面长什么样的 XML，存在 ir.ui.view 里。同一个模型通常有表单、列表、搜索等多个视图。第 10 章
arch
视图的 XML 结构本身。调试菜单的 Computed Arch 显示合并所有继承之后的最终结构。第 10 章
表单 / 列表 / 搜索视图
最基本的三种：表单（form）编辑一条记录；列表（list，旧称 tree）显示多条；搜索（search）定义搜索框里的字段、过滤器和分组。第 10 章
看板视图（kanban）
卡片式的视图，卡片内容用 QWeb 模板 <t t-name="card"> 描述，常按阶段分列显示。第 11 章
动作（action）
「点了之后做什么」的记录。窗口动作打开某个模型的视图；服务器动作执行代码；报表动作生成 PDF；客户端动作打开一个前端组件。第 3 章
菜单（menu）
ir.ui.menu 的记录，组成界面上的导航。叶子菜单指向一个动作。第 3 章
部件（widget）
字段在界面上的显示方式，如 widget="many2many_tags"、widget="statusbar"。同一个字段可以用不同部件显示。第 10 章
按钮（type="object" / "action"）
表单上的按钮：object 调用模型方法，action 执行一个动作。第 10 章
动态属性（invisible / readonly / required）
在视图里写成表达式，根据记录的值动态控制字段或按钮，如 invisible="state == 'done'"。取代了旧版的 attrs。第 10 章
智能按钮（smart button）
表单右上角显示统计数字的按钮，点击跳转到相关记录。第 10 章
消息区（chatter）
表单旁边的消息、关注者和活动区域，由 mail.thread 混入类提供。第 4 章
QWeb
Odoo 的模板语言，用 t-if、t-foreach、t-field 等属性。在服务器端渲染报表和网页，在浏览器端渲染 OWL 组件。第 11 章
OWL
Odoo 自己的前端组件框架，整个后台界面都是用它写的。第 11 章
资源包（assets bundle）
清单 assets 里声明的 JS、CSS、XML 文件，被合并打包后发给浏览器，如 web.assets_backend。第 11 章
报表（report）
报表动作 + 服务器端 QWeb 模板，渲染成 HTML 再转换成 PDF。第 12 章

术语表：用户与安全

用户（res.users）
能登录的账号。分内部用户、门户用户、公共用户三类。每个用户都关联一个伙伴记录。第 14 章
伙伴（res.partner）
任何「人或组织」：客户、供应商、联系人、公司、用户本人。Odoo 里最常被关联的模型。第 14 章
公司（res.company）与多公司
一个数据库可以管理多家公司，记录上的 company_id 决定它属于哪家，访问规则据此隔离数据。第 14 章
组（res.groups）
权限的载体：用户属于若干组，访问规则、菜单、视图元素都可以限定给某些组。第 3 章
作用域（res.groups.privilege）
Odoo 19 起把同一个应用的组（如「用户」「管理员」）归到一个作用域下，用户设置页面按作用域显示一个下拉框。第 3 章
访问规则（ir.access）
Odoo 20 统一的权限记录：对某个模型、某个组，允许哪些操作（crud 的组合），以及可选的域。带组的是「许可」，多条之间是「或」；不带组的是「限制」，多条之间是「且」。第 3 章
超级用户
跳过一切权限检查的身份（sudo()，或调试菜单的 Become Superuser）。注意 admin 账号并不是超级用户。第 7 章
门户用户 / 公共用户
门户用户是能登录前台「我的账户」的外部人员（如客户）；公共用户代表未登录的网站访客。第 13 章
API 密钥（API key）
给外部程序用的凭证，代替密码。JSON-2 API 用 Authorization: bearer 请求头携带它。第 9 章

术语表：业务逻辑与集成

方法装饰器
@api.depends（计算依赖）、@api.constrains（约束）、@api.onchange（表单里的即时联动）、@api.model（不依赖具体记录）、@api.model_create_multi（批量创建）。第 8 章
onchange
用户在表单里修改字段时立即触发的逻辑，只影响界面上的未保存数据。能用计算字段解决的，优先用计算字段。第 8 章
UserError / ValidationError
给用户看的错误。抛出后当前事务回滚，界面弹出消息。第 8 章
向导（wizard）
基于临时模型的对话框，收集参数后执行一个操作，比如批量发消息。第 8 章
计划任务（ir.cron）
定时执行的服务器动作，例如每天凌晨清理数据。第 8 章
自动化规则（base.automation）
不写代码，在界面上配置「当……时，做……」的规则。第 8 章
测试（TransactionCase）
自动化测试的基类，每个测试在独立的保存点里运行，结束后回滚。用 --test-tags 运行。第 8 章
JSON-2 API
Odoo 19 起推荐的外部接口：POST /json/2/模型/方法，用 API 密钥认证。取代旧的 XML-RPC / JSON-RPC。第 9 章
控制器（controller）与路由
处理网址请求的 Python 类，方法用 @http.route 装饰，可以返回网页或 JSON。第 13 章
门户（portal）
给外部用户（客户、供应商）用的前台「我的账户」页面，可以查看属于自己的单据。第 13 章
翻译（i18n）
界面文字的多语言支持：代码里用 self.env._() 标记，模块的 i18n/ 目录放 .pot 模板和各语言的 .po 文件。第 18 章

术语表：部署与维护

反向代理（reverse proxy）
位于 Odoo 前面的 Nginx 等服务器，负责 HTTPS、压缩、转发。Odoo 要开启 proxy_mode 才能正确识别客户端信息。第 15 章
WebSocket / gevent
实时通知（新消息、在线状态）走 WebSocket 连接，多进程模式下由监听 gevent_port（8072）的 gevent 进程处理。第 15 章
预发布环境（staging）
生产数据库的一份副本，用来在上线前测试更新。第 15 章
中和（neutralize）
复制出来的数据库里关掉发邮件、计划任务等对外操作，避免预发布环境误发邮件给真实客户。第 15 章
迁移脚本（migrations/）
模块版本号升高时自动执行的 Python 脚本，用来转换旧数据。第 19 章
upgrade_code
Odoo 自带的命令，把旧版本写法的模块代码自动改写成新版本写法。附录 A
镜像 / 容器（Docker）
镜像是打包好的运行环境（如 odoo:20），容器是它运行起来的实例。第 17 章

小结

  • 模块是交付单位，模型是数据结构；一个模块可以定义、也可以扩展多个模型。
  • 菜单 → 动作 → 视图 + 模型 → ORM → 数据库，是后台界面工作的主线。
  • 菜单、动作、视图、权限、数据都是数据库里的记录，由模块的数据文件创建，靠 XML ID 互相引用。
  • 「继承」有四种：类继承、原型继承、委托继承作用于模型，视图继承作用于界面。
