常见报错与排错手册

学 Odoo 时最让人沮丧的，往往不是概念难懂，而是一个看不懂的报错卡住一下午。 好消息是：初学者遇到的报错高度集中，翻来覆去就那二三十种。这个附录先教你怎么读报错，再按「症状 → 原因 → 解决」把最常见的情况整理成一本手册。 遇到问题时，先用浏览器的查找功能（Ctrl+F）搜报错里的关键词。

本附录内容

  • 报错会出现在哪里，怎样从一大段 Traceback 里找到关键信息
  • 「我改了什么 → 要重启、升级还是刷新」决策图
  • 模块安装、XML 数据、视图、权限、ORM、前端、运行环境七类常见报错
  • 从旧教程抄来的代码在 Odoo 20 上会怎样报错
  • 排错工具箱，以及怎样提一个能得到回答的问题

报错出现在哪里

Odoo 是一个「浏览器 + 服务器 + 数据库」的三层系统，同一个问题可能在不同的地方露头。新手最常犯的错误是只盯着浏览器里的弹窗， 而真正有用的信息在服务器终端里。先认识这四个地方：

💡 先把日志开到合适的详细程度

默认的 info 级别通常够用。想看更多细节时：--log-level=debug 打开全部调试日志； --log-sql 打印每条 SQL；--dev=access 让访问错误也打印完整的调用栈（第 2 章）。 排错完记得关掉，调试日志很多，会把真正的错误淹没。

读懂 Traceback

Python 的报错叫 Traceback（回溯）。它从最外层的调用一路列到出错的那一行，在 Odoo 里经常有几十行长， 其中绝大部分是框架内部的调用。读它有固定的顺序：先看最后一行，再往上找自己的文件。

最后一行的异常类型本身就是一条重要线索：

异常类型通常意味着
UserError / ValidationError代码主动拒绝了这个操作（业务规则、约束）。读消息内容即可，往往不是 bug。
AccessError权限不够：缺少 ir.access 规则，或者记录不满足规则的域。
MissingError要访问的记录已经被删除了（常见于浏览器还开着旧页面）。
ParseError安装或升级时，某个 XML / CSV 数据文件有问题。消息里有文件名和行号。
ValueError / KeyError / AttributeError通常是代码 bug：字段名写错、记录集里有多条记录、调用了不存在的方法。
psycopg2.errors.*数据库层面的错误：列不存在（没升级模块）、违反唯一约束、并发冲突。

改了什么，需要做什么

「代码改了但没生效」是初学者问得最多的问题，原因几乎总是同一个：没有做对应的那一步。 Odoo 的代码分三种，生效方式各不相同：Python 代码在服务器启动时加载；XML / CSV 数据在安装或升级模块时写进数据库； 静态文件（JS、CSS、OWL 模板）由浏览器下载。第 3 章介绍过基本规则，这里给出完整版：

拿不准时的万能做法

停掉服务器，用 odoo -c 配置文件 -d 库名 -u 你的模块 重新启动，然后在浏览器里按 Ctrl+Shift+R。 这一套下来，上表里除了「全新模块」以外的所有情况都能覆盖。慢一点，但不会错。

模块安装类问题

在「应用」里搜不到我的模块

这是第一天最常见的问题。按下面的顺序排查，十有八九在前三步就能找到原因：

第 ① 步要看的是服务器启动后最开始的几行日志：

INFO ? odoo: Odoo version 20.0
INFO ? odoo: Using configuration file at /home/you/work20/library.conf
INFO ? odoo: addons paths: _NamespacePath(['/home/you/work20/odoo/odoo/addons', '/home/you/work20/library', ...])

第 ④ 步里最容易踩的是从旧教程抄来的版本号：

WARNING ? odoo.modules.module: The module library_app has an incompatible version, setting installable=False
原因
清单里写的是 "version": "15.0.1.0.0"。Odoo 只接受 x.y、x.y.z、20.0.x.y 或 20.0.x.y.z 这几种格式，以别的大版本号开头的模块会被直接标记为不可安装。
解决
改成 "20.0.1.0.0"（推荐，见第 19 章），或者干脆写 "1.0.0"，Odoo 会自动补上 20.0. 前缀。

依赖的模块找不到

ERROR ? odoo.modules.loading: Some modules are not loaded, some dependencies or manifest may be missing: ['library_member']
原因
清单的 depends 里列了一个 Odoo 找不到的模块：名字拼错了，或者那个模块（比如从 OCA 下载的）所在的目录没有加进 addons_path。
解决
核对 depends 里的每个名字；第三方模块要把它的仓库目录加进 addons_path 并重启。在界面上升级时，同样的问题会显示为「…depends on the module: xxx. But this module is not available in your system.」

缺少 Python 库

Unable to install module "library_app" because an external dependency is not met: ...
ModuleNotFoundError: No module named 'isbnlib'
原因
代码 import 了一个没装的第三方库。第一种消息来自清单里的 external_dependencies 检查，第二种是 Python 在导入时直接报错。
解决
在运行 Odoo 的那个虚拟环境里 pip install 它（先确认提示符前有 (env20)）。用 Docker 的话要装进镜像里（第 17 章）。别忘了在清单的 external_dependencies 里声明，让别人安装时得到清楚的提示。

XML / CSV 数据文件

安装或升级时，Odoo 按清单 data 列表的顺序逐个加载数据文件。任何一个出错，整个安装就会回滚，并打印 ParseError：

odoo.tools.convert.ParseError: while parsing /home/you/work20/library/library_app/views/library_menu.xml:12, somewhere inside
&lt;menuitem id="menu_library_book" name="Books" parent="menu_library" action="action_library_book"/&gt;

先看「while parsing」后面的文件和行号，再往上翻真正的原因。最常见的三种：

原因信息说明与解决
External ID not found in the system: library_app.action_library_book 引用了一个还不存在的 XML ID。要么拼错了；要么定义它的地方排在引用它的地方后面——数据是从上到下依次加载的，同一个文件里菜单要写在动作后面，不同文件则要调整清单里 data 的顺序；要么引用别的模块的记录时忘了写模块名前缀，或者那个模块不在 depends 里。
Opening and ending tag mismatch、XMLSyntaxError XML 本身写坏了：标签没闭合、属性值里直接写了 < 或 &（要写成 &lt;、&amp;）。编辑器的 XML 插件能当场标红。
The XML file '…' does not fit the required schema! 结构不符合 Odoo 数据文件的规范（RNG 校验）：标签名写错、标签放错了位置。它下面的 WARNING 行会给出具体位置；按提示 pip install jingtrang 后消息会更精确。
CSV 文件的列名就是字段名

ir.access.csv 的表头必须是 id,name,model_id,group_id/id,operation,domain，而且文件名决定了导入到哪个模型： 文件叫 ir.access.csv，就导入 ir.access。从旧教程抄来的 ir.model.access.csv 在 Odoo 20 里已经没有对应的模型了（第 3 章）， 可以用 odoo upgrade_code 自动转换（附录 A）。

视图问题

字段在模型里不存在

Field "isbn" does not exist in model "library.book"
原因
视图里用了一个模型上没有的字段。最常见的是刚在 Python 里加了字段，却只升级、没重启（Python 没重新加载，Odoo 根本不知道这个新字段），或者字段名有拼写错误。还有一种：字段定义在另一个模块里，而那个模块不在 depends 中。
解决
确认拼写，停掉服务器再带 -u 启动（同时完成「重启 + 升级」）。

继承视图时 XPath 定位失败

Element '&lt;xpath expr="//field[@name='isbn']"&gt;' cannot be located in parent view
原因
继承视图（第 4 章）里的 expr 或 <field name="..." position="..."> 在父视图里找不到对应的节点。常见情况：字段名、name 属性写错；inherit_id 指向了另一个视图；父视图在新版本里改了结构（比如 tree 改叫 list、某个 group 换了名字）。
解决
打开开发者模式，在要修改的界面点调试菜单（小虫子）→ Computed Arch，看到的是所有继承合并之后的最终结构，直接在里面找你要定位的节点；或者点 View: 表单名 打开父视图本身，核对节点和属性。

网上大量教程基于 Odoo 16 以前的版本。把这些视图代码装进 Odoo 20，会碰到下面这些报错：

改了视图，界面上没变化

原因
① 没升级模块（视图存在数据库里，改文件不会自动生效）；② 这个界面实际用的是另一个视图（比如动作通过 view_id 指定了别的视图，或者有优先级更高的视图）；③ 另一个模块的继承视图把你的改动又盖掉了。
解决
先升级 + 强制刷新。还不行，就用调试菜单的 Computed Arch 看最终结构里有没有你的修改，再用 View: … 确认当前用的是哪一个视图。

权限问题

访问报错有两种，长得完全不一样，原因也不同。先弄清 Odoo 的检查分两层（第 3 章）：

第一种：模型级（You are not allowed to …）

You are not allowed to access 'Book' (library.book) records.

No group currently allows this operation.

Contact your administrator to request access if necessary.
原因
第二段告诉你答案：「No group currently allows this operation」表示根本没有任何规则允许这个操作——新建的模型忘了写 ir.access.csv，或者写了却没加进清单的 data。 如果第二段列出了一些组（This operation is allowed for the following groups），说明规则是有的，只是当前用户不在这些组里。
解决
补上规则并升级模块；或者到「设置 → 用户」把用户加进相应的组。
ⓘ 管理员也会遇到权限错误

很多人以为管理员账号（admin）可以无视权限。其实不是：admin 只是属于很多组的普通用户，新模型如果没有给它所在的组写规则，admin 一样会报错。 真正跳过所有权限检查的只有超级用户模式（开发者模式下调试菜单里的 Become Superuser，以及代码里的 sudo()）。 排错时可以用它确认「是不是权限问题」，但别用它掩盖问题。

第二种：记录级（top-secret records）

Uh-oh! Looks like you have stumbled upon some top-secret records.

Sorry, Ana (id=6) doesn't have 'write' access to:
- Book, Odoo Development Essentials (library.book: 3)

Blame the following accesses:
- Book: user
原因
用户对这个模型有许可，但这几条具体的记录不满足许可的 domain，或者被某条「限制」（没有组的 ir.access，最典型的是多公司隔离）挡住了。
解决
开着开发者模式时，消息里会列出具体是哪些记录、哪几条规则（Blame the following accesses）——普通模式下只显示模型名。 对照这些规则的域看看记录为什么不满足；如果消息里提到 multi-company，切换右上角的当前公司往往就能解决。

菜单不见了

原因
菜单本身设置了 groups 而用户不在组里；或者菜单指向的动作所属的模型，用户连「读」的权限都没有——Odoo 会自动隐藏这样的菜单，不报任何错。
解决
先给用户补上读权限，再检查菜单和它的上级菜单的 groups。

ORM 与 Python 代码

Expected singleton

ValueError: Expected singleton: library.book(1, 2)
原因
对一个包含多条记录的记录集读取了字段值（比如 self.name），而 Odoo 不知道你要哪一条。按钮方法、计算方法的 self 都可能包含多条记录（第 7 章）。
解决
用 for record in self: 逐条处理；如果确实只应该有一条，在方法开头写 self.ensure_one()，让错误更早、更明确地暴露出来。

数据库里没有这一列

psycopg2.errors.UndefinedColumn: column library_book.isbn does not exist
原因
Python 里新增了存储字段，服务器也重启了，但没有升级模块，所以数据库表里还没有这一列。
解决
-u 模块名 升级。

写入时字段名不对

ValueError: Invalid field 'author' on model 'library.book'
原因
传给 create() / write() 的字典里有模型上不存在的字段。本例中正确的字段是 author_ids：多对多字段按惯例以 _ids 结尾，多对一字段以 _id 结尾（第 19 章）。
解决
在开发者模式下打开「设置 → 技术 → 模型」，或者在 odoo shell 里执行 env['library.book']._fields.keys()，查看真实的字段名。

计算字段的值不更新

原因
@api.depends 漏了某个依赖字段，Odoo 不知道该在什么时候重新计算。对存储的计算字段（store=True）尤其要紧：漏了依赖，数据库里的值就一直是旧的。
解决
把计算里读到的所有字段都写进 @api.depends，关联字段写成点号路径，比如 @api.depends("line_ids.quantity")。修好后升级模块，已存储的旧值才会重新计算。

重写方法后功能「消失」了，或者无限递归

原因
重写 create、write 或按钮方法时忘了调用 super()，原来的逻辑就不会执行；反过来，在 write() 里又调用 self.write()，会无限递归，最终报 RecursionError。
解决
重写时总是调用 super() 并返回它的结果；在 write() 里要写别的字段，就把值合并进传给 super().write() 的字典里。

前端问题

页面白屏，或者按钮没反应

原因
前端 JavaScript 出错时，服务器日志里往往什么都没有。常见原因：OWL 模板里引用了不存在的变量、导入路径写错（@web/...）、模板名和组件里 static template 写的不一致。
解决
按 F12 打开浏览器的控制台看红色报错；在网址里加 ?debug=assets，前端资源会以未压缩的形式加载，报错的文件名和行号才看得懂。 如果报的是 Missing template 或某个文件 404，检查清单的 assets 有没有包含这个文件，改了清单要重启服务器。

改了 JS / CSS，浏览器里还是旧的

原因
浏览器缓存了旧的资源包。
解决
Ctrl+Shift+R 强制刷新；还不行就在调试菜单点 Regenerate Assets，让服务器重新打包。

升级之后的意外

升级了模块，数据文件里的修改却没有生效

原因
那条记录放在 <data noupdate="1"> 里（第 5 章）。这种记录只在第一次安装时创建，以后升级都不会再覆盖，目的是保护用户在界面上做过的修改。
解决
开发阶段可以卸载再重装模块；已经上线的系统，在界面上手工修改，或者写一个迁移脚本（第 19 章）。

我在界面上改过的视图 / 菜单，升级后被还原了

原因
和上一条正好相反：不带 noupdate 的记录，每次升级都会按模块文件里的内容重新写一遍，界面上的修改会被覆盖。
解决
不要直接改模块自带的记录。想调整界面，就写一个继承视图放进你自己的模块里（第 4 章）——这也是 Odoo 推荐的做法。

排错工具箱

🐛

开发者模式

网址加 ?debug=1。调试菜单里的 Computed Arch、View、Metadata（查看记录的 XML ID）、Become Superuser 都是排错利器。

💻

odoo shell

直接在命令行里调用 ORM，验证字段名、试运行一段逻辑，不用反复点界面（第 7 章）。

⏸

断点调试

代码里写 breakpoint()，或者用 VS Code 打图形化断点，一步步看变量怎么变（第 8、17 章）。

📜

日志开关

--log-level=debug、--log-sql、--log-handler=模块:DEBUG，只放大你关心的那一块。

🧪

测试

把复现问题的步骤写成一个测试（第 8 章），修好以后它还能防止问题再次出现。

🔍

读源码

Odoo 的源码就在 ~/work20/odoo。用编辑器全局搜索报错消息，就能找到抛出它的那一行和触发条件。

最有效的一招：拿报错文字去搜源码

报错消息几乎都是源码里的一行字符串。复制消息中固定不变的部分（去掉记录名、ID 这些变量），在 Odoo 源码里全局搜索， 就能找到抛出它的 raise 语句。看懂它上面的 if 条件，通常就知道问题出在哪了。

怎样提问才能得到回答

自己实在解决不了，就去 Odoo 官方论坛、OCA 的 GitHub 或中文社区求助。一个好问题应该包含：

  1. 版本：Odoo 20 社区版还是企业版，Python 版本，怎么安装的（源码 / Docker / 安装包）。
  2. 你想做什么：一两句话说明目标，而不只是「这段代码报错」。
  3. 最小的可复现代码：删掉和问题无关的部分，只留下能触发报错的最少代码。很多时候在精简的过程中，你自己就发现问题了。
  4. 完整的 Traceback：从服务器日志里复制文字，不要截图，也不要只贴最后一行。
  5. 你已经试过什么：重启过吗？升级过吗？这能帮回答的人少走弯路。

小结

  • 浏览器弹窗只是表象，完整的信息在服务器日志里；前端问题看浏览器的控制台。
  • 读 Traceback：先看最后一行的异常类型和消息，再往上找自己模块的文件和行号。
  • Python 改动要重启，数据和视图要升级，静态文件要强制刷新；拿不准就 -u 重启再 Ctrl+Shift+R。
  • 模块找不到：查 addons paths、路径层级、更新应用列表和「应用」筛选，以及清单版本号。
  • ParseError 看文件和行号；External ID not found 多半是文件顺序或模块前缀的问题。
  • 两种 AccessError：「not allowed to access」是没有规则，「top-secret records」是记录不满足规则的域。
  • 旧教程的 attrs、tree、kanban-box、@api.multi、odoo.osv 在 Odoo 20 上都会报错，先用 upgrade_code 自动迁移。

动手练习：故意制造错误

认识报错最好的办法，是亲手把它制造出来。在图书馆模块的一个副本上逐个尝试，观察报错出现在哪里、长什么样：

  1. 把清单的版本号改成 15.0.1.0.0，重启后在「应用」里搜索这个模块。
  2. 在 library_menu.xml 里把图书子菜单 menu_library_book 挪到动作 action_library_book 前面，然后升级模块。
  3. 在表单视图里加一个不存在的字段 <field name="foo"/>，升级模块。
  4. 注释掉 ir.access.csv 里图书的那一行，升级后用普通用户打开图书菜单。
  5. 在一个按钮方法里去掉 for 循环直接读 self.name，然后在列表里选中两条记录执行它。
  6. 在 Python 里加一个新的存储字段，只重启、不升级，打开列表视图看看会发生什么。
