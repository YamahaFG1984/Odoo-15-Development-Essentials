第 6 章

模型：组织应用数据

模型是 Odoo 框架的心脏：它描述应用的数据结构，是应用服务器和数据库之间的桥梁。业务逻辑围绕模型实现，用户界面建立在模型之上。 这一章把模型层讲透：有哪些模型类型、有哪些字段类型、字段之间怎么建立关系、怎么让字段自动计算、怎么保证数据正确。

本章目标

  • 掌握常用模型属性，分清普通模型、临时模型和抽象模型
  • 认识全部基本字段类型和通用字段属性，学会设置默认值
  • 建立多对一、一对多、多对多、层级和引用关系
  • 写计算字段（含可搜索、可写入的）和关联字段
  • 用 SQL 约束和 Python 约束保证数据质量

学习项目：丰富图书馆应用

我们回到 library_app，让每本书能存更丰富的信息，并增加一个图书分类的层级结构：

  • 名称：分类标题
  • 上级分类：它属于哪个分类
  • 子分类：以它为上级的分类
  • 精选：一本代表这个分类的书，或者一位代表作者

同时给书加两条校验规则：书名 + 出版日期不能重复；ISBN 必须合法。

创建模型

模型属性

模型类可以用一些以下划线开头的类属性控制它的行为。最常用的三个：

_name
模型的内部标识。创建新模型时必须写。
_description
给人看的模型名称，比如 Book。可选但推荐，不写会在日志里告警。
_order
默认排序，相当于 SQL 的 ORDER BY 子句。它很聪明：支持可翻译字段，也支持多对一字段（按关联记录的排序）。
class LibraryBook(models.Model):
    _name = "library.book"
    _description = "Book"
    _order = "name, date_published desc"   # 先按书名，再按出版日期从新到旧

还有一些在特殊情况下有用的属性（下面写的都是它们的默认值）：

    _rec_name = "name"          # 用哪个字段作为记录的显示名称
    _table = "library_book"     # 数据库表名，默认为模型名把点换成下划线
    _log_access = True          # False 时不创建 create_uid / write_date 等审计字段
    _auto = True                # False 时 ORM 不自动建表，需自己在 init() 里创建

_auto = False 的典型用途是报表模型：模型背后不是一张表，而是一个数据库视图（VIEW），汇总了报表需要的数据。 比如销售模块的 sale.report，就在 init() 方法里用 CREATE OR REPLACE VIEW 创建自己的视图。

模型和 Python 类

所有模型都保存在一个中央注册表里，通过环境对象访问，通常写作 self.env。注册表像字典一样，用模型名取模型： self.env["library.book"]。所以模型名非常重要，并且必须全局唯一。

💡 模型命名规范
  • 用单数：library.book，不是 library.books。
  • 小写单词用点连接，第一个词是所属应用：library.book、library.book.category；官方的例子有 project.project、project.task、project.task.type。
  • Python 类名按 PEP 8 用驼峰式，它只在所在文件里有意义。

三种模型类型

  • 临时模型（models.TransientModel）用于向导式的交互。数据也存在数据库里，但只是临时的，有一个定时任务会清掉旧数据（默认保留 1 小时）。比如「设置 → 翻译 → 导入翻译」打开的对话框就是一个临时模型。
  • 抽象模型（models.AbstractModel）没有数据存储，用作可复用的功能集合，通过继承混入其他模型。

在界面上查看模型

开发者模式下，设置 → 技术 → 数据库结构 → 模型列出所有模型。打开 library.book，可以看到它是所有模块修改叠加后的最终结果： 右上角「In Apps」列出了影响它的模块（比如 library_app 和 library_member）； 下方的标签页有字段（Fields）、访问规则（Access Rights）、说明（Notes，即模型类的 docstring）和视图（Views）。

模型的 XML ID 由 ORM 自动生成：model_ 加上模型名（点换成下划线），所以 library.book 的完整 XML ID 是 library_app.model_library_book。

字段

基本字段类型

我们把书模型的字段换成下面这样，借此展示各种字段类型：

class LibraryBook(models.Model):
    _name = "library.book"
    _description = "Book"
    _order = "name, date_published desc"

    # 文本类
    name = fields.Char("Title", required=True)
    isbn = fields.Char("ISBN")
    book_type = fields.Selection(
        [("paper", "Paperback"),
         ("hard", "Hardcover"),
         ("electronic", "Electronic"),
         ("other", "Other")],
        "Type",
    )
    notes = fields.Text("Internal Notes")
    descr = fields.Html("Description")

    # 数值类
    copies = fields.Integer(default=1)
    avg_rating = fields.Float("Average Rating", digits=(3, 2))
    price = fields.Monetary("Price", currency_field="currency_id")
    currency_id = fields.Many2one("res.currency")  # 金额字段需要一个币种字段

    # 日期时间类
    date_published = fields.Date()
    last_borrow_date = fields.Datetime(
        "Last Borrowed On",
        default=lambda self: fields.Datetime.now(),
    )

    # 其他
    active = fields.Boolean("Active?", default=True)
    image = fields.Image("Cover", max_width=1024, max_height=1024)

    # 关系类
    publisher_id = fields.Many2one("res.partner", string="Publisher")
    author_ids = fields.Many2many("res.partner", string="Authors")

大多数字段的第一个位置参数是标签（对应关键字参数 string）。例外是 Selection 和所有关系字段，它们的第一个位置参数是选项列表或关联模型。 不写标签时，Odoo 会根据字段名自动生成：下划线换空格、每个单词首字母大写，date_published 变成「Date Published」。

⇪ 和书上代码的区别
  • 封面字段改用了 fields.Image（Odoo 13 引入），它会自动把大图缩小，比 Binary 更适合图片。
  • 书里 Float("Average Rating", (3, 2)) 用位置参数传精度；这里用关键字 digits= 更清楚。
  • 书中的 active 字段漏写了 default=True，那样新建的书都是「已归档」状态，这里补上了。

文本类字段还有几个专用属性：

  • translate=True：内容可翻译，每种语言存一个值（Odoo 16 起以 JSONB 形式存在同一列里）。翻译的完整机制见第 18 章。
  • trim：默认为 True，Web 客户端会自动去掉首尾空白；设为 False 保留。

通用字段属性

下面这些关键字参数适用于所有字段类型：

  • group_operator：Odoo 17.2 改名为 aggregator。

书中「列出全部属性」的示例因此要删掉 states 和 deprecated 两项，否则会报错。

默认值

默认值可以是固定值，也可以是一个函数，在新建记录时被调用：

# 1. lambda：适合简单计算
last_borrow_date = fields.Datetime(
    "Last Borrowed On",
    default=lambda self: fields.Datetime.now(),
)

# 2. 函数引用：函数必须定义在字段之前
def _default_last_borrow_date(self):
    return fields.Datetime.now()

last_borrow_date = fields.Datetime(
    "Last Borrowed On",
    default=_default_last_borrow_date,
)

# 3. 函数名字符串：运行时才查找，所以函数可以定义在后面
last_borrow_date = fields.Datetime(
    "Last Borrowed On",
    default="_default_last_borrow_date",
)

惯例是把默认值函数写在字段定义之前，并使用第 2 种（函数引用）写法 —— 代码编辑器能检查出拼写错误。

⚠ 别写 default=fields.Datetime.now()

注意 lambda 写法里 now() 是在 lambda 内部调用的。如果写成 default=fields.Datetime.now()， 它会在 Python 加载这个文件时就被执行一次，所有新记录都会得到同一个（服务器启动时的）时间。 想直接传函数的话，写 default=fields.Datetime.now（不带括号）。

自动字段和保留字段名

每个模型都自动有一个 id 字段作为主键。除非设置了 _log_access = False，还会自动加上四个审计字段：

  • create_uid / create_date：创建人 / 创建时间
  • write_uid / write_date：最后修改人 / 最后修改时间

在表单上通过调试菜单 → Metadata 可以看到它们的值。

还有一些字段名会被 Odoo 的内置功能「默认使用」，最好只用于约定的用途：

字段名类型约定用途
name / x_nameChar记录的显示名称。可用 _rec_name 改用别的字段
active / x_activeBoolean为 False 的记录被「归档」，默认从查询中排除。上下文加 {'active_test': False} 可以查到它们
stateSelection记录的生命周期状态，比如草稿、已确认、已完成
parent_idMany2one树状层级结构，启用域运算符 child_of 和 parent_of。可用 _parent_name 改用别的字段
parent_pathChar配合 _parent_store = True，加速层级查询
company_idMany2one记录所属公司。为空表示各公司共享。用于多公司一致性检查
sequenceInteger手动排序。常配合 _order = "sequence"，并在列表视图里加 <field name="sequence" widget="handle"/> 实现拖动排序

显示名称：display_name

每条记录都有一个计算字段 display_name，它决定了这条记录在下拉框、关系字段、面包屑里显示成什么。默认取 _rec_name（即 name）的值。 如果想自定义，比如让书显示为「书名 (出版年份)」，就重写 _compute_display_name： 

    @api.depends("name", "date_published")
    def _compute_display_name(self):
        for book in self:
            year = book.date_published.year if book.date_published else ""
            book.display_name = f"{book.name} ({year})" if year else book.name
⇪ name_get() 已被废弃

Odoo 16 以前自定义显示名称要重写 name_get() 方法，你在老代码里会经常看到它。Odoo 17 起废弃，统一改为计算 display_name 字段。 相应地，「按显示名称搜索」也从重写 _name_search() 改为设置 _rec_names_search = ["name", "isbn"]（列出参与搜索的字段）。

模型之间的关系

以图书馆为例，书模型有这些关系：

多对一（Many2one）

多对一是对另一个模型中一条记录的引用。书的出版社 publisher_id 就是：每本书有一个出版社，一个出版社可以出很多书。 在数据库里它是一个整数列，存着关联记录的 ID，并带有外键约束保证引用完整性。 

publisher_id = fields.Many2one("res.partner", string="Publisher")

第一个位置参数是关联模型（comodel_name）。其余常用的关键字参数：

  • ondelete：关联记录被删除时怎么办。"set null"（默认，置空）、"restrict"（阻止删除并报错）、"cascade"（连带删除本记录）。
  • domain：一个域表达式，限制界面上可选的记录。
  • context：通过这个字段跳转或新建关联记录时，带给 Web 客户端的上下文，比如默认值。
  • check_company=True：多公司场景下，校验关联记录与本记录属于同一公司。
  • delegate=True：委托继承（第 4 章），此时还必须 required=True 和 ondelete="cascade"。
  • bypass_search_access=True：通过这个字段搜索时绕过关联模型的访问规则，查询更快但有安全风险，慎用。
⇪ auto_join 改名了

书中的 auto_join=True 在 Odoo 19 改名为 bypass_search_access=True，新名字把「它会绕过权限」这件事说得更直白。

一对多（One2many）：反向关系

一对多是多对一的反面：列出所有指向本记录的记录。书通过 publisher_id 指向出版社，那么出版社就可以有一个一对多字段，列出它出版的所有书。 因为要给 res.partner 加字段，所以用经典继承扩展它： 

from odoo import fields, models


class ResPartner(models.Model):
    _inherit = "res.partner"

    published_book_ids = fields.One2many(
        "library.book",       # 关联模型
        "publisher_id",       # 关联模型里指向我的那个 Many2one 字段
        string="Published Books",
    )

别忘了在 models/__init__.py 里加上 from . import res_partner。

多对多（Many2many）

书和作者之间是多对多：一本书多位作者，一位作者多本书。两边都可以定义 Many2many 字段：

# 书这边（library_app/models/library_book.py）
author_ids = fields.Many2many("res.partner", string="Authors")

# 作者这边（library_app/models/res_partner.py）
book_ids = fields.Many2many("library.book", string="Authored Books")

多对多不会给任何一张表加列，而是由 ORM 自动建一张关系表，只有两列，分别是指向两边的外键。 默认表名是两个表名用下划线连接再加 _rel：library_book_res_partner_rel。两边的字段如果默认表名相同，就自动共用同一张关系表。

有时需要手动指定关系表：

  • 两个模型名都很长，自动生成的表名超过 PostgreSQL 的 63 字符限制；
  • 同一对模型之间需要第二个多对多关系（比如书和联系人之间除了「作者」还有「译者」），必须换一张表，否则会和第一个关系混在一起。
author_ids = fields.Many2many(
    comodel_name="res.partner",
    relation="library_book_res_partner_rel",  # 关系表名
    column1="a_id",                           # 指向本模型（书）的列
    column2="b_id",                           # 指向关联模型（联系人）的列
    string="Authors",
)
💡 抽象模型上别指定 column1 / column2

ORM 在抽象模型上有个设计限制：如果强制指定了关系列名，这个字段就无法被干净地继承。在抽象模型里定义 Many2many 时，让 ORM 自动生成列名。

层级关系

父子树状结构用一个指向同一模型的多对一字段表示：每条记录存着它的父记录。反向的一对多字段就是它的直接子记录。 只要模型有 parent_id 字段，域表达式里就可以用 child_of（某节点的所有后代）和 parent_of（某节点的所有祖先）运算符。 

from odoo import fields, models


class LibraryBookCategory(models.Model):
    _name = "library.book.category"
    _description = "Book Category"
    _parent_store = True

    name = fields.Char(translate=True, required=True)

    # 层级字段
    parent_id = fields.Many2one(
        "library.book.category",
        "Parent Category",
        ondelete="restrict",
    )
    parent_path = fields.Char(index=True)

    # 可选，但很方便：
    child_ids = fields.One2many(
        "library.book.category",
        "parent_id",
        "Subcategories",
    )

_parent_store = True 开启层级查询优化，此时必须同时有一个带索引的 parent_path 字段。 它存着从根节点到本节点的 ID 路径，这样查询「某分类下的所有后代」只需要一个前缀匹配，而不用一层层递归：

这个优化有存储和写入的代价（移动一个节点要更新它所有后代的路径），适合「读多写少、层级较深」的数据，比如分类树。层级很浅、节点很少时不必开启。

引用字段（Reference）：灵活的关系

普通关系字段只能指向一个固定的模型。引用字段可以指向多个模型中的任意一个。给分类加一个「精选」字段，它可以是一本书，也可以是一位作者： 

    highlighted_id = fields.Reference(
        [("library.book", "Book"), ("res.partner", "Author")],
        "Category Highlight",
    )

写法很像 Selection，只是选项列表里列的是模型。界面上用户先选模型，再选具体记录。 它在数据库里存成一个字符串 "模型名,ID"，比如 "library.book,3"。

计算字段

字段的值也可以由一个函数自动计算，而不是读数据库里存的值。计算字段的声明和普通字段一样，只是多了 compute 参数，指定计算方法。 例子：在书上显示出版社所在的国家。 

from odoo import api, fields, models


class LibraryBook(models.Model):
    # ...

    publisher_country_id = fields.Many2one(
        "res.country",
        string="Publisher Country",
        compute="_compute_publisher_country",
    )

    @api.depends("publisher_id.country_id")
    def _compute_publisher_country(self):
        for book in self:
            book.publisher_country_id = book.publisher_id.country_id
  • compute 给出计算方法的名字。惯例是 _compute_ + 字段名。
  • 计算方法接收一个记录集 self，要给其中每一条记录的计算字段赋值，所以总是用 for 循环。
  • 每条执行路径都必须赋值。如果方法里有 if 分支，确保每个分支都给字段赋了值，否则会报错。
  • 一个计算方法可以同时计算多个字段：几个字段的 compute 指向同一个方法，方法里给它们全部赋值。

@api.depends：告诉 ORM 什么时候重算

@api.depends 声明计算依赖哪些字段，可以用点号沿关系往下走。ORM 据此知道：当 publisher_id 变了，或者出版社的 country_id 变了， 就要重新计算 publisher_country_id。

⚠ 依赖要写全

忘了写 @api.depends，或者漏写了计算中用到的某个字段，计算字段就不会在该更新的时候更新。 检查方法：计算方法里读了哪些字段（包括点号后面的），@api.depends 里就应该有哪些。

存储、搜索与写入

默认情况下，计算字段不存进数据库，每次读取时现算。所以它不能被搜索、不能用于排序和分组，也不能被写入。有三种办法扩展它的能力：

1. 存储：加上 store=True，值就会被存进数据库，依赖变化时自动重算。存了就能像普通字段一样搜索、排序、分组。

2. 不存储也能搜索和写入：实现搜索函数和反向函数：

    publisher_country_id = fields.Many2one(
        "res.country",
        string="Publisher Country",
        compute="_compute_publisher_country",
        inverse="_inverse_publisher_country",
        search="_search_publisher_country",
    )

    def _inverse_publisher_country(self):
        # 在书上改「出版社国家」= 去改出版社的国家
        for book in self:
            book.publisher_id.country_id = book.publisher_country_id

    def _search_publisher_country(self, operator, value):
        # 搜索「出版社国家 = X」= 搜索「出版社.国家 = X」
        return [("publisher_id.country_id", operator, value)]
  • 反向函数（inverse）在用户写入计算字段时被调用，实现「计算的逆运算」。 注意：这会改掉出版社本身的国家，所有这个出版社的书都会受影响；而且受常规权限约束，当前用户必须有权修改联系人才能成功。
  • 搜索函数（search）在域表达式里出现这个字段时被调用，收到运算符和值，返回一个只用存储字段写成的替代域。

可编辑的计算字段

计算字段还可以设置 readonly=False 并同时 store=True：依赖变化时自动算一个值，但用户也可以手动覆盖它。 这在实现「选了 A 自动带出 B，但 B 允许修改」时非常有用，是 onchange 的现代替代品，第 8 章详细讲。

关联字段（related）

上面的计算字段只是从关联记录上「搬」一个值过来，这种需求非常普遍。Odoo 为此提供了一个简写 —— 关联字段： 

    publisher_country_id = fields.Many2one(
        "res.country",
        string="Publisher Country",
        related="publisher_id.country_id",
    )

关联字段本质上就是计算字段，而且自动实现了搜索和反向函数，所以可以被搜索。它默认是只读的，要允许通过它写入，设置 readonly=False； 也可以加 store=True 存储。在视图里没法用点号访问关联记录的字段时（比如想在书的表单上显示出版社的国家），关联字段就是标准做法。

模型约束

应用经常需要保证数据完整、正确。PostgreSQL 本身就支持很多校验（比如防重复、检查简单条件），Odoo 模型可以直接利用； 更复杂的检查则用 Python 代码实现。

SQL 约束

SQL 约束被加到数据库表的定义里，由 PostgreSQL 直接强制执行。最常用的是 UNIQUE（防重复）和 CHECK（检查一个 SQL 表达式）。 我们给书加两条：书名 + 出版日期不能重复；出版日期不能是未来。 

class LibraryBook(models.Model):
    _name = "library.book"
    # ...

    _name_date_uniq = models.Constraint(
        "UNIQUE (name, date_published)",
        "Book title and publication date must be unique.",
    )
    _date_check = models.Constraint(
        "CHECK (date_published <= current_date)",
        "Publication date must not be in the future.",
    )

每个约束是一个类属性，属性名（以下划线开头）就是约束的名字，models.Constraint 的第一个参数是 SQL 定义，第二个是违反时给用户看的消息。 语法细节见 PostgreSQL 约束文档。

Odoo 15（书中写法，Odoo 19 起被忽略）
_sql_constraints = [
    ("library_book_name_date_uq",
     "UNIQUE (name, date_published)",
     "Title and date must be unique."),
    ("library_book_check_date",
     "CHECK (date_published <= current_date)",
     "Date must not be in the future."),
]

同样的写法还能定义索引：

    # 普通的多列索引
    _publisher_date_idx = models.Index("(publisher_id, date_published)")
    # 唯一索引，可以带条件：只有有效的书才要求 ISBN 唯一
    _isbn_uniq = models.UniqueIndex("(isbn) WHERE active IS TRUE")

Python 约束

Python 约束可以执行任意代码。约束方法用 @api.constrains 装饰，列出它检查的字段；当这些字段被修改时，方法就会运行，校验失败时抛出异常（通常是 ValidationError）。 我们已经有判断 ISBN 是否合法的 _check_isbn()，正好用它阻止保存非法 ISBN： 

from odoo.exceptions import ValidationError

    # （在 LibraryBook 类中）
    @api.constrains("isbn")
    def _constrain_isbn_valid(self):
        for book in self:
            if book.isbn and not book._check_isbn():
                raise ValidationError(self.env._("%s is an invalid ISBN", book.isbn))
ⓘ @api.constrains 只看「被写入的字段」

它只在列出的字段出现在 create / write 的值里时触发。点号路径（如 "publisher_id.country_id"）在这里不支持 —— 关联记录变了不会触发它。另外，有了这个约束之后，第 3 章那个「Check ISBN」按钮的意义就小多了，因为非法 ISBN 根本存不进去。

Odoo 基础模型概览

Odoo 核心框架包含 base 模块（在源码 odoo/odoo/addons/base/），提供 Odoo 应用运行所需的基础功能； 所有官方应用（在源码 odoo/addons/）都建立在它之上。base 提供两类模型：

ir.* —— 信息仓库（Information Repository）
框架自身运行需要的数据，「技术」菜单里看到的大多是它们：
ir.actions.act_window 窗口动作 · ir.ui.menu 菜单 · ir.ui.view 视图 · ir.model 模型 · ir.model.fields 字段 · ir.model.data XML ID · ir.access 访问规则 · ir.config_parameter 系统参数 · ir.cron 定时任务
res.* —— 资源（Resources）
所有模块都可以使用的基础主数据：
res.partner 联系人（客户、供应商、地址） · res.company 公司 · res.country 国家 · res.country.state 省 / 州 · res.currency 币种 · res.groups 用户组 · res.users 用户

第 14 章会更详细地介绍这些内置模型。

小结

  • 模型由 _name 唯一标识；_order、_rec_name、_table 等属性控制它的行为。
  • 普通模型永久存储；临时模型给向导用，会被定期清理；抽象模型没有表，用作混入类。
  • 字段类型涵盖文本、数值、日期、布尔、二进制、图片、JSON 等；通用属性有 default、required、readonly、index、copy、groups 等。states 已移除。
  • 显示名称由 display_name 计算字段决定，自定义时重写 _compute_display_name（不再用 name_get）。
  • 关系：多对一是外键；一对多是反查；多对多用关系表；层级用 parent_id + _parent_store；引用字段能指向多个模型。
  • 计算字段用 compute + @api.depends；可以存储，也可以通过 search / inverse 支持搜索和写入；关联字段是它的简写。
  • 约束：SQL 约束用 models.Constraint（旧的 _sql_constraints 已失效）；Python 约束用 @api.constrains。
