第 12 章

PDF 报表

界面再好用，有些场合还是需要「打印出来」：发给客户的报价单、随货的送货单、盖章存档的合同。 Odoo 的报表就是用 QWeb 生成 HTML，再转换成 PDF。所以上一章学的模板技能可以直接用来设计报表， 只是这一次模板在服务器上渲染，表达式写的是 Python。

本章目标

  • 安装 PDF 转换引擎（wkhtmltopdf），了解 Odoo 20 新的引擎机制
  • 用报表动作把报表放进「打印」菜单，设置纸张格式
  • 用标准布局模板和 Bootstrap 网格设计报表内容
  • 使用字段组件、图片、合计、累计、多语言
  • 写一个自定义报表模型，为报表准备任意数据

安装 PDF 引擎

Odoo 报表本质上是 HTML 页面，转换成 PDF 需要一个外部工具。默认使用 wkhtmltopdf（WebKit HTML to PDF）。 它的版本很挑剔：某些版本有已知问题（比如页眉页脚不显示），而发行版自带的包往往不合适。推荐使用官方打包的 0.12.6.1（with patched qt） 版本。

  1. 先检查系统里是否已经装了别的版本：wkhtmltopdf --version。如果不是推荐版本，先卸载：sudo apt remove --purge wkhtmltopdf。
  2. 到 wkhtmltopdf/packaging 的发布页下载对应系统的包。Ubuntu 24.04 可以使用为 22.04（jammy）打包的版本。
  3. 安装，并自动补齐依赖。
  4. 确认版本。
wget https://github.com/wkhtmltopdf/packaging/releases/download/0.12.6.1-3/wkhtmltox_0.12.6.1-3.jammy_amd64.deb -O /tmp/wkhtml.deb
sudo apt install -y /tmp/wkhtml.deb
wkhtmltopdf --version
wkhtmltopdf 0.12.6.1 (with patched qt)

装好以后，Odoo 启动日志里就不会再出现 You need Wkhtmltopdf to print a pdf version of the reports.。 注意另一条提示：如果用 --workers=1 运行，生成 PDF 会失败 —— 渲染 PDF 时 wkhtmltopdf 要回头向 Odoo 请求样式和图片，至少需要两个工作进程（开发时默认的多线程模式没有这个问题）。

⇪ PDF 引擎变成了可插拔的

Odoo 19.4 起把报表引擎拆成了独立模块：base_report_wkhtmltox（wkhtmltopdf，自动安装，仍是默认）和可选的 base_report_paper_muncher —— Odoo 自研的新渲染引擎 Paper Muncher。安装后者后，报表类型里会多出「PDF (Paper Muncher)」 （qweb-pdf-paper-muncher）。在 wkhtmltopdf 早已停止维护的背景下，这是值得关注的方向；本章仍以默认引擎为准。

报表动作

我们给图书馆应用做一份「书目」报表：列出书名、出版社、出版日期、出版社地址和作者。按惯例，报表文件放在模块的 reports/ 目录。 第一步是报表动作 —— 它之于报表，就像窗口动作之于视图。报表动作存在 ir.actions.report 模型里，可以在 设置 → 技术 → 动作 → 报表中查看。 

<odoo>
    <record id="action_library_book_report" model="ir.actions.report">
        <field name="name">Book Catalog</field>
        <field name="model">library.book</field>
        <field name="report_type">qweb-pdf</field>
        <field name="report_name">library_app.book_catalog</field>
        <field name="binding_model_id" ref="model_library_book"/>
        <field name="binding_type">report</field>
    </record>
</odoo>

记得把文件加入清单的 data。现在在书的列表里选中记录，顶部的 ⚙ 操作旁边会出现 🖨 打印菜单，里面有「Book Catalog」。

字段含义
name报表标题
model报表基于哪个模型
report_typeqweb-pdf、qweb-html 或 qweb-text。开发时用 qweb-html，直接在浏览器里看渲染出的 HTML，调好了再改回 PDF
report_nameQWeb 模板的 XML ID。这里必须写完整的 模块名.标识符
binding_model_id / binding_type出现在哪个模型的打印菜单里；binding_type 设为 report（不设就进「操作」菜单）
print_report_name生成的文件名，Python 表达式，object 代表当前记录，如 'Book - %s' % object.name
attachment / attachment_use把生成的 PDF 存为附件（文件名表达式）；再次打印时直接用存好的附件而不重新生成（适合发票这类不该变的文件）
paperformat_id使用的纸张格式
group_ids哪些用户组能使用这个报表（书中为旧名 groups_id）
multi为 True 时，在表单视图的打印菜单里不显示
ⓘ <report> 快捷标签

早期版本可以用 <report> 快捷标签定义报表动作，Odoo 14 起废弃，现在统一用 <record model="ir.actions.report">。

报表模板的骨架

报表模板就是普通的 QWeb 模板，但要嵌套几个标准的容器模板，确保分页、页眉页脚正确：

<template id="book_catalog">
    <t t-call="web.html_container">
        <t t-foreach="docs" t-as="o">
            <t t-call="web.external_layout">
                <div class="page">
                    <!-- 一条记录的内容 -->
                </div>
            </t>
        </t>
    </t>
</template>
  • web.html_container：生成支撑一个 HTML 文档的基本结构。
  • web.external_layout：按当前公司的「文档布局」设置生成页眉页脚，适合对外的单据。
  • web.internal_layout：只有简单的页眉，适合内部使用的报表。web.basic_layout 则完全没有页眉页脚。
  • docs：要生成报表的记录集。通常用 t-foreach 遍历它。

上面的写法是每条记录一份文档（各有页眉页脚，适合发票、订单）。书目是一份列表：整份文档只有一个页眉页脚，每本书一行。 所以把循环移到 page 里面： 

<template id="book_catalog">
    <t t-call="web.html_container">
        <t t-call="web.external_layout">
            <div class="page">
                <!-- 表头 -->
                <t t-foreach="docs" t-as="o">
                    <!-- 每本书一行 -->
                </t>
                <!-- 表尾：合计 -->
            </div>
        </t>
    </t>
</template>

文档布局

使用 external_layout 的报表，外观由用户在 设置 → 通用设置 → 公司 → 文档布局里配置： 点 配置文档布局打开配置器，可以选择版式、上传 Logo、设置颜色和字体，并实时预览。所以报表模板只负责内容，样式交给每家公司自己定。

纸张格式

Odoo 自带欧洲 A4、美国 Letter 等纸张格式，存储在 report.paperformat 模型中（设置 → 技术 → 报表 → 纸张格式）。 书目的栏目比较多，我们定义一个横向的 A4： 

<record id="paperformat_euro_landscape" model="report.paperformat">
    <field name="name">A4 Landscape</field>
    <field name="format">A4</field>
    <field name="orientation">Landscape</field>
    <field name="margin_top">40</field>
    <field name="margin_bottom">32</field>
    <field name="margin_left">7</field>
    <field name="margin_right">7</field>
    <field name="header_line" eval="False"/>
    <field name="header_spacing">35</field>
    <field name="dpi">90</field>
</record>

这是 base 模块里欧洲 A4 格式（data/report_paperformat_data.xml）的副本，只把方向改成了横向。在报表动作上引用它：

<record id="action_library_book_report" model="ir.actions.report">
    <field name="name">Book Catalog</field>
    <field name="model">library.book</field>
    <field name="report_type">qweb-pdf</field>
    <field name="report_name">library_app.book_catalog</field>
    <field name="binding_model_id" ref="model_library_book"/>
    <field name="binding_type">report</field>
    <field name="paperformat_id" ref="paperformat_euro_landscape"/>
</record>

不指定纸张格式时，使用公司设置里的默认格式。

设计报表内容

服务端渲染上下文

报表模板在服务器上用 Python 实现的 QWeb 渲染，表达式是 Python。模板里可以使用这些变量：

变量含义
docs要生成报表的记录集 —— 最重要的一个
doc_ids / doc_model记录的 ID 列表 / 模型名
user运行报表的用户
res_company当前公司
web_base_urlOdoo 服务器的基础网址
timePython 的 time 模块
context_timestamp把 UTC 时间转换成用户时区的函数

和看板最大的不同：这里拿到的是真正的记录集，可以用点号一路访问关联数据，比如 o.publisher_id.country_id.name， 也可以调用记录的方法、使用 len()、列表推导等任何 Python 表达式。

表头和数据行

报表用 HTML + Bootstrap 5 排版。Bootstrap 的网格系统把一行分成 12 列，每个单元格用 col-N 指定占几列，一行加起来正好 12： 

<div class="page">
    <div class="container">
        <!-- 表头 -->
        <div class="row bg-primary text-white fw-bold">
            <div class="col-3">Title</div>
            <div class="col-2">Publisher</div>
            <div class="col-2">Date</div>
            <div class="col-3">Publisher Address</div>
            <div class="col-2">Authors</div>
        </div>
        <!-- 每本书一行 -->
        <t t-foreach="docs" t-as="o">
            <div class="row border-bottom py-1">
                <div class="col-3">
                    <h5><span t-field="o.name"/></h5>
                </div>
                <div class="col-2">
                    <span t-field="o.publisher_id"/>
                </div>
                <div class="col-2">
                    <span t-field="o.date_published" t-options="{'widget': 'date'}"/>
                </div>
                <div class="col-3">
                    <div t-field="o.publisher_id"
                         t-options='{"widget": "contact",
                                     "fields": ["address", "email", "phone", "website"],
                                     "no_marker": true}'/>
                </div>
                <div class="col-2">
                    <!-- 作者，见下文 -->
                </div>
            </div>
        </t>
        <!-- 表尾，见下文 -->
    </div>
</div>
💡 网格还是表格？

上面沿用书里的网格写法。对规整的表格数据，用 HTML 表格往往更省事、跨页也更稳： <table class="table table-sm"><thead>…</thead><tbody><tr t-foreach="docs" t-as="o">…</tr></tbody></table>， 表头在每一页都会自动重复。Odoo 自己的销售订单、发票报表都是这样写的。

t-field 与字段组件

t-field 输出记录字段的值，并按字段类型和用户语言正确格式化（日期格式、货币符号、多对一显示名称……）。 它可以配合 t-options 选择组件和选项：

组件用途与常用选项
date / datetime日期 / 日期时间；format 自定义格式
monetary金额；display_currency 指定币种
contact联系人卡片；fields 选择显示 name、address、phone、email、website 等，no_marker 去掉图标
image图片；style、width 等
duration / float_time时长
barcode条形码 / 二维码
relative相对时间（「3 天前」）
💡 文档不全时看源码

所有服务端字段组件定义在源码 odoo/addons/base/models/ir_qweb_fields.py 里：每个继承 ir.qweb.field 的类就是一种组件， 它的 get_available_options() 方法列出了支持的选项。

图片

最后一栏显示作者及其头像。在多对多字段上循环，用 image 组件渲染联系人的 image_128 字段：

<ul class="list-unstyled">
    <li t-foreach="o.author_ids" t-as="author">
        <span t-field="author.image_128"
              t-options="{'widget': 'image', 'style': 'max-width: 32px'}"/>
        <span t-field="author.name"/>
    </li>
</ul>

合计

报表常常需要合计。在 t-foreach 循环结束之后加一行表尾，统计书的数量和不重复的作者数量：

<div class="row fw-bold">
    <div class="col-3"><t t-out="len(docs)"/> Books</div>
    <div class="col-7"/>
    <div class="col-2"><t t-out="len(docs.author_ids)"/> Authors</div>
</div>

docs.author_ids 在多条记录上取关系字段，得到所有书的作者的并集（不重复），len() 就是作者数。 求和也一样简单，比如 <t t-out="sum(docs.mapped('copies'))"/>。当然，如果模型本身就有算好的合计字段，直接用它更好。

累计值

有时需要在循环中逐行累加，比如显示「到目前为止，有多少本书没有出版社」。在循环前用 t-set 初始化变量，在循环里更新并显示： 

<!-- 循环前：初始化 -->
<t t-set="missing_count" t-value="0"/>
<t t-foreach="docs" t-as="o">
    <div class="row">
        ...
        <div class="col-2">
            <span t-field="o.publisher_id"/>
            <!-- 循环中：累加并显示 -->
            <t t-set="missing_count" t-value="missing_count + int(not o.publisher_id)"/>
            <p class="small text-muted">(accum. <t t-out="missing_count"/>)</p>
        </div>
        ...
    </div>
</t>

服务端 QWeb 的循环也提供辅助变量：o_index、o_size、o_first、o_last、o_odd、o_even 等，可以用来做斑马纹之类的效果。

多语言

报表默认使用当前用户的语言。但有时文档应该使用客户的语言打印 —— 比如中国员工给法国客户打印报价单。 QWeb 的 t-call 可以搭配 t-lang，用指定的语言渲染被调用的模板。我们再加一个「用图书馆本地语言打印」的报表： 

<record id="action_library_book_report_native" model="ir.actions.report">
    <field name="name">Native Language Book Catalog</field>
    <field name="model">library.book</field>
    <field name="report_type">qweb-pdf</field>
    <field name="report_name">library_app.book_catalog_native</field>
    <field name="binding_model_id" ref="model_library_book"/>
    <field name="binding_type">report</field>
    <field name="paperformat_id" ref="paperformat_euro_landscape"/>
</record>

<template id="book_catalog_native">
    <t t-call="library_app.book_catalog" t-lang="res_company.partner_id.lang"/>
</template>

新模板只做一件事：以公司联系人的语言（res_company.partner_id.lang）调用原来的书目模板。 t-lang 只能和 t-call 写在同一个元素上。（书中这里把 partner_id 误拼成了 parter_id。）

⇪ 服务端 t-call 的传参方式

Odoo 19.1 起，服务端 QWeb 推荐把传给子模板的参数直接写成 t-call 元素的属性，而不是在它内部用 t-set： 

<!-- 普通属性：值是 Python 表达式 -->
<t t-call="library_app.book_line" book="o" show_authors="True"/>
<!-- 以 .f 结尾：值是格式化字符串（等同 t-valuef） -->
<t t-call="library_app.section" title.f="Books of {{ o.name }}"/>
<!-- 以 .translate 结尾：可翻译的文字 -->
<t t-call="library_app.section" title.translate="Book Catalog"/>

odoo-bin upgrade_code 带有自动转换脚本（19.1-00-t-call.py）。t-call 元素内部的内容仍然可以在子模板里用 t-out="0" 输出。 看板等客户端模板不受影响，仍用第 11 章的写法。

自定义报表

默认情况下，报表拿到的是用户选中的记录（docs）。有时需要为报表准备任意的数据结构，比如分组、汇总、来自其他模型的数据。这时用自定义报表。

例子：「按出版社列书」报表。在联系人列表里选中几个出版社，打印出每家出版的书。

准备数据

from odoo import api, models


class PublisherReport(models.AbstractModel):
    _name = "report.library_app.publisher_report"
    _description = "Books by Publisher Report"

    @api.model
    def _get_report_values(self, docids, data=None):
        books = self.env["library.book"].search([("publisher_id", "in", docids)])
        publisher_books = [
            (publisher, books.filtered(lambda book: book.publisher_id == publisher))
            for publisher in books.publisher_id
        ]
        return {
            "publisher_books": publisher_books,
        }

让模块加载这个文件：

  • 新建 reports/__init__.py，内容 from . import library_publisher_report；
  • 在模块的 __init__.py 里加上 from . import reports。

要点：

  • 它是 AbstractModel：没有表，不存数据，只负责计算。
  • 名字是约定好的：report. + 报表模板的完整 XML ID。报表引擎运行时会去找这个名字的模型，找到了就调用它的 _get_report_values()。
  • docids 是用户选中的记录 ID 列表。报表基于 res.partner，所以这里是联系人 ID。data 是从向导等地方传来的额外参数（这里没用到）。
  • 方法返回的字典里每个键都会成为模板里的变量。这里 publisher_books 是一个「(出版社记录, 它的书的记录集)」二元组列表。

报表模板

<odoo>
    <record id="action_publisher_report" model="ir.actions.report">
        <field name="name">Books by Publisher</field>
        <field name="model">res.partner</field>
        <field name="report_type">qweb-pdf</field>
        <field name="report_name">library_app.publisher_report</field>
        <field name="binding_model_id" ref="base.model_res_partner"/>
        <field name="binding_type">report</field>
    </record>

    <template id="publisher_report">
        <t t-call="web.html_container">
            <t t-call="web.external_layout">
                <div class="page">
                    <div class="container">
                        <h1>Books by Publisher</h1>
                        <t t-foreach="publisher_books" t-as="group">
                            <h2 t-field="group[0].name"/>
                            <ul>
                                <li t-foreach="group[1]" t-as="book">
                                    <b><span t-field="book.name"/></b>
                                    <span t-field="book.author_ids"/>
                                </li>
                            </ul>
                        </t>
                    </div>
                </div>
            </t>
        </t>
    </template>
</odoo>

模板里没有使用 docs，而是遍历自定义的 publisher_books：group[0] 是出版社，group[1] 是它的书。 把 XML 文件加入清单，升级模块后，在联系人列表里选中记录（或打开某个出版社的表单），打印菜单里就有「Books by Publisher」了。

⇪ Bootstrap 5

书里报表用的是 Bootstrap 4，Odoo 16 起升级到 Bootstrap 5（Odoo 20 为 5.3）。常见的改名：text-right → text-end、ml-*/mr-* → ms-*/me-*、 font-weight-bold → fw-bold、badge-pill badge-info → rounded-pill text-bg-info。

小结

  • 报表 = 服务端 QWeb 渲染的 HTML + PDF 引擎转换。默认引擎 wkhtmltopdf 推荐 0.12.6.1（patched qt）；Odoo 20 还提供可选的 Paper Muncher 引擎。
  • 报表动作（ir.actions.report）指定模型、模板、类型和纸张格式，binding_model_id + binding_type="report" 把它放进打印菜单。
  • 模板骨架：web.html_container → web.external_layout → <div class="page">；循环的位置决定是「每条一份」还是「一份清单」。
  • 渲染上下文里有 docs、user、res_company 等，表达式是 Python，记录集可以随意导航。
  • t-field + t-options 格式化字段；合计用 Python 表达式，累计用循环里的 t-set；t-lang 换语言。
  • 自定义报表：名为 report.<模板 XML ID> 的抽象模型，实现 _get_report_values() 返回模板变量。

动手练习

  1. 安装 wkhtmltopdf，按本章做出书目报表。先用 qweb-html 调好样式，再改回 qweb-pdf。
  2. 把书目报表改写成 HTML 表格版本，并在每一页重复表头。
  3. 给报表动作加上 print_report_name，让下载的文件名为「Book Catalog - 日期.pdf」。
  4. 为借书单做一份「借书凭证」报表：每张借书单一份文档，列出会员信息和借的每一本书，底部留签名栏。
  5. 在「按出版社列书」报表里，给每家出版社加上书的数量和最早 / 最晚的出版年份。
  6. 把「借书凭证」中「每一本书一行」的部分抽成一个子模板，用 Odoo 20 的属性传参方式 t-call 它。
