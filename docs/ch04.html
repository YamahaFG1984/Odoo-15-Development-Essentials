第 4 章

扩展模块

Odoo 最强大的能力之一：不碰别人的代码，也能修改别人的功能。 你不需要去改 sale 模块的源码来给销售订单加个字段，而是写一个新模块，像一层透明薄膜一样叠在上面。 这一章我们写第二个模块 library_member，用它来扩展上一章的 library_app，把每一层的扩展方法都走一遍。

本章目标

  • 用 _inherit 给已有模型加字段、改字段属性、扩展方法
  • 分清 Odoo 的四种模型继承：经典继承、原型继承、委托继承、混入类
  • 给模型加上消息记录（chatter）和计划活动
  • 扩展视图（定位器、XPath、position）和已有数据记录
  • 扩展网页控制器和 QWeb 模板

学习项目：图书馆会员

我们要让图书馆能管理会员，为将来的借书功能做准备。需求如下：

对「书」的修改
  • 加一个「可借阅？」字段，暂时手动维护
  • ISBN 校验除了 13 位，还要支持老式的 10 位
  • 网页书目标出不可借的书，并支持只看可借的书
新增「会员」
  • 新模型：姓名、借书卡号、邮箱、地址等联系信息
  • 会员表单带消息记录和计划活动，方便协作

这些修改全部放进一个新模块 library_member，和 library_app 并列：

新建 ~/work20/library/library_member/ 目录，先放一个空的 __init__.py 和清单文件：

    "author": "Daniel Reis",

    "application": False,

给已有模型加字段

第一个任务最常见也最简单：给书加一个 is_available 布尔字段。正好借它来认识 Odoo 的继承机制。

按「一个模型一个文件」的约定，准备好 Python 文件的导入链：

from . import models

from . import library_book

from odoo import fields, models


class LibraryBook(models.Model):
    _inherit = "library.book"

    is_available = fields.Boolean("Is Available?")

关键在 _inherit = "library.book"：它声明「我要扩展 library.book 这个模型」。 注意这里没有写 _name，因为我们不打算改模型的名字。只需要写出想要添加或修改的部分，其余一切从原模型继承。

经典继承：原地修改

可以把这种继承理解为：从一个中央注册表（registry）里拿到模型定义的引用，然后原地修改它。 Odoo 启动时会按模块的依赖顺序，把同一个模型的所有类「叠」在一起，组装出最终的模型：

💡 如果同时改了 _name 会怎样？

那就不是修改原模型，而是创建一个复制品新模型，称为原型继承。本章后面会讲。

别忘了，代码里扩展的是 library.book，所以要把 library_app 写进 depends —— 已经写了。安装模块后，在 设置 → 技术 → 数据库结构 → 模型里查看 library.book，能看到新字段。

把字段加到表单上

模型有了新字段，还要让它显示出来。视图是 XML，扩展视图就是「找到 XML 里的某个位置，在那里做修改」。 继承视图和普通视图的写法几乎一样，只多一个 inherit_id，指明要扩展哪个视图。

先找到要扩展的视图的 XML ID：在 设置 → 技术 → 用户界面 → 视图里能查到书的表单是 library_app.view_form_book。 再选定插入点：我们想把新字段放在 ISBN 后面，ISBN 字段在视图里是 <field name="isbn"/>。 

<odoo>
    <record id="view_form_book_extend" model="ir.ui.view">
        <field name="name">Book: add Is Available? field</field>
        <field name="model">library.book</field>
        <field name="inherit_id" ref="library_app.view_form_book"/>
        <field name="arch" type="xml">
            <field name="isbn" position="after">
                <field name="is_available"/>
            </field>
        </field>
    </record>
</odoo>
  • inherit_id：用 ref 引用被扩展视图的 XML ID。跨模块引用时要写全 模块名.标识符。
  • arch 里的 <field name="isbn" position="after"> 是定位器：找到 name 为 isbn 的字段，在它之后插入里面的内容。

把文件加入清单的 data，升级模块，书的表单上 ISBN 后面就多了「Is Available?」。

深入经典继承

增量修改已有字段

扩展模型时，已有字段也可以增量修改：只写出要改或要加的属性，其他属性保持不变。 我们做两处修改：给 ISBN 加一个提示说明，给出版社字段加数据库索引（让按出版社搜索更快）： 

class LibraryBook(models.Model):
    _inherit = "library.book"

    is_available = fields.Boolean("Is Available?")
    isbn = fields.Char(help="Use a valid ISBN-13 or ISBN-10.")
    publisher_id = fields.Many2one(index=True)

升级后，鼠标悬停在 ISBN 上能看到提示。索引的效果不太容易察觉，但可以在开发者模式下通过调试菜单 → Fields 找到出版社字段，看到它已被标记为索引。

扩展 Python 方法

业务逻辑同样可以扩展，用的是 Python 本身的类继承机制。原来的 _check_isbn() 只认 13 位 ISBN，但一些老书只有 10 位 ISBN。 10 位 ISBN 的规则是：前 9 位分别乘以 1 到 9，求和后对 11 取余，结果应等于第 10 位。 

    def _check_isbn(self):
        self.ensure_one()
        digits = [int(x) for x in self.isbn if x.isdigit()]
        if len(digits) == 10:
            ponderators = [1, 2, 3, 4, 5, 6, 7, 8, 9]
            total = sum(a * b for a, b in zip(digits[:9], ponderators))
            check = total % 11
            return digits[-1] == check
        else:
            return super()._check_isbn()

在继承的类里定义一个同名方法，就扩展了它。方法里在适当的时候调用 super()._check_isbn()，执行「下一层」的原有逻辑。 这里我们把新逻辑放在 super() 之前：如果是 10 位就自己处理，否则交给原来的方法处理 13 位的情况。

⚠ 几乎总是要调用 super()

如果扩展方法里不调用 super()，原方法（以及其他模块对它的扩展）就再也不会执行了。 这会悄悄破坏别人的功能。除非你非常确定要整体替换，否则务必调用 super()。

不妨给它写个测试。威廉·戈尔丁《蝇王》原版的 10 位 ISBN 是 0-571-05686-5： 

from odoo.tests import TransactionCase


class TestBookISBN10(TransactionCase):

    def test_check_isbn10(self):
        "10 位 ISBN 也能通过校验"
        book = self.env["library.book"].create({
            "name": "Lord of the Flies",
            "isbn": "0-571-05686-5",
        })
        self.assertTrue(book._check_isbn())

（还需要一个 tests/__init__.py 导入它。）

更多继承机制

经典继承最常用，但 Odoo 一共提供了四种模型继承方式，各有用途：

委托继承：嵌入另一个模型

委托继承让我们复用另一个模型的数据结构，而且数据不重复。它在新模型里嵌入一条被委托模型的记录：

  • 创建一条新模型的记录时，会自动创建并关联一条被委托模型的记录。
  • 被委托模型的字段，在新模型上可以直接读写，就像自己的字段一样（底层其实读写的是关联的那条记录）。

最典型的例子是用户：每个用户（res.users）都嵌入了一个联系人（res.partner），所以用户有姓名、邮箱、地址等联系人字段，另外还有登录名、密码等用户特有的字段。

ⓘ 严格说这不是继承

技术上，委托继承是组合：一个对象的部分功能委托给另一个对象提供。它只在数据层面起作用，方法不会被继承。要调用嵌入记录的方法，得通过关系字段：member.partner_id.some_method()。

图书馆会员正好适合这样做：会员需要借书卡号，还需要姓名、邮箱、地址等个人信息 —— 而联系人模型已经有完整的联系方式和地址结构了，没必要再造一遍。 

from odoo import fields, models


class LibraryMember(models.Model):
    _name = "library.member"
    _description = "Library Member"

    card_number = fields.Char()
    partner_id = fields.Many2one(
        "res.partner",
        delegate=True,
        ondelete="cascade",
        required=True,
    )

delegate=True 是关键。还有一种等价的写法，使用模型属性 _inherits（注意多一个 s），它来自旧 API，至今仍很常见： 

class LibraryMember(models.Model):
    _name = "library.member"
    _description = "Library Member"
    _inherits = {"res.partner": "partner_id"}

    card_number = fields.Char()
    partner_id = fields.Many2one("res.partner", ondelete="cascade", required=True)

ondelete="cascade" 表示：如果关联的联系人被删除，会员记录也跟着删除。required=True 保证每个会员都有一个联系人。

要让新模型可用，还要补上导入、访问规则、视图和菜单：

原型继承：复制一个模型

如果同时设置 _inherit 和一个不同的 _name，得到的是一个新模型：原模型的复制品，有自己的表和数据，之后对它的修改不影响原模型。 实践中很少这样直接复制模型，需要复用数据结构时，委托继承通常是更好的选择。

原型继承真正有用的地方是 _inherit 写成列表：从多个父模型「混合」出一个新模型。这正是混入类的用法。

混入类：可复用的功能包

混入类（mixin）就像一个功能容器，实现了某种通用功能，专门用来被加到其他模型里。它不单独使用，所以是抽象模型： 继承自 models.AbstractModel，在数据库里没有对应的表。

Odoo 自带了很多混入类（在源码里搜 models.AbstractModel 就能找到），用得最多的两个来自讨论应用（mail 模块）：

💬

mail.thread

消息墙（chatter）：表单底部或右侧的消息记录、关注者、通知。

⏰

mail.activity.mixin

计划活动：给记录安排待办（打电话、开会……），带提醒和期限。

给会员加上 chatter 和活动

三步：加依赖、继承混入类、在表单里放上 chatter。

    "depends": ["library_app", "mail"],

class LibraryMember(models.Model):
    _name = "library.member"
    _description = "Library Member"
    _inherits = {"res.partner": "partner_id"}
    _inherit = ["mail.thread", "mail.activity.mixin"]

    card_number = fields.Char()
    partner_id = fields.Many2one("res.partner", ondelete="cascade", required=True)

只多了一行，模型就拥有了混入类提供的全部字段和方法。

💡 给「已有」模型加混入类

上面是在定义新模型时加混入。如果要给别的模块已经定义好的模型加混入，_inherit 列表里要把原模型自己也写上，并且不写 _name： _inherit = ["library.book", "mail.thread", "mail.activity.mixin"]。

最后在会员表单里加上 chatter：

            <field name="card_number"/>
        </group>
    </sheet>
    <chatter/>
</form>

从 Odoo 18 起，一个 <chatter/> 标签就自动放好了关注者、活动和消息三部分，并根据屏幕宽度显示在表单下方或右侧。

⚠ 混入类不会改变访问权限

加了 mail.thread 不意味着「只有关注者能看到记录」。如果需要这样的限制，要自己写带域的访问规则。 mail.thread 提供了关注者字段 message_partner_ids，域可以写成 [('message_partner_ids', 'in', [user.partner_id.id])]。

扩展视图和数据

定位器和 position

扩展视图的核心是「定位 + 操作」。最简单的定位方式是写一个和目标同名的标签，带上能唯一识别它的属性（通常是 name），再用 position 指明做什么： 

<field name="isbn" position="after">
    <!-- 要插入的内容 -->
</field>

除了 string，任何属性都可以用来定位。string 不行，因为它在生成视图时会被翻译成用户的语言，值不稳定。 

<!-- 用 $0 给原有字段包一层 h1 -->
<field name="name" position="replace">
    <h1>$0</h1>
</field>

<!-- 修改属性：把某字段设为只读 -->
<field name="isbn" position="attributes">
    <attribute name="readonly">True</attribute>
</field>

<!-- 在已有的 invisible 条件上「或」一个新条件，而不是覆盖它 -->
<field name="isbn" position="attributes">
    <attribute name="invisible" add="not active" separator="or"/>
</field>

<!-- 不带内容的 attribute：删除这个属性 -->
<field name="isbn" position="attributes">
    <attribute name="readonly"/>
</field>
💡 能隐藏就不要删除

position="replace" 配合空内容可以删除元素，但应当尽量避免：别的模块可能正拿这个元素当定位点，你删了它，那些模块就会安装失败。 更稳妥的做法是保留元素，把它设为 invisible="1"。

移动节点

在 inside、after、before 定位器里放一个带 position="move" 的子定位器，可以把一个已有元素移动到新位置： 

<!-- 把 my_field 从原来的位置移到 target_field 之后 -->
<field name="target_field" position="after">
    <field name="my_field" position="move"/>
</field>

用 XPath 定位

有时候没法用简单定位器：目标元素没有 name（常见于 <group>、<notebook>、<page>）， 或者同名元素出现了好几次（比如看板模板里同一个字段出现多次）。这时用 XPath 表达式： 

<!-- 与 <field name="isbn" position="after"> 完全等价 -->
<xpath expr="//field[@name='isbn']" position="after">
    <field name="is_available"/>
</xpath>
XPath含义
//field[@name='isbn']任意位置、name 属性为 isbn 的 field 元素
//group[@name='group_right']name 为 group_right 的 group
//sheet/group[1]sheet 下的第一个 group
//page[@name='lines']//listname 为 lines 的页签里的列表
//div[hasclass('oe_title')]CSS 类里含 oe_title 的 div（Odoo 扩展的函数）
.根节点本身

如果一个 XPath 匹配到多个元素，只有第一个会被修改。所以表达式要尽量精确 —— 这也再次说明了： 写视图时给元素加上唯一的 name，是在为将来扩展它的人（包括你自己）铺路。

修改已有的数据记录

普通数据记录也能「扩展」，其实就是覆盖已有的值。<record id="x" model="y"> 的语义是「如果 x 不存在就创建，存在就更新」， 而用 模块名.标识符 可以引用其他模块创建的记录。

比如，把 library_app 创建的「User」组改名为「Librarian」：

<odoo>
    <!-- 修改 library_app 中定义的组名 -->
    <record id="library_app.library_group_user" model="res.groups">
        <field name="name">Librarian</field>
    </record>
</odoo>

这里只写了 name 字段，相当于对这条记录做一次只改 name 的写操作，其他字段不受影响。记得把文件加入清单的 data。

⚠ 快捷标签是「整体覆盖」

用 <record> 可以只写想改的字段，但 <menuitem> 这样的快捷标签不行：它会写入全部属性，没写的属性会被清空。 要修改别的模块的菜单项的某个属性，用 <record id="其他模块.菜单id" model="ir.ui.menu"> 只写那个字段。

💡 点号是保留字符

XML ID 里的 . 专门用来分隔模块名和标识符，所以标识符本身只能用下划线，不能有点。

扩展网页

网页控制器和 QWeb 模板同样可以扩展。我们利用新加的「可借阅？」信息改进书目页面：

  • 控制器：支持查询参数 /library/books?available=1，只显示可借的书。
  • 模板：在不可借的书旁边标注「(Not Available)」。

扩展控制器

控制器负责处理网页请求、准备渲染的数据。它应该只处理展示逻辑（比如解析 URL 参数），业务逻辑应该放在模型方法里。 

from odoo import http
from odoo.addons.library_app.controllers.main import Books


class BooksExtended(Books):

    @http.route()
    def list(self, **kwargs):
        response = super().list(**kwargs)
        if kwargs.get("available"):
            all_books = response.qcontext["books"]
            available_books = all_books.filtered("is_available")
            response.qcontext["books"] = available_books
        return response

别忘了让 Python 能找到它：

from . import models
from . import controllers

from . import main

逐行理解：

  • 导入原控制器类。模型有中央注册表，self.env["library.book"] 就能拿到，不用关心它在哪个文件。 控制器没有这样的注册表，必须知道原控制器在哪个模块的哪个文件里，用 odoo.addons.模块名.路径 导入。
  • 继承它。新类的名字无所谓，它只是一个用来扩展原类的载体。
  • 重新声明方法，并且必须再次加上 @http.route()。不带参数的 @http.route() 表示沿用父类定义的路由； 不加这个装饰器，路由就失效了。也可以传入参数来修改路由。
  • **kwargs 收集 URL 里的所有参数，比如 ?available=1 会变成 {"available": "1"}。用 **kwargs 能让页面容忍未知参数； 如果只声明特定参数，访问时带了别的参数就会直接报错。

关键在于：父方法用 request.render() 返回的 Response 对象还没有生成 HTML，它只记着模板名（template）和模板变量（qcontext）。 HTML 要等整个控制器执行完才生成。所以我们能在中间替换 qcontext["books"]，用过滤后的书目去渲染。 filtered("is_available") 返回记录集中 is_available 为真的那些记录。

现在访问 http://localhost:8069/library/books?available=1，只显示勾了「可借阅」的书。

扩展 QWeb 模板

网页模板也是 XML，扩展方式和后台视图一样，只是用 <template> 元素加 inherit_id 属性。 网页模板里 HTML 元素多，通常需要用更灵活的 XPath： 

<odoo>
    <template id="book_list_extended"
              name="Extended Book List"
              inherit_id="library_app.book_list_template">
        <xpath expr="//span[@t-field='book.publisher_id']" position="after">
            <t t-if="not book.is_available">
                <b>(Not Available)</b>
            </t>
        </xpath>
    </template>
</odoo>

小结

  • 可扩展性是 Odoo 的核心设计：扩展模块叠加在原模块之上，原模块的代码一行不改。
  • 经典继承（_inherit）原地修改模型；字段可以增量重定义；方法扩展记得调用 super()。
  • 委托继承（delegate=True / _inherits）复用另一个模型的数据结构，不重复存储。
  • 混入类是抽象模型，mail.thread 和 mail.activity.mixin 最常用；Odoo 20 用一个 <chatter/> 标签显示它们。
  • 视图扩展 = inherit_id + 定位器（简写或 XPath）+ position；给自己写的视图元素加 name，方便别人扩展。
  • 控制器扩展要重新加 @http.route()；延迟渲染的响应允许修改 qcontext。
